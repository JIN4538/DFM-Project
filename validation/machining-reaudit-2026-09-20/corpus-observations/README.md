# 무작위 형상 26개 — 절삭 입력 견고성 관측

**최종 관측에서는 26개 모두 입력 처리 결과를 확보했다. 제한된 CAD 특징 검토 9개, 정량 판정 보류 17개다. 26개 치수 정확도 검사 통과라는 뜻이 아니다.** 최초 45초 한도에서 24개가 완료되고 2개가 시간 초과했으며, 그 2개만 실제 앱의 180초 한도로 다시 읽어 완료했다. 다운로드 형상의 원 설계 치수와 실제 가공 정답이 없으므로, 이번 관측은 입력 처리·지원 범위·미확정 보존·예외 발생을 확인한다. 생산 코드와 기존 형상을 수정하지 않았다.

## 조건과 재현

- 대상: `examples/corpus/manifest.json`에 등록된 모든 `kind=geometry` 26개. 원본 형상을 복제하거나 새 STEP을 추가하지 않았다.
- 호출: `load_model(..., deflection_mm=0.05, timeout_s=45)` 후 `review_machining(..., direction=(0,0,1), visibility=False)`.
- 최초 시간 초과 2개만 `timeout_s=180`으로 재시도했다. 이는 `app.py`의 실제 입력 한도와 같다. 다른 24개는 다시 실행하지 않았다.
- 공구: 지름 4 mm / 날 길이 10 mm / 끝날부터 홀더까지 돌출 길이 15 mm라는 **시연 조건**. 장비·재료는 미확정이며 검증된 가공 조건이 아니다.
- STL의 기본 mm 단위는 미확정 상태를 유지한다. STEP·3MF는 선언 단위를 사용한다.
- 조립체의 부품을 자동 선택하지 않고 입력 전체로 관측했다. STL·3MF·표면 STEP을 솔리드 CAD로 바꾸지 않았다.
- 한 번에 한 모델씩 순서대로 처리했다. 점 가림 검사는 실행하지 않았다. 회귀검사와 브라우저 작업이 동시에 진행되었으므로 시간 값은 독립 성능 벤치마크가 아니다.
- 재현 스크립트: `observe_corpus.py <존재하지 않는 새 출력 폴더>`. 기존 결과 폴더의 덮어쓰기를 거부한다.
- 실제 실행 로그: `run-01.txt`. 환경·프로필·버전·소스 SHA: `run-01/environment.json`. 전수 요약: `run-01/summary.json`. 완료한 24개 입력의 상세 결과: `run-01/model_01.json` 등.
- 추가 관측: `observe_timeout_retry.py <이전 결과 폴더> <새 출력 폴더>`, `retry-180s.txt`, `retry-180s/environment.json`, `retry-180s/summary.json`. 최신 관측을 합친 색인은 `combined-summary.json`이며, 두 단계 실행을 한 번의 전수 성공 실행으로 표현하지 않는다.

## 이 관측에서 드러난 지원 한계

1. **복잡한 CAD를 전수 특징 인식했다고 볼 수 없다.** 단일 솔리드 9개 중 8개에는 미지원 곡면 또는 미확정 원통면이 있어 CAD 정보 범위 결과가 `unknown`이었다. 나머지 1개도 제한된 평면·원통면 범위의 정보 확인이며 가공 가능 판정이 아니다.
2. **직사각 포켓 인식은 좁은 범위다.** 이 입력들에서 엄격한 4변 바닥은 검출되지 않았다. Gearbox의 내부 바닥 후보 38개, Cap의 1개, Arduino의 62개는 위치를 남기고 폭·높이를 미측정 상태로 보존했다. 이 수는 포켓 개수가 아니며, 실제 특징이 없다는 증거도 아니다. 인식 정확도는 별도의 치수 정의 기준형상으로 검증해야 한다.
3. **큰 입력의 대기 시간이 길다.** Pump와 Raspberry Pi STEP은 최초 45초 한도에서 완료되지 않았고, 실제 앱의 180초 한도로 추가 관측하자 각각 66.94 / 142.41초에 완료됐다. 따라서 최초 결과는 조기 감사 한도의 제한이었으며 제품에서 영구적으로 읽을 수 없다는 증거가 아니었다. 무한 대기하거나 부분 데이터를 정상 결과로 사용하지 않았고, 부품별 재검토는 이번 관측에서 수행하지 않았다.
4. **조립체·메시 입력의 사용 목적을 구분해야 한다.** 다중 솔리드는 사용자가 부품을 선택해야 하고, STL/3MF의 삼각형을 CAD 해석 원통·포켓 치수로 확정하지 않는다. 이번 실행은 이 보류 계약이 유지되는지 확인했으며 자동 선택을 통한 성공률 높이기를 하지 않았다.

원본 26개의 SHA는 모두 기존 manifest와 일치했고 두 단계 실행 전후 바이트가 유지됐다. 엔진 digest도 각 단계의 시작·종료 시 `9b8fda0296c7bccb9fa320a9ffa15638f11a738ca497bc11b6925dfbdf674fe5`로 동일했다. 최초 45초 시간 초과 2개 외에 입력·검토 예외는 관측되지 않았고 추가 관측 2개도 예외 없이 완료됐다. 이 결과는 물리 가공 실험·전체 표면의 가림 검사·실제 공구 충돌 검증을 대신하지 않는다.
