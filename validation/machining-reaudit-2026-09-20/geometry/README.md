# 절삭 계산 독립 재검토 — 2026-09-20

직접 매개변수로 만든 OCCT 형상을 STEP으로 내보낸 다음, 실제 CAD 변환과 절삭 검토 함수를 연결해 대조했다. 기대값은 생성 치수·Rodrigues 회전식·원통 면적식이다. 제조 실험, 공구 경로, 전체 가공 가능성 또는 성공 확률 검증은 아니다. 이 폴더의 계산 시험과 부모 작업의 실제 브라우저 시험은 서로 다른 증거다.

## 확인한 결함과 수정

1. **회전만으로 같은 치수가 초과로 바뀌었다.** 20 × 12 mm, 벽 높이 8 mm인 포켓을 임의축으로 0.713 rad 회전하고 날 길이·돌출 길이에 8 mm를 입력하면, 측정 높이 `8.000000000000675` 때문에 둘 다 초과로 표시됐다. `before-rotation/summary.json`과 `before-rotation.txt`가 당시 결과다. 비교에 `max(1e-9 mm, 비교 치수 × 1e-10)` 수치 밴드를 적용하고 경계 항목을 별도 보존했다. 실제 제조공차·가공 여유로 사용하는 값이 아니다. `after-rotation/summary.json`에서 초과 오경보가 사라지고 경계 목록은 남는 것을 확인했다. 0.001 mm의 실제 차이는 계속 검출한다.

2. **멀리 이동한 STEP의 내부 바닥이 검토 대상에서 조용히 사라졌다.** 회전한 동일 포켓을 1,000,000 / 100,000,000 mm 이동한 STEP은 저장 정밀도에 따른 경계 불일치로 엄격한 직사각 인식에서 탈락했다. 인식 허용치를 임의로 키워 포켓이라고 확정하지 않았다. 대신 위를 향한 면에 위쪽으로 뻗는 안쪽 수직벽이 있는 위치를 `unresolved_floor_face_ids`로 보존하고 폭·벽 높이 미측정 상태로 안내한다. 이 목록은 열린 포켓의 개수가 아니다. 채널·섬·밀폐 공동에서도 미확정 위치를 보존하며, 단순 블록·돌출 보스·포켓 상단 테두리를 내부 바닥 후보로 잘못 추가하지 않는 반례를 포함한다.

3. **축 정렬의 코사인 임계값이 실제 작은 기울기를 삼켰다.** 기존 `abs(dot) >= 1 - 1e-8`는 약 0.0081°까지 축이 일치하는 것으로 취급했다. 0.005° 기울기 반례를 확인하고 `norm(cross) <= 1e-8`로 변경했다. 이는 약 0.000000573°의 수치 정책이며 제조 허용각이 아니다. 실제 최소 축각을 `atan2(sin, abs(cos))`로 측정해 `axis_angle_deg`로 보고한다. 밴드 안팎을 회전·이동한 형상과 대조했다. 축이 다른 면의 지름·돌출 길이 비교는 보류하며, 다른 공구·경로까지 가공 불가라는 뜻이 아니다.

4. **UV 범위 360°를 완전한 원통 벽으로 읽을 수 있었다.** 내부 원통에 측면 창을 낸 형상은 UV 각도 범위가 360°이지만 면적은 온전한 원통보다 작다. 문구를 ‘원주 방향 범위가 360°인 내부 원통면’으로 고쳤다. 막힌/관통 원통, 분할 반원통 2면, 측면 창 반례에서 구간 길이·면수와 구멍 전체 깊이·개수를 구분하는 계약을 검증했다.

5. **모든 항목에 같은 문헌·분석 방법이 붙었다.** 입력·CAD 정보 범위는 변환 메타데이터/경계 추출, 원통은 해석 곡면 치수, 포켓은 제한된 인접관계 인식, 가림은 메시 표본 직선 검사로 구분했다. 실제 계산 방법과 문헌이 설명하는 적용 한계를 분리했다. Autodesk 홀더 문헌은 점 레이 구현의 검증 근거라고 표시하지 않는다.

6. **문제가 해소돼도 공구를 줄이라고 안내했다.** 오목 원통 R3에서 공구 Ø8은 작은 공구/반경 확대 검토, Ø4는 반경 비교 문제 미관측 후 진입 경로·홀더 확인, Ø6은 수치 경계·가공 여유 확인, 공구 미입력은 치수 입력으로 다음 행동을 구분한다. 원통 항목도 축·지름·길이·사용자 비율 기준 중 실제 관측한 항목에 맞춰 행동을 설명한다.

## 실행 증거

- 새 독립 반례: `tests_v3/test_machining_reaudit.py` — 22개.
- 기존 절삭 판단 40개, 결과/UI 계약 20개, CAD 추출 10개, 점 가림 39개를 함께 실행했다.
- **최종 대상 검사 131 / 131 통과, 44.16초:** `final-subset.txt`, `final-subset.xml`.
- 초기 새 시험 15개 중 6개 실패는 `first.txt/xml`에 보존했다. 3개는 검사 문구의 `manufacturing`/`machining` 불일치, 3개는 새 후보 인식이 상단 테두리까지 포함한 실제 초기 결함이었다. 테두리 결함은 인접벽이 바닥보다 위쪽에 있는지 확인해 수정했다.
- 중간 75개 통과: `retest.txt/xml`. 축·분할 반례 추가 후 17개 통과: `axis-and-split.txt/xml`. 이 중간 결과를 최종 전체 프로젝트 통과로 표현하지 않는다.
- 마지막 대상 검사의 소스 SHA: `audited_source_sha256.json`. 전체 앱의 최종 통과 여부와 소스 보관본은 부모 감사 기록을 따른다.

## 보관 형상과 재현

`before-rotation/` 및 `after-rotation/`에 각각 `transformed_0.step`부터 `transformed_4.step`까지, 총 **10개 STEP 파일**을 보존했다. 각 폴더의 JSON/NPZ는 해당 STEP의 실제 CAD 추출 결과이고 `summary.json`은 당시 검토 결과다. STEP 헤더에 생성 시간이 있어 전후 파일 바이트가 같다는 뜻은 아니다. `probe_geometry.py <새 출력 폴더>`는 기존 출력 폴더를 덮어쓰지 않는다.

추가 pytest 형상은 pytest 임시 폴더에만 생성한다. 저장소의 기존 12개 절삭 예제나 원본 CAD를 바꾸지 않았다. 변환 호출을 직접 사용하는 독립 시험이므로 프로세스 격리/브라우저 경로 전체를 검증했다고 확대하지 않는다. 그 경로는 기존 및 부모 작업 검사에서 별도로 다룬다.

여전히 공구·홀더·고정구·소재의 swept-volume 충돌, 실제 입구 연결성, 절삭력·강성·표면 품질, 형상 밖 미표본 영역과 실제 가공 성공은 미검증이다. 참고문헌의 구체적 역할과 적용 조건은 `docs/research/MACHINING_EVIDENCE_REAUDIT_2026-09-20.md`를 따른다.
