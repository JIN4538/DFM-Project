# 개선안 선택 학습: 무엇이 달라졌나

이 모델은 기존 문제 판정을 다시 흉내 내는 분류기가 아니다. 계산으로 확인한 **서로 다른 개선안 중 하나를 선택**하고, 사용자가 명시적으로 선택한 대안을 다음 추천에 반영한다. 기하 측정과 문제 탐지는 기존 검사기가 담당한다.

| 항목 | 구현 범위 |
|---|---|
| 적층 | 측정한 방향 후보의 하향면 투영 합·높이·평평한 바닥을 해당 공정의 적용 범위 안에서 비교한다. |
| 절삭 | 공구 지름·날 길이·돌출 길이 변경과 구멍/포켓 치수 변경을 조합하고, 각 조합의 수치 충돌을 다시 계산한다. |
| 사용자 조건 | 형상 보존, 공구 변경 허용 여부를 우선 적용한다. 허용 범위에서 충돌 수가 가장 작은 후보만 비교한다. |
| 학습 모델 | 후보의 특징으로 선호 점수를 계산한다. 실제 추천 순서에 사용하며, 별도 정답 함수로 뒤에서 순서를 덮어쓰지 않는다. |
| 선호 반영 | 사용자가 대안의 ‘선호’ 버튼을 누른 경우에만 후보 간 특징 차이를 학습한다. 같은 공정·장비·재료·중점·변경 제약의 후속 선택에 반영한다. |
| 보호 조건 | 더 나쁜 지표만 가진 후보는 제외한다. 미확인 CAD 특징과 접근 범위는 개선안 뒤에도 남겨 둔다. |

초기 모델의 목표값은 이 프로젝트가 공개한 절충 선택 정책이다. 문헌을 읽은 전문가의 정답이나 실제 사용자 선호를 대량 확보한 것은 아니다. 초기 점수를 정하는 결정적 목적함수는 계산 비용이 낮고 직접 최적화할 수도 있다. 따라서 모델이 그 목적함수보다 우수하다고 주장하지 않는다. 학습 구조의 실제 추가 가치는 **명시적 사용자 선택으로 선호 모델을 바꿀 수 있다는 것**이며, 초기 모델의 품질과 목적함수 자체의 타당성은 별개다.

## 학습과 검증

`scripts/train_plan_model.py`가 실제로 `GradientBoostingRegressor.fit`을 실행한다. 96개/깊이 3 트리와 180개/깊이 4 트리를 검증 집합에서 비교한다. 최종 배포는 JSON 트리이고, 실행할 때 sklearn·pickle·외부 AI API가 필요하지 않다.

확장 데이터는 10개 계열의 물체 360개를 실제 메시로 생성하여 방향별 기하량을 계산하고, 별도로 720개 절삭 치수 시나리오에서 조건·제약별 개선안을 계산한다. 회전은 축 정렬·90도 회전·한 축 기울임·자유 회전을 섞어 바닥 면적이 있는 사례도 포함한다. 절삭 720개를 실제 CAD 파일 720개라고 부르지 않는다. 한 물체의 여러 방향·공정·중점이나 같은 절삭 시나리오의 여러 공구 조건을 독립 물체 수로 세지 않는다.

물체/시나리오 단위로 훈련·검증·시험을 분리한다. 쐐기와 토러스 계열은 훈련·모델 선택에 사용하지 않는다. 절삭의 복합 특징 한 계열도 전부 시험에 둔다. 별도로 훈련 범위 밖 크기와 지름 경계 근처 조건을 기록한다. 저장소의 기존 STEP 26개는 모델의 `fit`이나 두 모델 중 선택에 넣지 않고 CAD 입력 연결 회귀검사에 사용한다. 다만 개발 중 이 CAD 결과를 보고 생성 데이터의 바닥 접촉 사례 부족을 보완했으므로, 이 26개를 손대지 않은 독립 시험 집합이라고 부르지 않는다.

평가는 아래를 구분한다.

- 학습 모델: 공개한 목적함수 최선값과 선택값의 차이(후회값).
- 기존 고정 비교: 같은 후보 집합에서 기존/기본 규칙이 고른 결과의 후회값.
- 모델 제거: 점수를 모두 0으로 둔 선택 결과. 측정치와 후보는 그대로 둔다.
- 목적함수 직접 최적화: 비교 기준인 결정적 최적화. 이 기준의 후회값은 원칙상 0이다.
- 실제 영향: 모델 점수 또는 명시적 사용자 선호가 달라지면 선택이 바뀌는 독립 예제를 검사한다.

동점 처리도 실제 프로그램과 동일하게 점수를 소수 9자리로 반올림한 뒤 고정된 축/식별자 순서를 사용한다. 모델 내보내기 점수·선택은 sklearn 결과와 대조한다. 소스와 학습 스크립트의 시작/종료 SHA가 달라지면 모델을 쓰지 않는다.

## 범위와 남은 한계

적층 개선은 측정한 방향 후보 안의 선택이며 새 형상을 자동 설계하지 않는다. 절삭은 입력한 특징 치수와 공구 조건의 수치 관계를 다시 계산한다. 추천된 공구 치수는 **필요 조건 제안**이며 실제 보유 공구나 판매 제품이 아니다. 치수를 바꾸면 특징의 인접 관계가 달라질 수 있으므로 수정 CAD의 재검토가 필요하다. 유한한 공구/홀더의 충돌 경로, 강성 또는 가공 시간 계산을 대신하지 않는다.

사용자의 선호 기록은 `%LOCALAPPDATA%/DFM/plan_preferences.json`에 저장한다. 파일명·CAD 좌표·장비명 원문은 저장하지 않고, 조건의 해시와 정규화된 후보 간 차이만 저장한다. 초기화는 현재 조건의 선호 기록만 지운다. 선호를 저장하지 않아도 기본 모델로 사용할 수 있다.

모델 체크섬·입력 스키마·소스 SHA가 맞지 않으면 기본 비교로 돌아간다. 미확인 값을 0으로 채워 우수 후보로 만들지 않는다. 알려진 수치 충돌·미확인 범위는 모델 점수 때문에 사라지지 않는다.

## 개발 기록

- `run-001`, `run-002`: 초기 64개 메시/120개 절삭 시나리오 개발 실행. 평가 코드의 동점 처리가 실제 프로그램과 달랐으므로 배포 성능 근거로 사용하지 않는다.
- `run-003`: 확장 데이터 개발 중, 미지원 복수 솔리드 CAD의 예외를 검사 기록으로 보존하도록 평가기를 고치기 위해 모델 저장 전에 중단했다.
- `run-004`: 360/720 확장 개발 실행. 별도 CAD 입력 집합에서 학습 선택의 평균 후회값 0.01040이 고정 비교의 0.00890보다 나빴다. 모든 생성 메시를 자유 회전시켜 평평한 바닥 접촉 사례가 부족했음을 확인하고 회전 구성 범위를 수정했다. 이 실행의 시험/회귀 결과는 개발 검증으로 취급한다.
- `run-005`: 동결 뒤 독립 검토에서 현재 방향 유지 시 동등 후보의 축 이름을 실제 현재 벡터에 붙이는 표시 오류를 발견했다. 학습/시험 결과가 나오기 전에 실행을 중단하고 실제 방향에 맞는 이름을 표시하도록 수정했다.
- `run-006`: 소스·특징·목적함수·생성 범위를 동결한 뒤 새 시드 2909202612로 실행하는 최종 평가다. 정확한 데이터 분할·소스 SHA·모델 SHA·집합별 결과는 `run-006/evaluation.json`에 보존한다. 이 결과를 본 뒤 가중치나 표현을 다시 조정하지 않는다.

## 방법 참고자료

- [scikit-learn: Gradient Tree Boosting](https://scikit-learn.org/stable/modules/ensemble.html#gradient-tree-boosting): 초기 선호 점수의 지도 회귀 구현.
- [scikit-learn: GroupShuffleSplit](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.GroupShuffleSplit.html): 관련 표본을 같은 그룹에 보존하는 분할의 필요성. 이 프로젝트는 재현 가능한 명시적 계열/그룹 분할을 구현한다.
- [Freund 등, An Efficient Boosting Algorithm for Combining Preferences](https://www.jmlr.org/papers/v4/freund03a.html): 선호 쌍을 이용한 순위 학습의 원문. 이 프로젝트의 사용자 선호 모듈은 정규화된 선호 차이에 대한 로지스틱 최적화이며 RankBoost 구현이라고 주장하지 않는다.

이 방법 자료는 프로젝트의 구체적 가중치나 가공 한계를 공인하지 않는다. 기하 검사는 기존 AM·절삭 규칙의 문헌/조건과 연결되어 있고, 학습 목표의 절충 정책은 본 프로젝트의 설계 선택이다.
