## 1. 결론

**정보 구조는 잘 짜였고, 그 위의 시각화가 못 따라간다.**

v2.6은 한 화면에 모든 걸 쌓아 올려 단면 블록 하나에만 한글 설명이 1,725자 들어갔다.
3.0은 5개 탭으로 나눠 **탭당 본문 379~1,635자**로 줄였다. 이건 큰 개선이다.

| 탭 | 본문 글자 수 | 문서 높이 |
|---|---:|---:|
| 설계 조치 | 755자 | 1,633px |
| 방향 비교 | 665자 | 1,797px |
| 정밀 검토 | 768자 | 1,389px |
| 수정 전후 | 379자 | 1,100px |
| 근거·내보내기 | 1,635자 | 1,530px |

문장 자체도 좋아졌다. `프린팅 층마다 놓치거나 받쳐 줄 곳이 있나요?`, `벽이 입력한 최소 기준보다 얇은가요?`처럼
**검사 이름이 아니라 질문**으로 제목을 단 것, `현재 판단 → 확인할 위치 → 다음 행동` 3단 카드,
`먼저 할 일` 버튼이 해당 탭으로 이동시키는 것 — 전부 옳은 설계다.

문제는 그림 쪽이다. 확인한 것 중 **그림이 정보를 전혀 전달하지 못하는 경우가 3건**, 그리고
**결과가 항상 화면 밖에 있다**.

## 2. 시각화 — 실제로 깨져 있는 것

### (1) 벽 검토 3D: 부품 전체가 주황색이 된다

기본 예제 `07_bracket.step`에서 `벽 검토 실행`을 누르면 **부품 전체가 주황색으로 칠해진다.**
캡션은 "주황색 면은 가장 짧게 측정된 표본의 위치입니다"라고 말한다.

원인을 확인했다.

```
메시 삼각형 수: 24
thinnest_face_indices 개수: 24 · 고유 면: 24
강조되는 면 비율: 100.0%
측정 거리 범위: 4.0 ~ 40.0 mm
```

`detail.py`가 기준 미입력 시 `face_indices = m['thinnest_face_indices']`를 쓰는데
이건 항상 **가장 짧은 표본 상위 50개**다. 이 부품은 면이 24개뿐이라 전부가 "상위 50"에 들어간다.
4mm와 40mm가 같은 주황색으로 칠해진다 — **10배 차이나는 값이 같은 색이다.**

반대 방향의 실패도 있다. 면이 4만 개인 부품에서는 강조되는 게 50개 삼각형뿐이고,
배경 메시는 `opacity=0.18`이라 **작은 주황 점 50개가 반투명 유령 속에 묻힌다.**
면 수가 적으면 전부 주황, 많으면 안 보임 — 중간이 없다.

**수정 방향**

- 면을 칠하지 말고 **표본 점을 3D 마커로** 찍는다. `samples[].point_mm`과 `normal_chord_mm`이
  이미 결과에 있다. 거리로 색을 매기면(짧을수록 진하게) 면 수와 무관하게 동작하고,
  4mm와 40mm가 구분된다.
- 기준(`minimum_wall_mm`)이 입력돼 있으면 기준 미만만 빨강, 나머지는 회색 — 지금의 이진 강조는
  기준이 있을 때만 의미가 있다.
- `transparent` 기본값을 끄는 것도 같이 봐야 한다. 강조할 게 없는 항목(하향면 미검출 등)에서
  **18% 유령만 남아 형상을 알아보기 어렵다.** "강조할 위치가 있을 때만 투명"이 맞다.

### (2) 방향 비교: 추천 방향과 화면의 수치가 서로 다른 것을 가리킨다

`「높이를 낮추기」 기준으로 먼저 비교할 후보: **+Y**`라는 파란 안내가 뜨는데,
바로 아래 `적용할 방향` 선택은 여전히 `+Z`이고, 그 아래 큰 수치 3개도 +Z 값이다.
**추천과 수치가 한 화면에 동시에 나오면서 서로 다른 방향을 말한다.** 둘을 맞추려면
`이 후보를 아래 비교에 선택` 버튼을 눌러야 한다.

거기에 현재 방향과 같은 방향이 선택돼 있으니 증감이 전부 0인데,
`↑ +0 mm` / `↑ +0 mm²`처럼 **화살표가 붙은 델타 배지가 3개 뜬다.** 변한 게 없는데 변한 것처럼 보인다.

**수정 방향** — 추천이 나오면 `적용할 방향`을 곧바로 그 후보로 맞추고
(사용자가 직접 고른 뒤에는 유지), 델타가 0이면 배지를 생략한다.

### (3) 방향 비교 3D: 방향을 비교하는 화면인데 방향을 알 수 없다

이 탭의 그림에는 다음이 모두 없다.

- **빌드 플레이트(바닥 평면)가 없다.** 방향 비교에서 가장 중요한 정보가 "어느 면이 바닥에 닿는가"인데
  z=0 평면이 그려지지 않는다. 반투명 회색 사각형 하나면 해결된다.
- **현재 방향과 나란히 보여주지 않는다.** 제목이 "방향을 바꾸면 무엇이 좋아지고 나빠지나요?"인데
  그림은 하나뿐이다. 좌우 2열이면 질문에 그림만으로 답할 수 있다.
- **하향면이 강조되지 않는다.** `model_figure(model, preview, 'orientation_preview')`로 호출하는데
  그런 `finding_id`는 없어서 `finding=None`이 되고 강조가 통째로 꺼진다.
  게다가 `compare_orientations`가 `row.pop("overhang_face_indices")`로 방향별 하향면 인덱스를
  버리고 있어, 선택한 방향의 하향면을 다시 계산해야 한다 — `measure_orientation` 한 번이면 되고,
  기어박스 223,054삼각형에서 **32방향 전체가 1.8초**였으니 비용은 없다시피 하다.
- **`적층 +Z` 화살표가 약하다.** 초록 선 하나에 글자 하나이고, 투명 모드에서는 형상과 섞여 사라진다.

### (4) 단면 도면: 그림이 캔버스 가운데 1/3에만 그려진다

단면 비교 도면(파란 점선=이전, 주황 실선=현재)은 **이 앱에서 가장 잘 만든 그림이다.**
색 구분, 범례, 등축 비율, 위쪽의 수치 설명이 전부 맞다.

다만 X축이 −60~+60으로 잡히는데 **형상은 −20~+20에만 있다.** 도형이 화면 가운데 1/3로 쪼그라든다.
`yaxis=dict(scaleanchor='x', scaleratio=1)`로 등축을 강제하는데 컨테이너는 가로 ~1,100px·세로 340px라,
비율을 맞추느라 X 범위가 3배로 늘어난 것이다.

**수정** — 높이를 데이터 종횡비에 맞춰 잡거나(`height = width * (dy/dx)`), 축 범위를
데이터 범위 + 5% 여백으로 명시하고 `xaxis.constrain='domain'`을 준다. 한 줄이고 효과가 크다.
세로로 회전한 축 제목(`빌드 Y (mm)`)이 왼쪽에서 잘리는 것도 같이 고쳐진다.

### (5) 단면적 산점도: 선택한 단면을 찾을 수 없다

`st.scatter_chart`로 그리는 `높이에 따른 재료 단면적`에서

- `다른 단면`과 `선택한 단면`의 색이 **둘 다 옅은 파랑**이라 범례에서도 구분이 안 되고
  차트에서 어느 점이 선택된 건지 알 수 없다. Streamlit 기본 팔레트가 인접한 두 색을 골랐다.
- 데이터가 4점인데 **x축 눈금이 0~35까지 36개** 찍힌다. 빈 격자가 화면을 채운다.
- y축 제목이 회전·클리핑된다.

**수정** — 선택 단면은 색이 아니라 **형태와 크기로** 구분한다(주황 큰 점 + 그 높이에 세로 기준선).
`st.scatter_chart` 대신 Plotly로 직접 그리면 색·크기·눈금을 다 통제할 수 있고, 위의 단면 도면과
색 체계(파랑=이전, 주황=현재)를 맞출 수 있다. 지금은 두 그림의 색 규칙이 서로 다르다.

## 3. 결과가 항상 화면 밖에 있다

DOM에서 `실행` 버튼의 세로 위치를 실측했다.

| 정밀 검토 하위 탭 | 실행 버튼 y좌표 |
|---|---:|
| 벽 | **945 px** |
| 단면 | **855 px** |
| 층간 | 691 px |

캡처는 1,600×1,100 뷰포트인데, **실제 노트북 브라우저의 콘텐츠 높이는 보통 700~800px다.**
즉 일반적인 화면에서는 `벽 검토 실행` 버튼 자체가 안 보이고, 결과는 훨씬 더 아래다.

버튼 위에 매번 쌓이는 것들:

| 요소 | 대략 높이 |
|---|---:|
| 제목 `적층제조 설계 검토` + 부제 | 90px |
| `결과 보기` 세그먼트 | 55px |
| `전체 검토 판단 ·…` expander | 50px |
| `07_bracket.step · 재료 압출 · 현재 높이 40 mm` 캡션 | 25px |
| `기하 기반 설계 검토입니다…` 캡션 | 25px |
| `확인하려는 질문을 선택하세요` H2 | 60px |
| `자세히 확인할 질문` 세그먼트 | 55px |
| 질문 소제목 + 공정별 설명 3줄 | 140px |
| 단면 배치 방법 선택 + 설명 | 90px |
| 실행 버튼 | 55px |

위 5개(약 245px)는 **다섯 탭 모두에서 똑같이 반복된다.**

**수정 방향**

- 제목·부제는 첫 화면에서만 크게 두고, 결과가 있으면 한 줄로 줄인다.
- `기하 기반 설계 검토입니다…`는 매 탭 고정 캡션이 아니라 하단 푸터로.
- 공정별 설명 3줄(`reason`/`action`)은 expander 안으로. 지금 화면 위쪽에서 가장 많은 자리를
  차지하는데, 같은 내용이 결과 카드의 `다음에 할 일`에 다시 나온다.
- **가장 효과적인 건 실행 버튼을 없애는 것이다.** 아래 §4 참고.

## 4. 첫 실행이 "버튼을 더 누르세요"로 끝난다

기본 예제로 검토를 돌린 직후 화면 최상단 카드:

> **지금까지 검출된 수정 후보는 없고, 추가 확인이 남아 있습니다**
> 먼저 할 일 · 얇은 벽·세부 특징 — '벽 검토 실행'을 누르세요.

`얇은 벽·세부 특징 확인하기` → 정밀 검토 탭 → 스크롤 → `벽 검토 실행` → 결과:

> **벽은 측정됐지만 비교 기준이 없습니다**
> 다음에 할 일 · 최소 벽 기준(mm)과 근거를 입력하세요.

**세 번 클릭하고 스크롤 두 번 한 결과가 "기준을 입력하세요"다.**

그런데 이 부품의 벽 검토는 **0.5초**다(펌프 하우징 46,770삼각형도 1.1초). 빠른 검토 자체가 0.3~1.8초인데
그보다 빠른 계산을 별도 버튼 뒤에 숨겨 둔 셈이다.

**수정 방향**

- **작은 부품(예: 삼각형 5만 개 이하)은 빠른 검토에 벽 측정을 포함**한다. 그러면 첫 화면에서
  "가장 짧게 측정한 거리 4 mm"가 바로 보이고, `먼저 할 일`이 "버튼 누르기"가 아니라
  실제 설계 판단이 된다. 큰 부품만 지금처럼 버튼을 남긴다.
- 기준 입력 expander(`이 화면에서 벽 기준 입력·변경`)가 기준 미입력 시 **자동으로 펼쳐지는 것**도
  다시 볼 필요가 있다. 바로 옆 캡션이 "기준을 모르면 비워 둔 채 측정 위치부터 볼 수 있습니다"라고
  말하면서 화면은 그 입력란을 먼저 들이민다. 측정 결과를 먼저 보여주고 기준 입력은 그 아래가 맞다.
- §3의 `설계 조치` 카드에서 바로 실행되게 하는 것도 방법이다. `얇은 벽·세부 특징 확인하기` 버튼이
  탭 이동만 하지 말고 계산까지 하고 이동하면 클릭 3회가 1회가 된다.

## 5. HTML 보고서 — 97.6%가 JSON이고 그림이 0장이다

`근거·내보내기`의 `검토 보고서 HTML`이 "사람에게 설명하기"용 산출물이다.
브래킷 하나(층간 200층 포함)로 생성해 구성을 분석했다.

```
전체 685,453자
<pre> 블록 12개 · 합계 669,091자 = 97.6%
  상위 1개 블록만 635,207자  (층간 200층 원자료)
<img|svg|canvas> 태그 수: 0
```

- **97.6%가 `<pre>` 안의 원자료 JSON**이다. 기어박스급(1,500층 한도)이면 수 MB가 된다.
- **그림이 한 장도 없다.** 3D 형상도, 단면 도면도, 방향 비교도 없다.
  화면에서는 가장 잘 만든 단면 도면이 보고서에는 존재하지 않는다.

구조·문장 자체는 좋다. 앵커 목차, 판단 카드(색 구분), 조건 표, 출처 각주, 인쇄 CSS(`break-inside:avoid`)까지
들어 있다. 여기에 그림만 넣으면 그대로 발표 자료가 된다.

**수정 방향**

- 단면 윤곽은 이미 `rows[].outlines`에 좌표로 있다. **인라인 SVG로 그리면 의존성 0, 용량 수 KB다.**
  이전·현재 두 단면을 화면과 같은 색 규칙으로 그리면 보고서만 봐도 무엇이 바뀌는지 알 수 있다.
- 3D는 방향별 외곽(`placed_extents_mm`)만으로도 간단한 정사영 3면도를 SVG로 그릴 수 있다.
  Plotly 이미지 내보내기(kaleido)는 의존성이 늘어나므로 권하지 않는다.
- 원자료 JSON은 `<pre>`에 박지 말고 **별도 `.json` 첨부**로 빼고, 보고서에는 링크만 둔다.
  이미 `전체 결과 JSON` 버튼이 따로 있으므로 중복이다. 그것만으로 파일이 685KB → 16KB가 된다.

## 6. 잘 된 것 (유지할 것)

- **질문형 제목.** `벽이 입력한 최소 기준보다 얇은가요?` / `어느 높이에서 단면 모양과 넓이가 크게 바뀌나요?`
  — 검사 이름이 아니라 사용자의 질문을 제목으로 단 것.
- **`현재 판단 → 확인할 위치 → 다음 행동` 3단 카드**가 모든 검사에서 같은 구조로 반복된다.
  학습 비용이 한 번만 든다.
- **층간 결과 화면.** `검사한 200개 층에서 세 종류의 후보가 발견되지 않았습니다` + 검사별 카드
  (후보 층 수, 설명, 확인 범위). v2.6의 7열 표보다 압도적으로 읽기 쉽다.
  다만 세 카드가 전부 0일 때 400px를 쓰므로, 0일 때는 한 줄 + expander로 접는 게 낫다.
- **단면 비교 도면의 색 규칙**(파란 점선 = 이전, 주황 실선 = 현재)과 그 아래 한 줄 설명.
- **`점 하나가 실제 계산한 단면 하나입니다. 점 사이의 모양을 추정하는 연결선은 표시하지 않습니다.`**
  — 산점도를 꺾은선으로 그리지 않은 이유를 화면에서 밝힌다. 이런 절제가 이 프로젝트의 성격을 보여준다.
- **공정별 설정 분리 저장**(`key=f'wall_limit_{process}'`). MEX 기준이 VPP로 새지 않는다.
- **stale 처리.** 설정이 바뀌면 이전 결과를 지우고 재실행을 요구하는 것, 상세 결과의
  fingerprint·profile·transform을 대조해 다른 입력의 결과를 거부하는 것.
- **근거·내보내기 탭**의 4종 산출물 구분(`사람에게 설명하기 / 슬라이서에서 확인하기 /
  측정값 재현하기 / CAD 수정하기`)이 용도별로 정확히 나뉜다.

## 7. 그 밖의 작은 것들

- **사이드바 `설계 검토` 버튼이 폼 맨 위에 있다.** 버튼 아래에 그 버튼이 적용할 설정
  (탐색 각도, 26방향 비교, 장비 기준, 빌드 공간)이 이어진다. 읽는 순서상 아래 설정이 버튼과
  무관해 보인다. 폼 상단·하단 양쪽에 두거나(Streamlit은 제출 버튼 복수 배치 가능),
  설정 요약 한 줄을 버튼 옆에 붙이면 해소된다.
- **`무작위 형상 테스트` 입력 항목**은 개발·검증용이다. 배포본에서는 `검증용 예제 형상` 정도로
  이름을 바꾸거나 숨기는 게 맞다.
- **G-code의 `Cura 기준 실험`**이 `내 G-code`와 같은 선택 상자에 있다. 현재 부품과 무관한
  고정 파일이라고 캡션에 적혀 있지만, 나란히 두면 오해를 부른다. expander를 나누는 게 낫다.
- **`부피 검산`이 맨 아래 접힌 expander 안에 있다.** 이벤트 단면 방법의 핵심 주장인데
  네 개의 접힌 expander 중 두 번째에 들어가 있다. 앞 보고서 §3에서 지적한 것처럼
  많은 실제 CAD에서 이 값이 `미확정`으로 나오는데, 사용자는 그 사실조차 펼쳐 보지 않으면 모른다.
- **빈 공간.** 첫 화면은 좌 3 : 우 2 두 열인데 오른쪽 열 내용이 짧아 화면 아래 절반이 비어 있다.
  3D를 더 크게 쓰거나 치수·경고를 3D 아래로 내리면 첫인상이 달라진다.

## 8. 권장 작업 순서

| 순위 | 작업 | 근거 | 작업량 |
|---|---|---|---|
| 1 | 벽 3D를 면 칠하기 → 표본 점 마커(거리로 색) | 기본 예제에서 24/24면 전부 주황, 4mm와 40mm가 같은 색 | 함수 1개 |
| 2 | 단면 도면 축 범위·높이를 데이터 종횡비에 맞춤 | 도형이 캔버스 1/3로 축소됨 | 2줄 |
| 3 | 방향 비교에 빌드 플레이트 + 현재/선택 2열 + 하향면 강조 | 방향 비교인데 방향을 알 수 없음 | 중간 |
| 4 | 보고서의 원자료 JSON 분리, 단면 SVG 삽입 | 685KB 중 97.6%가 JSON, 그림 0장 | 중간 |
| 5 | 소형 부품 벽 측정을 빠른 검토에 포함 | 0.5초짜리를 클릭 3회 뒤에 숨김 | 조건 1개 |
| 6 | 정밀 검토 상단 고정 영역 축소 | 실행 버튼 y=945px | 배치 조정 |
| 7 | 추천 방향을 `적용할 방향`에 자동 반영, 0 델타 배지 제거 | 한 화면에서 +Y 추천·+Z 수치 | 몇 줄 |

1·2·9번은 반나절이면 되고 체감이 가장 크다. 4번은 교수님께 보여줄 산출물의 질을 바꾼다.
