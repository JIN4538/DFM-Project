# Claude 검토 후 사건 단면 재검증 보관본

2026-09-15, Windows / Python 3.12.14에서 저장소 STEP 21개에 대응하는 기존 변환 캐시를 읽었다. 곡면 전용 입력 2개는 솔리드 선택 대상에서 제외하고, 나머지 19개에서 OCCT 적분 체적이 가장 큰 솔리드를 선택해 +Z로 배치했다. 원본 CAD·캐시를 수정하지 않았으며 새 STEP 변환, 슬라이서 실행, 실물 출력·치수 측정은 수행하지 않았다.

이 자료는 Claude 보고서에 첨부되지 않은 외부 실행 로그를 대신하는 자료가 아니다. 이번 개선 코드와 기존 변환 캐시를 사용한 별도 재검증이다. 사건 검토의 기하 계산과 기본 예산은 유지했고, 부분합·누락 사유 메타데이터와 명시적 자동 전환을 추가한 시점이다. 실행에 사용한 모든 `amdfm/`·`src/core/` Python 파일 SHA와 실행 중 변경 여부를 [summary.json](summary.json)에 기록했다. 실행 중 소스 변경은 없었다.

| 사건 검토 결과 | 개수 | 자동 모드의 처리 |
|---|---:|---|
| 전체 사건 단면 완료 | 5 | 사건 결과 유지 |
| 표현 가능한 두 내부 표본을 확보하지 못한 구간만 있음 | 5 | 부분 결과·계산된 부분합·누락 높이 기여 범위 제공 |
| 실제 단면 재구성 실패 | 1 | 부분 결과와 실패 사유 유지 |
| 사전 예산 초과 | 7 | 최초 사건 시도를 보존하고 균등 64개 단면 계산 완료 |
| 입력 위상 조건 미충족 | 1 | 미확정 유지 |

따라서 보고서의 기존 5개 완료·6개 부분·7개 예산 거부·1개 위상 거부 분포는 이번 캐시에서도 재현됐다. 균등 단면 계산 완료를 사건 적분 완료로 집계하지 않는다. 사건/균등 기하 계산 시간 합계는 66.538초였고, 각 작업자는 90초 한도로 격리했다. 저장·프로세스 준비 시간은 이 합계에 포함하지 않는다. 실패·시간 초과 작업은 없었다.

부분합과 누락 높이 기여 범위는 전체 체적의 검증된 상·하한이 아니다. 예를 들어 Raspberry Pi 선택 솔리드에서 계산된 부분합과 같은 메시의 독립 사면체 체적의 상대차는 약 `4.35e-10`, 누락 기여 범위/부분합은 약 `8.82e-15`였다. 누락 구간이 아주 작아도 계산한 단면 자체의 수치 오차까지 그 범위로 제한할 수 없다. CAD 해석 체적과 메시 체적도 서로 다른 기준으로 기록했다.

## 파일과 출처

- `file_*.json`: 19개 솔리드별 입력 SHA, 선택 바디·메시 SHA, 배치, 독립 사면체 체적, CAD 적분 체적, 사건 결과와 필요한 경우 별도 균등 결과. 화면 윤곽 배열 대신 미확정 구간·계산 개수·수치 결과를 보존했다.
- [summary.json](summary.json): 위 개별 결과와 실행 환경·코드 SHA·집계. 개별 결과의 중복을 포함하는 읽기 편한 종합 기록이다.
- [audit_event_corpus.py](audit_event_corpus.py): 실행한 재현 스크립트 원본.
- [archive_manifest.json](archive_manifest.json): 복사한 21개 원본 파일의 작업공간 상대 출처, 크기, SHA-256. 원본 바이트를 그대로 복사하고 대조했다.
- [focused_test_results.json](focused_test_results.json): 기존 사건 검사 24개와 새 누락 계약 검사 12개의 Python 3.12.14·3.13.15 실행 결과. 각각 `36 passed in 2.49s`, `36 passed in 9.29s`였다. 도구 출력과 종료 코드를 근거로 기록했으며 전체 stdout 로그 파일은 당시 별도로 저장하지 않았다. 전체 저장소 회귀검사 결과와 구분한다.

원본 보관 위치는 작업공간의 `study/claude-review-20260915/event-corpus-audit-01/`과 그 상위의 실행 스크립트다. 입력 캐시는 `study/random-shape-audit/final-01/file_*/model.json`·`model.npz`였다. 기록 내부의 절대 경로는 **실행 당시 머신의 출처**이며 GitHub 복제본 안의 파일 경로가 아니다. 원래 캐시는 이 폴더에 복제하지 않았으며 캐시 SHA를 기록했다.

## 재현

저장소 루트에서 해당 입력 캐시를 확보한 뒤 **아직 없는 출력 폴더**를 지정한다. 스크립트는 기존 결과 폴더를 덮어쓰지 않는다.

```powershell
.venv/Scripts/python.exe -X utf8 validation/v3/claude-review-20260915/event-corpus/audit_event_corpus.py --repo . --cache ../study/random-shape-audit/final-01 --out ../study/claude-review-20260915/event-corpus-audit-02
```

새로 STEP을 변환하면 커널·설정·플랫폼에 따라 캐시 좌표가 달라질 수 있으므로 이 기록과 같은 SHA인지 먼저 확인한다. 캐시 없이 실행 가능한 합성 형상·실패 반례 검사는 다음과 같다.

```powershell
.venv/Scripts/python.exe -m pytest tests_v3/test_event_omission_contract.py tests_v3/test_event_sections.py -q
```
