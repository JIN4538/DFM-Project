# 절삭 강화학습 최종 검증 — 2026-09-29

**Double DQN 순차 계획기를 구현하고 앱에 연결했다. 다만 최종 시험에서는 기존 조합 후보보다 더 좋은 안을 찾지 못했다. 따라서 강화학습이 기존 알고리즘보다 우수하다고 주장하지 않는다.** 신경망이 만든 개별 특징 수정 조합은 수치 재검산 후 비교하며, 기존보다 나쁜 추천으로 교체하지 않는다. 기존 후보 생성·수치 검증을 없애는 방식으로 연결하지 않았다.

## 구현과 계보

- 입력 64개 → 은닉층 64·32(ReLU) → 행동 가치 1개. 온라인망/표적망, 경험 재생, Double Q 대상값, Huber 손실, Adam을 실제 사용한다.
- 측정한 CAD 특징의 치수와 공구 조건을 한 단계씩 바꾸며 상태·충돌을 재계산한다. 최대 64특징·24단계이다. 도중의 가장 좋은 검증 상태를 보존한다.
- `run-002`: 24,000 episode, 104,944 transition. 검증으로 선택한 23,500 episode 체크포인트를 다음 실행의 초기망으로 사용했다.
- `run-003`: 새 시나리오에서 추가 12,000 episode, 51,333 transition, 12,802 gradient update. 최종 선택은 검증 비용이 가장 낮았던 11,500 episode 체크포인트이다.
- 두 실행 합계 36,000 episode·156,277 transition을 수행했다. 선택되지 않은 마지막 학습 구간까지 최종 가중치에 모두 반영됐다고 해석하지 않는다.
- 초기 개발 `run-001`은 최종 가중치의 선행 학습이 아니다. 실패·개선 경과 기록으로 보존했다.

## 최종 분리 시험

`run-003`은 새 seed `2026093049`를 사용한다. 학습 600개, 검증 80개, 시험 490개 수치 시나리오이다. 시험 중 140개는 학습하지 않은 특징 조합 가족 2개이다. 사용자 중점 3종과 형상/공구 변경 허용 3종을 독립 조합했다. 사례는 분석적 CAD 특징 치수의 절차적 조합이며, 490개 CAD 파일을 직접 측정한 자료라는 뜻은 아니다.

모든 비교는 먼저 남은 수치 충돌 수, 그다음 동일한 공개 변경 비용을 비교한다.

| 비교 대상 | DQN 우수 | DQN 열세 | 동일 |
|---|---:|---:|---:|
| 기존 후보 중 정확한 최저비용안 | 0 | 151 | 339 |
| 한 단계 탐욕적 선택 | 50 | 108 | 332 |
| 무작위 행동 | 345 | 22 | 123 |
| 같은 구조의 미학습 신경망 | 458 | 0 | 32 |

기존안과 DQN의 남은 수치 충돌 수는 490건 모두 같았다. 차이는 변경 비용에서 생겼다. 평균 비용은 DQN `0.613751`, 기존 후보 최저비용 `0.584296`, 탐욕법 `0.606040`이다. 비용은 프로젝트 선택 목적함수이며 절삭 시간·금액·공차의 단위가 아니다.

시험 중 439건에서 2단계 이상의 개선 경로가 생성됐고 가장 긴 채택 경로는 22단계였다. 최대 단계 수 자체를 모델 성능으로 평가하지 않는다.

개발 실행 `run-002`에서는 350건 중 4건이 기존 최저비용보다 좋았지만, 새 최종 시험에서 이 효과를 재현하지 못했다. 따라서 그 4건만 골라 최종 성능으로 홍보하지 않는다. 자세한 원자료는 각 실행의 `test-evaluation.json`에 더 나쁜 사례까지 모두 남아 있다.

## 실제 앱 선택 경로 검증

`scripts/audit_rl_planner.py`가 최종 `dfm/enhanced_planning.py`를 실제 호출했다. 이 결과는 단순히 `min(기존, DQN)`을 계산한 이론상 보호 수치와 별개이다.

- 490건 모두 실제 선택 경로를 통과했다.
- 강화학습 제안 때문에 기존 추천보다 나빠진 경우 **0건**.
- 새 강화학습안의 최종 채택 **0건**. 나은 안이 확인되지 않아 기존 추천을 유지한 것이며, 검증 건수를 AI 우위 건수로 설명하지 않는다.
- 모델 사용 불가 **0건**, 평균 기존+새 추천 비교 시간 약 **0.0165초/건**(최종 선택 코드에 대한 Windows 재실행).
- 실제 STEP 입력에 대한 검증은 다른 에이전트의 `scripts/audit_neural_cad.py` 및 해당 `cad/` 결과에 별도로 기록한다. 수치 시나리오를 STEP 검증으로 합산하지 않는다.

최종 선택 코드에서 검증된 의미 필드를 복사하고 충돌 수가 더 적은 안을 채택할 때 대안을 재정리한 후, 같은 490건을 `run-003/wrapper-audit-final.json`에 새로 실행했다. 결과는 기존 감사와 동일하게 악화 0·채택 0·모델 사용 불가 0건이다. 이전 `wrapper-audit.json`도 덮어쓰지 않고 보존했다. 최종 실행 파일의 `arbitration_sha256`과 `runtime_sha256`이 실제로 검사한 코드 버전을 고정한다.

## 안전한 계산 계약 검사

`tests_v3/test_rl_planner.py`: **18개 통과**, `rl-unit.xml`.

검사 내용: 서로 다른 CAD 면의 독립 수정, 돌출→날 길이 순서, 폭→반경 순서, 모든 단계의 공구/형상 잠금, 원래 치수·CAD 면 불일치 거절, 미확인 특징·다른 축·가려진 위치 보존, 배율 변환 불변성, 학습/JSON 추론 일치, 가중치 변조·누락·소스 변경 시 거절, 비정상 큰 비율에서 NaN/무한대 결과를 검증 완료로 반환하지 않음.
