2026-09-29 Windows · Python 3.12.14 · 최종 `cnc-run-003`.

**33개 STEP에서 594개 조건의 통합 계약 검사를 통과했다. 실제 선택 개선안의 수치 비교는 122건이며, 이 중 RL 혼합 조치가 1건 채택됐다.** 적용 불가와 예산 초과를 좋은 결과로 합산하지 않는다.

공구는 지름/날 길이/돌출 길이 4/8/10 mm와 12/15/25 mm, 홀 깊이비 비교값은 4였다. 잠금은 자유 변경, 형상 유지, 공구 변경 금지다. 사용자 개인 선호 파일은 사용하지 않았다. 소스·모델 SHA와 실행 중 불변 여부는 [summary.json](summary.json)에 있다.

## 실제 달라진 제안

`examples/corpus/9.1 Pump_housing.stp`, +Z, 공구 4/8/10 mm, 변경 잠금 없음에서 다음 결과를 재현했다.

| | 기존 선택안 | 최종 RL 선택안 |
|---|---|---|
| 공구 돌출 길이 | 10 → 30 mm | 10 → 13 mm |
| 형상 변경 | 없음 | CAD 면 57의 원통 구간 30 → 13 mm |
| 남은 수치 충돌 | 0 | 0 |
| 공개된 프로젝트 비용 | 0.6176225490 | 0.5963634832 |
| 돌출 길이/공구 지름 | 7.5 | 3.25 |

RL은 돌출 길이를 먼저 바꿔 충돌을 9→1개로 줄이고, 특정 원통 구간만 바꿔 1→0개로 줄였다. 다른 8개 홀의 치수를 일괄 수정하지 않았다. **원통 구간을 줄이는 설계 변경을 포함하는 교환관계**다. 이 변경의 기능상 수용 여부를 자동으로 안다고 해석하지 않는다. 두 선택안 모두 `cnc_coverage`, `cnc_visibility` 미확인 항목을 유지했다. 단계와 정확한 수치는 [analysis.json](analysis.json), 전체 조건은 [records.jsonl](records.jsonl)에 있다.

## 검사 범위

- 실제 제품의 STEP 로더, 절삭 특징 측정, 기존 계획 함수, 최종 `enhanced_planning` 함수를 호출했다. 예측값을 측정값으로 대신 쓰지 않았는지, 원보고서 불변, 잠금 유지, 비용의 유한성, 미확인 항목 보존을 검사했다.
- 계획 검산은 실제 변경안을 `rl_planner.evaluate_changes`에 다시 넣어 측정된 특징 치수의 규칙을 재계산했다. STEP를 수정·재생성하여 모든 연동 특징을 다시 측정한 것은 아니며, 별도의 CAD 커널 구현과의 대조나 모든 기하 공식의 독립 증명도 아니다.
- 가림 표본 검토는 이번 감사에서 실행하지 않았으며 해당 미확인 상태를 보존했다. 단일 솔리드가 아닌 조립체·표면 입력의 차단 상태도 유지했다.
- gearbox의 인식 특징 90개는 RL의 64개 예산을 넘는다. 해당 6조건은 최종 선택 객체가 기존 선택과 완전히 같은지를 확인했고, RL 수치 재검산을 수행했다고 세지 않았다.
- 단일 조건의 측정·기존 계획·최종 계획을 모두 포함한 시간은 평균 0.0148초, 95백분위 0.0761초였다. RL이 적용된 126조건만 보면 평균 0.0439초, 95백분위 0.1373초다. STEP 읽기 시간은 이 값에서 제외됐고 전체 실행은 234.9초였다. 단독 RL 추론 시간으로 인용하지 않는다.

이 결과는 **현재 측정 범위와 공개된 정책의 통합 검사**다. 모델의 일반 정확도나 전체 CAD 특징 인식 정확도 수치가 아니다. 학습 모델 자체의 별도 평가와 구분한다.
