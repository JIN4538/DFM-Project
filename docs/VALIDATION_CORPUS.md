# 무작위 형상 전수 검토의 재현 방법

이 워크플로는 형상 가져오기, 좌표·면적 산술, 공정별 적용 범위, 상세 계산의 미확정 영역을 분리해 기록한다. 제조 성공·강도·열변형·표면 품질의 실물 검증을 대신하지 않는다. 변경 전 결과는 [기준 기록](project-knowledge/CORPUS_BASELINE_2026-09-14.md)에 보존한다.

## 2026-09-15 완료 기록

바탕화면 원본 31개를 재귀 조사했다. 형상은 STEP 21개, STL 4개, 3MF 1개이고 동반 TXT가 5개다. `final-01`에서 26개 형상을 모두 가져와 전체 조립체와 개별 솔리드 186개 대상에 4공정씩 총 744개 결과를 생성했다. 종료 시 원본 31개 SHA가 모두 유지됐다. 이 수치는 형상 검토 실행의 완료이며 아래의 부분·미확정 계산까지 성공으로 바꾼 수치가 아니다.

| 상세 계산 | 확정/계산됨 | 부분 결과 | 미확정 | 실행 한도 초과 | 해당 없음 |
|---|---:|---:|---:|---:|---:|
| 64개 공통 단면, 4공정 | 664 | 8 | 72 | 0 | 0 |
| 벽 법선 거리, 4공정 | 308 | 364 | 72 | 0 | 0 |
| MEX 층 및 다른 공정의 적용 범위 | 164 | 1 | 13 | 8 | 558 |

MEX 층 실행 한도 초과 8건은 0.2 mm 간격에서 1,693~30,000개 층이 필요했으나 명시된 1,500개 실행 한도를 초과한 경우다. 프로세스 실패나 시간 초과가 아니다. 검토 층 수는 0, 체적과 점수는 `null`로 남겼다. 크기나 층 간격을 변경하지 않았다. 공통 단면의 부분 결과는 Pi STEP 솔리드 [67](project-knowledge/PI_BODY67_SECTION_LIMIT_2026-09-15.md)과 [108](project-knowledge/PI_BODY108_SECTION_LIMIT_2026-09-15.md)의 국소 교선 중첩을 각각 독립 추적했다. 폐곡면 검사만으로 자기교차 부재를 보장하지 않는다.

독립 정점 투영·삼각형 외적·테트라 체적 산술 검사에서 수치 오류는 없었다. 최대 높이 차이는 약 9.1×10⁻¹³ mm, 투영면적 차이는 약 1.2×10⁻¹⁰ mm²다. 표면 STEP 두 파일의 고분자 PBF 오버행 적용 범위 오류는 원감사에 보존하고, 최신 코드의 빠른 검토를 별도 `refreshed-01`에서 재실행해 `unknown → not_applicable`로 교정했다. 744개 모두 기하·방향 수치의 변화가 정확히 0이었고 판정 측정값·문제면 선택도 일치했다. 벽·층·균등 단면 상세 수치는 원감사 코드와 원결과 SHA를 붙여 재사용했다.

단면 체적 차이가 큰 상위 5개 대상의 256/1024개 재표본화 10건도 모두 계산했다. 같은 메시 테트라 체적 대비 상대 차이는 다음과 같다.

| 대상 | 64개 | 256개 | 1024개 |
|---|---:|---:|---:|
| Cooling fan 솔리드 2 | 35.7254% | 6.64654% | 3.91294% |
| Raspberry Pi 솔리드 96 | 9.04958% | 2.63396% | 0.416770% |
| Machine Frame 솔리드 3 | 2.99847% | 0.187405% | 0.187405% |
| Machine Frame 솔리드 4 | 2.99847% | 0.187405% | 0.187405% |
| Raspberry Pi 솔리드 71 | 2.36059% | 0.0139160% | 0.0156575% |

표본 증가가 항상 단조 수렴하거나 연속 높이의 극값을 찾는다는 보장은 없다. 특히 냉각팬의 1.2 mm 끝판 누락은 [별도 독립 단면·이벤트 구간 분석](project-knowledge/CROSS_SECTION_ALIASING_2026-09-15.md)에서 확인했다. 이후 개발한 이벤트 단면 검증은 이 균등 단면의 전수 결과와 별도로 기록한다.

공개 집계는 [전수 결과](../validation/v3/random-corpus/uniform-final-statistics.json), [상위 5개 정밀화](../validation/v3/random-corpus/section-refinement-statistics.json), [빠른 검토 갱신](../validation/v3/random-corpus/quick-refresh-statistics.json)에 있다. 원형상은 Git에 추가하지 않았다. 전체 JSON·HTML 및 코드 동결본은 저장소 옆 `study/random-shape-audit/final-01`, `refinement-01`, `refreshed-01`에 보존한다.

## 전수 실행

```text
python scripts/audit_random_models.py --input <형상폴더> --out <새감사폴더> --cad-timeout 180 --file-timeout 7200 --detail-timeout 90 --section-samples 64 --jobs 2
```

- 입력은 재귀 조사하며 원본 SHA-256, 파일 크기, 형식, 동반 TXT를 보존한다. 출력 폴더가 이미 있거나 입력 폴더 내부라면 실행하지 않는다. 종료 시 모든 입력 파일의 SHA를 다시 확인한다.
- 실행 시 엔진 `amdfm/`·`src/`와 배치 스크립트를 출력 폴더에 동결한다. 복사 전후 코드 SHA가 바뀌면 시작을 중단한다. 작업 중 편집된 엔진과 한 실행의 결과가 섞이지 않는다.
- 파일별 독립 프로세스와 시간 한도를 사용한다. 완료된 빠른 결과와 각 상세 결과를 즉시 별도 JSON에 보존한다. 실패·시간 초과·중단 단계도 파일/케이스 기록에 남긴다.
- 4공정 모두 `build_volume_mm=None`으로 검토한다. STL은 mm 가정이며 크기를 변경하지 않는다. 기본 배치는 +Z, 방향 비교26개, CAD 다중 솔리드는 전체와 각 솔리드를 구분한다.
- 벽 법선 거리·MEX 층 검토·공통 단면을 호출한다. 다른 공정에 MEX 층 판정을 적용하지 않는다. 벽과 공통 단면도 각 공정 프로필로 독립 호출하며, 물리적 합격 기준으로 바꾸지 않는다.
- `summary.json`·`summary.csv`·`index.html`, 파일별 `record.json`·`record.html`, 대상/공정별 JSON·HTML을 만든다. 입력 거절도 HTML에서 이유를 확인할 수 있다.

26방향 높이는 정점의 축 방향 투영으로, 투영면적 합은 삼각형 외적으로 독립 대조한다. 체적은 중심화한 부호 있는 테트라 적분과 비교한다. CAD B-rep/메시 전체 체적의 일치가 국소 형상 오차를 보증하지는 않는다.

## 단면 표본 수 증가

```text
python scripts/refine_corpus_sections.py --audit <완료된감사폴더> --out <새정밀화폴더> --top 5 --samples 256 1024 --detail-timeout 300 --jobs 2
```

전체 단면이 확정된 케이스에서만 균등 중점 적분 체적을 계산한다. 독립 테트라 체적·CAD 체적과의 상대 차이를 **재표본화 우선도**로 사용한다. 이 차이를 곧바로 엔진 오류라고 부르지 않는다. 미확정 케이스에는 숫자 순위를 붙이지 않고 별도 진단 대상으로 남긴다.

동일 파일·솔리드의4공정은 같은 공통 단면 기하를 비교하므로 상위5개 선정에서는 하나의 대상으로 묶는다. 원감사의 동결 엔진과 모델 캐시를 읽고, 모델 fingerprint와 코드 SHA를 검증한 뒤256·1024표본을 다시 계산한다. 각 수준의 상태, 확정 표본 수, 최대 표본 면적, 적분 체적, 기준별 상대 차이를 JSON·HTML에 보존한다. 극값이 표본 사이에 있거나 메시 근사가 지배적이면 표본 증가로 차이가 줄지 않을 수 있다.

## 빠른 검토·근거 문구의 후속 갱신

```text
python scripts/refresh_corpus_reports.py --audit <완료된감사폴더> --out <새갱신폴더> --jobs 2
```

이 단계는 원본 CAD 수입과 상세 계산을 반복하지 않는다. 원감사의 모델 캐시를 fingerprint로 확인하고 현재 엔진으로 빠른 검토만 다시 실행한다. 기하·방향 수치, 판정 측정값, 문제면 선택이 달라지면 해당 케이스의 갱신을 차단한다. 허용한 상태 변경은 표면 STEP의 고분자 PBF 오버행 `unknown → not_applicable` 교정뿐이다. 문구·근거 설명은 갱신할 수 있다.

상세 결과에는 `source_code_sha256`, `original_detail_sha256`, `recomputed_in_report_refresh=false`를 붙인다. 최종 JSON과 HTML은 현재 빠른 검토 코드와 원래 메시·상세 계산 코드를 구분한다. 원감사·정밀화 결과는 그대로 남으며, 갱신을 전체 상세 계산의 재실행으로 보고하지 않는다.

관련 회귀 검사는 `tests_v3/test_corpus_audit.py`와 `tests_v3/test_corpus_followups.py`에 있다. 알려진 CAD 상자에 대한4공정 실행과 실패 입력 보존 외에도, 미확정 값이0으로 바뀌는 경우·기하 숫자 변화·허용하지 않은 상태 변경을 차단하는 반례를 검사한다.

## 형상 변화 구간의 추가 검산

```text
python scripts/audit_event_sections.py --corpus <완료된감사폴더> --out <새사건검산폴더> --jobs 2 --timeout 90 --max-samples 8192
```

공통 단면 기하는 공정 중립이므로 고유 입력/솔리드마다 한 번 실행한다. 단일 솔리드의 whole/개별 선택을 함께 대조하면 이번 폴더에서는195선택이며, 중복9개를 제외한186대상은 균등 전수744사례의 기하 대상과 일치한다. `run_detail`을 통과하므로 곡면 STEP·조립체·미확정 다중 메시의 재료 보류 계약이 유지된다.4공정 API의 일치성은 해석적 반례 검사에서 별도 확인했다.

두 표본의 수치 표현, 닫힌 단면, 사건 수 및 예상 교차 예산을 검사하고 전체 구간이 확정돼야 적분 체적을 제공한다. [수학 근거와 누락 구간의 의미](EVENT_SECTION_METHOD.md)를 따른다. `summary.json`의 상태를 물리적 출력 성공으로 바꾸지 않는다. 원본/캐시/동결 엔진의 SHA 불변 여부도 확인한다.

## 사용자가 읽을 최종 묶음

```text
python scripts/summarize_corpus_review.py --audit <완료된감사폴더> --refreshed <새갱신폴더> --events <새사건검산폴더> --refinement <새정밀화폴더> --out <새최종보고서폴더>
```

완료·무결성 조건을 확인한 뒤 형상별 치수와 상태,744개 공정 보고서, 추가 사건 검산, 상위5 재표본화, 얇은 판의 표본화 그림을 한 HTML로 연결한다. 로컬 링크는 원검사 폴더를 참조한다. 해당 작업 기록 폴더를 함께 보존해야 개별 보고서를 계속 열 수 있다.

최종 Windows 회귀는 Python3.12.14/3.13.15에서 각각458개 통과했다. 두 환경의 로그는 `validation/v3/random-corpus/checks-02/`와 `checks-313-01/`에 있다. 실물 장비·공정 검증을 의미하지 않는다.
