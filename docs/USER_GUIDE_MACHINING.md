# 절삭 검토 사용법 — 개발 중인 고정축 밀링 범위

이 화면은 **선택한 공구와 CAD 특징이 맞는지, 어디를 다시 확인해야 하는지** 보여준다. 실제 절삭 경로를 만들거나 가공 성공을 보증하는 CAM은 아니다. 장비가 없어도 치수를 정의한 STEP 예제로 계산과 설계 수정 효과를 확인할 수 있다.

## 처음 실행하기

1. 왼쪽 **제조 공정 → 절삭가공**을 선택한다.
2. **절삭 검증 형상**에서 예제를 고르거나 **내 파일**에서 STEP/STP을 읽는다. 조립체는 검토할 솔리드 하나를 선택한다. STL/3MF에서는 CAD 특징 치수를 추정하지 않고 해당 항목을 보류한다.
3. **공구가 오는 방향**을 선택한다. 화살표는 부품에서 공구 쪽으로 향하고, 공구는 그 반대 방향으로 진입한다. 여섯 축과 직접 입력한 기울기·방위각을 사용할 수 있다. 여러 방향의 자동 최적화나 연속 5축 경로 생성은 제공하지 않는다.
4. 원통형 엔드밀의 **지름·날 길이·장착 후 돌출 길이(공구 끝~홀더 앞면)**를 입력한다. 날 길이는 실제 절삭날의 축방향 길이이며 공구 전장이나 감소 목부 길이와 다르다. 모르면 비워 둔다. 임의 숫자를 기본 공정 한계로 사용하지 않는다. 값의 제조사·도구 번호 등은 **공구·기준의 출처**에 기록한다. 재료·장비명은 현재 조건 기록용이며 절삭력·처짐 계산에는 사용하지 않는다.
5. **절삭 설계 검토**를 실행하고 먼저 확인할 항목을 선택한다. 상단의 **이 결과에 적용된 공구 조건**으로 현재 결과가 어떤 치수를 사용했는지 확인한다. 왼쪽 공구 입력은 실행 버튼을 눌러야 적용된다. 형상·방향이 바뀌면 이전 결과를 숨긴다.
6. 치수표에서 형상과 공구를 비교하고 **확인할 위치**에서 CAD 면을 선택한다. **파란색은 측정·추가 확인 위치**, **주황색은 해당 항목에서 조건 확인이 필요한 위치**다. 공구를 바꿔 반경 문제가 해소되면 그 측정 위치는 파란색으로 표시한다. 판단은 해당 항목의 결과·수치·**다음 행동**을 함께 읽는다. 마우스 휠은 문서를 스크롤하며 모델 확대·축소는 그림의 도구 모음을 사용한다.

## 각 기능이 있는 이유

| 항목 | 무엇을 보는가 | 왜 필요한가 / 다음 행동 |
|---|---|---|
| 절삭 검토 입력 | 단일 솔리드 STEP과 CAD 유효성 | 잘못된 입력이나 조립체 전체를 부품 하나로 판단하지 않기 위해 필요하다. |
| CAD 면 정보와 특징 인식 범위 | 미확정 경계·원통 내외부·미지원 곡면 | 검사하지 못한 특징을 숨기지 않는다. 경계 추출이 완료돼도 모든 포켓을 인식했다는 뜻은 아니다. |
| 원통형 내부 특징과 공구 | 원주 방향 범위가 360°인 내부 원통면의 지름·축 구간, 선택축과 정렬 여부 | 공구 지름·길이 조건과의 차이, 다른 접근 방향의 필요성을 확인한다. **원통면 개수는 홀 개수가 아니며 축 구간은 전체 드릴 깊이가 아니다.** 교차 구멍처럼 중간 벽이 끊긴 면도 포함할 수 있다. |
| 공구축과 나란한 오목 원통면 | 부분 원통의 반경과 엔드밀 반경 | 공구가 더 큰 반경이면 더 작은 공구 또는 설계 반경 확대를 검토한다. 모든 부분 원통을 포켓 코너로 확정하지 않는다. |
| 직사각 포켓 바닥과 내부 직각 | 직선 4변·동일 높이 수직 벽·열린 평면 테두리로 제한한 포켓 | 날카로운 내부 직각은 유한 반경의 원통형 엔드밀로 그대로 만들 수 없으므로 반경·코너 여유를 검토한다. 폭·국소 벽높이와 공구 치수도 비교한다. |
| 선택 방향의 표면 가림 | 삼각형 내부의 표본 한 점에서 지정 방향으로 뻗은 직선 | 앞을 가리는 형상과 다른 쪽을 향한 면을 찾는다. 공구의 유한한 지름·샤프트·홀더가 지나가는 공간은 별도 CAM 확인 대상이다. |

**포켓 폭·깊이는 현재 직사각 포켓에만 제공한다.** 둥근 포켓, 코너 챔퍼로 8변이 된 바닥, 섬·분할·곡선이 있는 포켓은 이 폭·깊이 인식 범위 밖이다. 둥근 포켓에서도 오목 원통면의 반경 비교는 별도로 가능하다. 같은 부품의 일부 항목만 측정될 수 있다.

안쪽 벽과 연결된 바닥은 보이지만 직사각 조건을 확인하지 못하면 **내부 바닥 후보·치수 미확정**으로 표시한다. 이 후보는 채널·밀폐 공동일 수도 있으며 열린 포켓 수로 읽으면 안 된다. 큰 좌표 이동 등으로 인식이 불안정한 경우에도 ‘포켓 없음’으로 승격하지 않는다.

치수표의 **아니오**는 해당 국소 치수가 입력한 수치를 초과하지 않았다는 뜻이다. 가공 통과 표시가 아니다. 예를 들어 깊은 포켓 안의 작은 포켓은 국소 벽높이가 짧아도 전체 진입 깊이와 홀더 간섭을 따로 봐야 한다.

**날 길이보다 벽이 높다**는 이유만으로 가공 불가가 되지는 않는다. 감소 목부 공구와 여러 깊이의 절입을 사용할 수 있다. 돌출 길이 비교도 홀더가 들어갈 공간과 실제 경로를 포함하지 않는다. **수치 경계**는 계산 오차 범위에서 같은 값이라는 뜻이며 설계 공차·실제 가공 여유가 확보되었다는 뜻이 아니다.

## 표면 가림의 점과 색을 읽는 방법

전체 면을 위험 색으로 칠하지 않고 실제 검사한 표본 위치를 점으로 표시한다. 색과 함께 기호·이름을 제공하고 표시할 표본을 선택할 수 있다.

| 표본 분류 | 의미 | 다음 행동 |
|---|---|---|
| 앞이 가려진 표본 | 표면에서 공구 방향으로 뻗은 직선이 다른 면과 만남 | 다른 방향·가공 순서를 검토한다. |
| 공구 반대쪽을 향한 표본 | 표면 법선이 선택축 반대쪽을 향함 | 다른 셋업에서 처리할 면인지 확인한다. |
| 공구축과 평행한 면의 표본 | 축이 면에 접하는 방향 | 측면 밀링·공구 반경·진입 방법을 별도로 확인한다. |
| 계산 미확정 표본 | 수치 경계 또는 계산 한도 등으로 결과를 확정 못함 | 가려지지 않은 점으로 바꾸어 해석하지 않는다. |
| 직선이 가려지지 않은 표본 | 검사한 점의 직선에 차폐가 검출되지 않음 | 유한 크기 공구와 홀더도 들어간다는 뜻은 아니다. |

표본 수·미표본 면 수와 한계를 함께 확인한다. 표본의 면적 가중 비율은 전체 가공 가능 면적률이나 성공 확률이 아니다. 밀폐 공동·분리/문제 메시·시간 한도 등 때문에 전체 검사를 보류할 수도 있다.

## 미팅에서 보여줄 재현 가능한 사례

**둥근 포켓 · 모서리 R3 / 깊이 8 mm**를 고르고 +Z, 지름 8 mm, 날 길이 10 mm, 도달 길이 15 mm로 검토한다. R3 오목면 네 곳은 공구 반경 4 mm보다 작으므로 확인 후보가 된다. 지름만 4 mm로 바꾸고 재실행하면 이 반경 충돌은 사라진다. 이때도 포켓 전체 접근·안정성·물리적 가공 성공은 미검증으로 남는다. 이 숫자는 시연용 공구 조건이며 제조사 권장값이 아니다.

이후 **직사각 포켓 · 20×12 / 깊이 8 mm**로 바꾸어 날카로운 내부 코너를 확인한다. **좁은 포켓**에서는 폭·날 길이·도달 길이와의 차이를 확인한다. 보스·밀폐 공동·열린 채널을 직사각 포켓으로 오인하지 않는 반례도 함께 제시한다.

## 내보내기와 남은 범위

HTML에는 한글 적용 조건·측정표·이유·다음 행동·한계·근거와 오프라인에서 볼 수 있는 형상 참고도가 있다. 참고도는 원본 좌표의 메시이며 정밀 도면이나 공구축 배치도는 아니다. 개별 측정 위치는 앱과 CAD 면 ID로 확인한다. JSON에는 표본과 코드/입력 식별자를 포함한 정밀 원자료가 있으며 원본 형상도 그대로 내려받는다.

선삭·연속 5축·샤프트/홀더/고정구의 실제 충돌·소재 제거 순서·절삭력·처짐·진동·공차·표면 품질·시간·비용·성공 확률은 구현하지 않았다. **사용자의 2026-09-20 지시에 따라 현재 개발 범위는 적층·절삭이며 사출·프레스는 진행하지 않는다.** AI를 도입할 때도 먼저 검증된 규칙 결과와 미확정 범위를 설명·도구 호출에 연결한다.

근거와 조건은 [절삭 근거 기록](research/MACHINING_EVIDENCE.md), 실제 시험 범위는 [구현·검증 기록](project-knowledge/MACHINING_IMPLEMENTATION_2026-09-19.md)을 따른다.

최신 추가 감사는 [문헌·수치 해석 재검토](research/MACHINING_EVIDENCE_REAUDIT_2026-09-20.md)와 [절삭 개선·검증 기록](project-knowledge/MACHINING_REAUDIT_2026-09-20.md)에 정리했다.
