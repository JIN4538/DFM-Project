# 절삭 1차 기능의 문헌·수치·해석 재감사

조회·코드 대조: 2026-09-20. 범위는 현재 `dfm/machining.py`, `dfm/accessibility.py`, CAD 특징 추출기와 [절삭 사용자 안내](../USER_GUIDE_MACHINING.md)다. 사용자의 최신 지시에 따라 **사출·프레스 개발은 진행하지 않는다.** 이 문서는 절삭 검토의 근거와 보완 조건을 다루며, 실제 가공 시험이나 CAM 실행 결과를 대신하지 않는다.

## 판단

현재 항목들은 대부분 유지할 이유가 있다. 공구보다 작은 내부 반경·좁은 폭, 공구 길이보다 큰 국소 치수, 접근 방향에서 가려진 위치는 사용자가 공구·방향·설계를 다시 결정하는 데 유용하다. 다만 **국소 치수 비교, 특징 인식, 표본 가시성, 실제 가공 가능성은 서로 다른 문제**다. 문헌은 앞의 항목을 검사할 이유를 뒷받침하지만, 우리 구현의 정확도나 최종 가공 성공을 입증하지 않는다.

최종 계산 코드와 안내서를 다시 대조한 결과, 항목별 출처·계산 방법의 분리, 공구 길이 용어, 원통면과 구멍의 구분, 가림 표본의 적용 한계가 반영됐다. 축 일치 계산과 치수 경계 처리도 아래의 수치 정책으로 바뀌었다. 작은 수치 오차를 제조 공차로 포장하거나, 제조사 서비스의 권고를 보편 합격선으로 채택할 근거는 없다. 이 문서의 반영 확인은 코드·안내서 읽기에 근거하며, 실제 회귀검사·브라우저 결과는 별도 실행 기록을 따른다.

Yeo 논문의 PMC 주소는 브라우저 확인 페이지만 반환하여 출판사 HTML 원문을 대신 읽었다. Protolabs Network의 sharp-corners 페이지는 재조회 중 시간 초과가 있어 코너 판단은 실제 본문을 확인한 E01/E03과 자체 기하 유도로 대조했다. 문헌의 참고문헌 목록을 보았다는 이유로 해당 논문까지 읽었다고 기록하지 않는다.

감사 시작 시 `_finding`은 CAD 입력과 표본 가림까지 같은 Protolabs 코너·일반 가공 출처를 붙였다. 최종 코드에서는 `_MECHANISMS`가 아래와 같이 항목별 계산 방법과 근거 ID를 배정한다. **입력/인식기의 자체 계약, 문헌의 기능 필요성, 실제 측정 알고리즘, 사용자 입력 기준**을 분리했다. 문헌을 붙이지 않은 자체 입력 계약은 독립 구현 검증의 대상이다.

보고서의 `sources`에는 위 ID의 제목·URL·적용 범위가 있고, 각 Finding의 `method`와 `evidence`가 실제 배정값을 보존한다. 길이 비교 경계는 `numerical_boundary_comparisons`, 전체 수치 정책은 보고서의 `numerical_policy`로 보존한다. 조건 초과·경계·미입력을 구분하는지에 대한 실행 검증은 별도 시험 기록으로 확인한다.

## 수치의 타당성

### 공구 크기 비교는 왜 유지하는가

선택축과 평행한 이상적인 원통형 공구의 단면은 반지름 `r=D/2`인 원이다. 오목한 원호를 옆날로 만들 때 `r>R`이면 원호에 접하는 공구가 주변 재료를 침범한다. 평행 벽 사이에 공구가 들어가려면 `D≤w`여야 한다. 이는 명시한 국소 형상·공구 가정의 기하 비교이며 통계적 제조 한계가 아니다. `R=0`인 내부 직각을 유한 반경의 원통 옆날로 그대로 만들 수 없다는 판단도 같은 가정에 한정한다. 바닥과 벽 사이의 직각까지 모두 불가능하다는 뜻이 아니다.

경계와 정확히 같은 값은 수학적으로 비초과지만 실제 공구 공차·런아웃·가공 여유·물림·진동을 허용한 결과는 아니다. 제조 안정성 경고를 추가하려면 공구·재료·작업별 기준이 필요하다. E01의 `D≤1.5R`를 자동으로 합격선에 넣지 않고 별도 조건부 권고로 관리하는 현재 방향이 적절하다.

### 길이는 한 종류가 아니다

사용자가 공구 전장, 날 길이, 카탈로그 LBS, 장착 후 돌출 길이를 혼동하면 정확한 계산도 잘못된 결과를 낸다. 수정한 사용자 안내는 **날 길이: 실제 절삭날의 축방향 길이**, **장착 후 돌출 길이: 공구 끝에서 홀더 앞면까지의 거리**라고 구분한다. 현재 코드의 `reach_mm`는 후자를 뜻한다. 카탈로그의 Reach를 같은 값으로 간주해 그대로 복사하면 안 된다.

벽높이가 날 길이보다 크다는 것은 그 날 전체로 벽 전 높이를 한 번에 훑을 수 없다는 비교다. 감소 목부와 나누어 가공하는 경로가 있으면 깊은 벽도 검토할 수 있으므로 무조건 긴 날로 교체하라는 결론은 피한다. 국소 깊이가 돌출 길이를 넘더라도 홀더가 들어갈 공간·형상을 모델링하지 않았으므로 충돌 확정으로 바꿀 수 없다. 반대로 비초과라도 위에 놓인 형상·입구·전체 깊이 때문에 충돌할 수 있다. 이들은 **추가 조건 확인** 항목으로 유지할 가치가 있다.

### 길이/지름비는 사용자 조건부 비교다

현재 값은 원통면의 축 구간을 지름으로 나눈 것이다. 이름을 일반적인 ‘홀 깊이비’로만 줄이지 않는다. 기준이 비어 있으면 미비교, 입력했으면 해당 입력의 출처와 함께 초과 여부를 표시한다. 기본 6D 등으로 채우지 않는 것이 맞다. 사용자가 근거 없이 기준을 넣었더라도 프로그램이 그 값을 검증된 제조 한계로 승격하면 안 된다. 장비·소재 텍스트를 입력하는 것만으로 재료별 힘·처짐이 계산되는 것도 아니다.

### 수치 안정성 설정과 실행 예산

다음은 2026-09-20 최종 계산 코드와 대조한 값이다. 가공 공차나 문헌의 제조성 합격선이 아니라 알고리즘의 수치 분류·자원 한도다. 구현이 바뀌면 해당 코드·실행 기록을 우선한다.

| 값 | 사용처 | 의미와 검증 요구 |
|---|---|---|
| 단위 축 사이 외적 크기 `≤10⁻⁸` | 원통 축 정렬, 포켓 바닥·테두리 법선의 선택축 방향 일치 | `sin(θ)≤10⁻⁸`, 약 0.000000573°의 수치 분류다. 실제 각도는 `atan2(외적 크기, 내적 절댓값)`으로 보존한다. 장비의 각도 허용오차가 아니다. |
| 변 방향 내적 `1−10⁻⁸`, 직교 내적 `10⁻⁸` | 직사각 바닥의 변 쌍, 벽 법선의 직교성 | 축 정렬과 별개인 제한 인식기의 수치 조건이다. 가공 가능한 경사·도면 각도 공차를 뜻하지 않는다. |
| `max(10⁻⁹ mm, max(측정값, 비교값)×10⁻¹⁰)` | 지름·반경 대응 지름·폭·국소 길이와 공구 조건 비교 | 차이가 이 수치 띠 안이면 초과로 확정하지 않고 해당 비교를 수치 경계로 기록한다. STEP 전송·회전의 작은 반올림을 확정 간섭으로 확대하지 않기 위한 정책이며 실제 가공 여유가 아니다. |
| 입력 기준 대비 상대 차이 `10⁻¹⁰` | 원통 축구간/지름비와 사용자 기준 비교 | 무차원 비율의 수치 경계이며 위 절대 길이 `10⁻⁹ mm`를 적용하지 않는다. 경계는 별도로 기록하고 비초과를 가공 통과로 바꾸지 않는다. |
| `max(10⁻⁷ mm, 최대변길이×10⁻⁸)` | 직사각 인식의 위치·같은 높이 비교 | 크기 변화에 따른 수치 여유. 도면 공차가 아니다. 원본 CAD의 허용오차를 수정하는 값도 아니다. |
| `|Uspan−2π|<10⁻⁶ rad` | 원주 방향 전체 범위 분류 | UV 경계가 약 360°라는 뜻이다. 모든 높이에서 끊김 없이 전주 벽이 존재한다는 검사가 아니다. 내부 트림·교차 홀은 별도 대상이다. |
| 정규화 길이·각도 내적 `10⁻¹⁰` | 레이 교차·접선 분류 | 최대 형상 길이로 정규화한 계산 오차 정책이다. 표면에서 레이를 띄워 시작하는 오프셋은 0이다. 근접·모서리 접촉은 미확정으로 보존한다. |
| 표본 최대 512, 메시 최대 200,000면, 교차 연산 20,000,000회, UI 작업자 10초 | 표면 가림 | 응답성과 자원 관리의 개발 선택. 통계적 신뢰구간이나 전체 검사 보장이 아니다. 누락/미확정 수와 요청/유효 표본을 보존해야 한다. |
| 평면 경계 512개/면, 50,000개/모델 | CAD 경계 추출 | 악성·과도한 입력에 대한 실행 예산. 제한 초과를 특징 없음으로 반환하지 않는다. |

이전 원통 축 정렬의 `1−|내적|≤10⁻⁸`은 약 0.0081°까지 같은 축으로 처리할 수 있었다. 최종 구현은 외적 기준으로 바꾸고 실제 각도를 보고한다. 이 변경은 정렬 오차를 숨기지 않기 위한 수치 분류 개선이며, 장비·공구의 제조 공차를 추정한 결과가 아니다.

## 사용자 관점의 채택 기준

1. 결과 첫 문장에 ‘현재 공구에서 치수 확인 필요’, ‘공구 조건을 넣어야 비교 가능’, ‘검사 범위에서 추가 후보를 찾지 못함’을 구분한다. 계산 완료라는 영문 상태만으로 의미를 전달하지 않는다.
2. 각 항목은 **위치 → 실제 치수 → 입력 공구/기준 → 차이 → 다음 행동**을 연결한다. 단순 ‘아니오’보다 ‘이 치수는 입력값을 넘지 않음’이 이해하기 쉽다. 이 비교를 전체 가공 통과로 표현하지 않는다.
3. 반경 초과와 미입력·미확정은 다른 표시를 사용한다. R3에 D8이면 R4가 맞지 않는 이유, D4이면 이 반경 비교에서 후보가 사라지는 이유를 설명한다. 작은 공구의 강성·공차 적합성까지 개선됐다고 말하지 않는다.
4. 완전한 원통/구멍이라는 말을 UV 범위만으로 사용하지 않는다. CAD 면 ID는 자세한 표에 유지하되 사용자에게는 지름·측정 구간·선택 방향을 먼저 보여준다.
5. 점 한 곳의 가림을 전체 면의 확정 위험 색으로 확장하지 않는다. 표본 위치·분류 기호·가린 면과 누락 범위를 제공한다. 전체 가공 가능 면적률·성공 확률은 표시하지 않는다.
6. 소재·장비명은 현재 기록용이며 재료별 절삭 해석에 반영되지 않는다고 입력 근처에서 설명한다. 기준 미입력은 0이나 자동 추천 기준으로 대체하지 않는다.
7. 내부 직각은 유지가 불가능하다고 무조건 설계 변경을 지시하지 않는다. 기능·조립 요건에 따라 반경 확대·코너 여유 또는 다른 가공법을 담당자와 검토하도록 한다.

이 항목들은 UX 요구사항이며 실제 브라우저 사용성 시험을 대신하지 않는다. 화면·다운로드 보고서가 동일한 값과 상태를 전달하는지 별도로 검증한다.

## 남은 검증과 범위

독립 기하 형상으로 수치가 맞는지 확인하고, 회전·이동·단위·면 분할·교차·경계값·잘못된 입력에서도 거짓 확정이 없는지 확인해야 한다. 특히 동일 구멍의 여러 면 표현, 원통에 교차 구멍이 난 경우, 목부 공구로 깊은 벽을 가공하는 경우는 단순한 한 면/한 치수 가정을 드러내는 반례다. 문헌에 특정 알고리즘이 있다고 현재 구현의 모든 결과가 맞아지는 것은 아니다.

현재 모듈은 고정축 원통형 엔드밀의 제한된 기하 검토다. 원소재·클램프·공구 어셈블리·공정 순서·이동 경로·얇은 벽의 강성·절삭력·공차·표면 품질은 이 계산에 없다. 이 제한은 개선 과제를 명확히 하기 위한 것이며 해당 기능을 구현한 것으로 표시하면 안 된다. 장비가 없는 상황에서는 독립 CAD·외부 CAM·공개 실물 자료를 구분해 검증을 확장할 수 있지만, 지금 수치 비교로 제조 성공 확률을 생성할 수는 없다.
