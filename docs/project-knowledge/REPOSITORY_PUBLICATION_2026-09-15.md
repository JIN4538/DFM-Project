# 전체 개발 파일과 테스트 형상의 GitHub 정리

사용자는 지금까지 변경한 파일과 모든 테스트 형상을 커밋 단위로 정리해 GitHub에 올리도록 요청했다. 이미 공개한 개발 커밋은 다시 쓰지 않고, 현재 브랜치 `codex/am-dfm-evidence-review`에 자료와 재현 편의를 추가한다. 현재 개선판은 이 브랜치와 PR #1에서 확인한다.

## 포함한 자료

| 위치 | 포함 내용 |
|---|---|
| `examples/cad` | 치수·기대값이 정의된 자체 STEP 기준형상 14개 |
| `examples/corpus` | 바탕화면 무작위 형상 26개와 공급자 TXT 5개. 원감사 입력 SHA와 일치 |
| `examples/external` | 초기에 전달받은 외부 STL 3개 |
| `examples/historical` | 과거 미팅 데모·규칙 시험·v1 예제 형상 22개와 생성 소스·당시 결과 |
| `examples/regressions` | 중첩 변환·인치 단위의 3MF 원본 3개와 오류·수정 확인 기록 |
| `cura_run`, `validation/v3` | 이미 추적하던 슬라이서 시험 형상 38개와 검증 기록 |
| `docs/artifacts` | 날짜별 작성 보고서·진행 가이드·문헌 요약·발표 자료 13개 |
| `validation/deployments` | 과거 배포의 SHA·파일 목록·검증 기록 원본 24개 |
| `validation/v3/random-corpus/diagnostics` | 국소 CAD/메시 단면 진단 스크립트·결과 원본 11개 |
| `validation/v3/random-corpus/reader-report-20260915` | 사용자용 최종 검토 보고서·요약·배포 확인 원본 3개 |

형상은 **106개 경로, SHA-256 기준 100종, 57,613,674바이트**다. 이는 서로 다른 물리 설계 100개라는 뜻이 아니다. 특히 회귀용 3MF 3개는 압축 파일의 바이트는 다르지만 내부 모델은 같다. 작업공간과 바탕화면에서 조사한 형상, 11개 ZIP 내부의 형상까지 SHA 집합으로 대조해 누락이 없음을 확인했다. 경로·형식·바이트 수·SHA는 [전체 색인](../../examples/geometry_manifest.json)에 있다.

복사 자료에는 원래 경로와 SHA 색인을 함께 둔다. 외부 형상은 제공된 공급자 정보만 보존하고 원설계 치수나 라이선스를 새로 추정하지 않는다. 과거 데모의 점수·당시 실행환경·실패 기록도 수정하지 않는다. 최신 제조성 검토 설명은 [현재 사용자 안내](../USER_GUIDE_V3.md)를 따른다.

## 재현 편의와 검증

바탕화면에 `무작위 형상 테스트` 폴더가 없을 때 앱은 `examples/corpus`의 26개 형상을 제공한다. 바탕화면 폴더가 있는 사용자는 기존 입력을 유지한다. 원본 바이트·배율·분석 알고리즘은 바꾸지 않았다. GitHub Actions는 다음 무결성 검사를 실행한다.

```powershell
python scripts/verify_geometry_inventory.py --require-tracked
python -X utf8 -m pytest tests_v3 tests -q
python -X utf8 verify_legacy.py
```

이번 로컬 변경에 관련된 형상 무결성·무작위 형상 선택·기존 앱·공정 UI 검사 **17개가 Windows Python 3.12.14(56.88초), 3.13.15(61.63초)에서 각각 통과**했다. 형상 106개 파일의 해시 검사도 통과했다. 이전 UX 커밋의 전체 609개/기본 55개 검증은 [당시 기록](USER_WORKFLOW_2026-09-15.md)에 있으며, 이번 17개 실행과 합쳐 전체 재실행으로 표현하지 않는다. 새 원격 전체 실행 결과는 해당 커밋의 GitHub Actions 기록에서 확인한다.

## 보존과 제외 범위

최초 커밋 `1706eac`의 PDF·DOCX·ZIP 등 원자료 24개는 원래 위치·바이트를 유지한다. `.venv`, 설치 의존성, 비밀 설정, 임시 로그, 렌더링 중간 이미지, 반복 배포 ZIP, 약 4 GB의 전수 감사 모델 캐시·반복 상세 출력은 Git에 넣지 않는다. 원래 작업공간에서는 삭제하거나 덮어쓰지 않는다. 전체 형상 입력·집계·국소 진단·재실행 스크립트는 저장소에 있다.

소스 배포 ZIP은 Git 추적 파일 중 최초 원자료 24개를 제외한 앱·형상·작성 자료·검증 기록을 묶는다. 과거 배포 매니페스트와 최종 보고서의 절대/상대 링크는 당시 배포 위치를 설명하는 보관 기록이다. 최종 보고서의 943개 개별 상세 링크는 저장소 밖 원감사 폴더가 있어야 열리며, 이를 이식 가능한 전체 보고서로 설명하지 않는다. [보고서 보관 안내](../../validation/v3/random-corpus/reader-report-20260915/README.md)를 참고한다.

이번 작업은 파일 정리·무결성 및 입력 접근성 개선이다. 이전 744개 공정 사례의 상세 계산을 다시 실행하거나 실물 출력·강도·치수 정확도를 새로 검증한 작업은 아니다.
