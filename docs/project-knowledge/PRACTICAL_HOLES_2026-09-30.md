# 구멍 치수·입구 방향을 개선안에 연결

사용자 후속 요청: 다음 개선 방향을 정하고, 처음 사용하는 사람에게 실용적인 툴로 개선한다. 기존 독립 시험에서 반복 관통 홀을 놓쳤던 문제를 우선한다.

## 사용자에게 달라지는 것

- 단순 원형 구멍의 개수·지름·깊이를 CAD 경계로 확인한다. 여러 원통면으로 나뉜 같은 구멍은 한 위치로 묶는다.
- 결과 바로 아래에서 구멍 치수를 펼쳐 보거나 위치를 연다. 위치 그림에 입구 원과 지름·깊이를 표시한다.
- **구멍 N개의 입구 방향으로 검토**를 누르면 해당 방향으로 재검토하고 구멍 위치까지 연다. 직접 입력한 공구·장비·재료·중점 조건은 유지한다. 여러 축의 구멍이 있으면 버튼에 그 방향으로 일치하는 개수만 표시한다.
- 막힌 구멍의 바닥 쪽을 선택한 경우, 지름·길이 변경을 해결책으로 추천하지 않고 먼저 입구 방향을 바꾸도록 한다.
- 확인한 구멍의 길이 제안은 실제 CAD 입구부터 끝까지의 깊이에 따른다. 떨어진 높은 돌출부 때문에 전체 상단 기준 길이가 과도하게 커지던 경우를 줄인다.
- 앱의 **절삭 검증 형상**에 관통·막힌·기울어진 분할 구멍 3가지 시연을 추가한다. 바탕화면 `DFM_구멍검토_STEP`에도 동일 STEP을 제공한다.

## AI와 측정의 구분

이번 단계의 신규 가중치 학습·외부 원본 추가는 **0**이다. 기존 GNN·MLP·공구 개선 모델을 유지하고, 학습 인식이 놓친 구멍을 별도 CAD 검산으로 보완한다. 이를 NN 검출률 상승이나 새 딥러닝 성능으로 보고하지 않는다. `external_feature_recognition.records`는 원래 인식을 보존하며 추가 후보는 `recognition_source=cad_verified_geometry`, `recognition_model_id=null`이다. 기존 원통·코너 검토는 `native_hole_face_review`, 필요한 경우 `native_corner_face_review`에 보존한다.

## 확인 방법과 적용 범위

`dfm/verified_holes.py`는 유효한 단일 STEP 솔리드에서 다음을 모두 요구한다.

1. 동일 축선·지름·몸체의 내부 원통면을 묶고, 모든 면의 축 구간이 같은지 확인한다.
2. 원주 범위 합 2π와 native 원통 면적 합 2πrL을 확인한다. 회전·이동에도 동일한 수치 비교를 적용한다.
3. 양 끝의 평면 경계가 같은 중심·지름의 닫힌 원형 루프인지, 인접 원통면 ID가 정확히 해당 그룹인지 확인한다.
4. 관통은 서로 반대인 두 입구, 막힌 구멍은 입구 하나와 완전한 평면 원판 바닥을 요구한다. 표면 법선은 재료 쪽을 확인한 CAD 기록을 쓴다.

내부 원통 512면, 원형 경계 2,048개 한도를 둔다. 한도를 넘거나 필수 기록이 없으면 미확정 상태를 보존한다. 축 방향 분할·단차·교차·밀폐·불완전 경계·곡면 바닥은 이 단계에서 완전한 구멍으로 확정하지 않는다. 이러한 구멍이 없다는 뜻이 아니며 기존 개별 원통 기록을 유지한다. 국소 입구 방향과 공구 몸통·홀더·고정구의 전체 경로는 서로 다른 검토다.

공구 지름 80%·길이 여유 1 mm는 기존의 변경 가능한 제안 정책 그대로다. [Sandvik Coromant 공식 자료](https://www.sandvik.coromant.com/en-us/knowledge/milling/milling-holes-cavities-pockets)의 Creating an opening / Circular ramping 항목은 드릴과 원호 밀링을 구분하고 입구·깊이·바닥을 제시하는 근거다. 해당 제조사 자료를 80%·1 mm 정책의 검증 근거나 구멍 인식 알고리즘의 정확도 근거로 사용하지 않는다. 인식 구현은 독립 CAD 기대값과 반례로 검산한다.

## 검증과 배포 기록

- `scripts/benchmark_verified_holes.py`가 평가 전에 STEP 24개와 기대값·SHA를 고정한다. 반복·분할·회전·이동·평평한 바닥·먼 돌출부와 단차·교차·밀폐·외부 보스를 포함한다. 첫 검사 24/24 통과. 정확한 기대 구멍 수와 면 ID는 `validation/practical-holes-2026-09-30/independent-01/result.json`을 따른다.
- `scripts/audit_practical_holes.py`는 실제 격리 STEP 로더로 기존 절삭 12개·공개 14개·새 시연 3개를 불러와 방향 및 공구 고정 조건을 검사한다. 최초 29/29, 98조건 통과. 최종 실행과 UI 결과는 같은 검증 폴더의 최신 XML/JSON을 따른다.
- 최초 기본 worker 탐색에서 `MemoryError`가 발생했다. AI 특징 인식 메모리 오류는 `unavailable`과 오류 종류를 기록하고 CAD 측정을 계속하도록 보완했다. 강제 메모리 오류 시험을 추가했다. 일반 CAD 변환 자체의 실패를 성공으로 바꾸는 처리는 하지 않는다.
- 최초 회귀 명령의 파일명 오류로 테스트가 실행되지 않았다. `regression-01.xml`과 로그를 보존하고 수정한 회귀 81개가 통과했다. 시험 수는 중복 실행을 더하지 않고 최종 개별 결과로 집계한다.
- 배포는 `scripts/deploy_practical_holes.py`로 한다. 기존 학습 아티팩트 전체와 이전의 계약 소스 9개를 SHA로 대조하며 독립 바탕화면 편집을 덮어쓰지 않는다. 배포 전 파일·실패 기록은 저장소 옆 `study/practical-holes-2026-09-30/`에 보존한다.

## 완료 기록 · 2026-10-01

바탕화면 `AM-DFM_v3_0` 실행본에 반영하고 `http://127.0.0.1:8507/`의 실제 브라우저에서 확인했다. 기울어진 분할 구멍 시연에서 입구 방향 적용 버튼을 한 번 눌러 재검토와 위치 화면 이동까지 실행했다. 구멍 3개, 지름 5.4 mm, 깊이 17.3 mm가 표시되며 자동 공구 제안은 엔드밀 지름 4.32 mm, 날 길이·돌출 길이 18.3 mm다. 결과 제목은 구멍의 치수와 접근 방향이 현재 공구와 맞는다는 결론을 먼저 보여준다. 추가 미확정 항목은 유지된다.

- 최종 독립 CAD 검사: **24/24**, 확인 대상 구멍 **26개**. 완전한 단순 구멍으로 확정해서는 안 되는 반례 10개를 포함한다. `independent-02/result.json`에 형상·기대값·측정값을 보존했다.
- 실제 격리 입력 검사: **29/29 STEP**, 방향·입구 적용·공구 고정 등 **98조건**. `runtime-02/result.json`을 따른다.
- 중복 실행을 제외한 최종 개별 회귀 결과: 저장소 **153개**, 바탕화면 실행본 **55개** 통과. 초기 실패는 삭제하지 않았으며 수정 후의 같은 시험 결과로 최종 상태를 판정했다.
- 배포 파일 **25개**와 기존 학습 아티팩트 JSON **34개**, 이전 소스 계약 **9개**의 SHA를 대조했다. 34개에는 매니페스트가 포함되며 학습 모델 34종을 뜻하지 않는다. 바탕화면 지식 색인의 별도 이력은 보존하고 새 문서 링크만 추가했다.
- 실제 UI에서 보고서를 다운로드해 결론·구멍 지름·깊이·공구 수치가 같은지 확인했다. 다운로드 원본과 확인 결과는 `native-download-01.html`, `native-download-01.json`이다.
- 실제 화면은 저장소 옆 `study/practical-holes-2026-09-30/final-conclusion.png`, `final-hole-location.png`, `final-hole-measurements.png`에 저장했다. 임시 브라우저 크기 설정은 해제했다.

최종 파일 대조 결과는 `validation/practical-holes-2026-09-30/final-integrity-*.json` 중 가장 최근 파일을 따른다. 이번 작업은 새 모델 학습이 아니라 기존 AI의 특징 인식과 CAD 치수 검산을 연결한 개선이다. 단차·교차·축 방향으로 분할된 구멍은 자동 깊이 확정 범위 밖이며, 다음 확장에는 이 형상들의 독립 기대값과 입구·바닥 연결 검증이 필요하다.
