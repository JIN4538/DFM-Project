# 2026-09-28 공통 조건 DB·엔진 연결 인수 기록

사용자는 적층·절삭의 조건 데이터베이스를 가능한 범위에서 정확하게 구축하고 코드 연결과 검사까지 수행하도록 요청했다. [조사·범위](../research/conditions-2026-09-28/README.md), [사용법](../CONDITION_LIBRARY.md)을 먼저 확인한다.

## 구현

- `data/conditions/`: 62개 시나리오·270개 값(자동 입력70/참고200), 공식 출처35카드/33URL. 기존 문헌43개는 별도 배경 색인이다.
- `dfm/conditions.py`: 명시적 시나리오 선택, 출처/단위/공정 검증, 외부 자료와 엔진의 의미가 같은 필드만 입력. CNC 카탈로그 길이를 장착 길이로 바꾸지 않는다.
- `dfm/conditions_view.py`, `app.py`, `dfm/machining_view.py`: 검색·미리보기·적용·초기화·조건 변경 이력·문헌 검색.
- `amdfm/profiles.py`, `dfm/machining.py`: 전체 조건 스냅샷을 검증해 미입력→새 입력 변화도 오래된 출처와 섞이지 않게 한다.
- AM/CNC HTML과 전체 JSON에 선택 조건·출처·원문 위치·사용자 변경·직접 입력·DB SHA를 기록한다.
- 계산 지문과 일괄 형상 감사의 재현용 코드 복사본에 조건 JSON을 함께 포함한다.

## 발견·수정한 결함

1. 자료 적용 후 사용자가 추가한 벽 기준이 원자료의 기준처럼 보일 수 있었다. 원자료에 없는 직접 입력·탐색 기본값을 별도 기록/표시했다.
2. API에서 미입력 값을 나중에 추가하면 원래 출처 스냅샷 검사가 놓쳤다. None을 포함한 전체 계산 입력 스냅샷과 반례를 추가했다.
3. CNC에 `slicer` 메타데이터를 넣으면 엔진 생성이 실패했다. DB 스키마 검증에서 공정 불일치를 거부한다.
4. 프로필 생성 API가 사용자의 실제 근거 문구를 기본 출처로 덮어썼다. 명시적 사용자 근거를 보존한다.
5. 일괄 형상검토의 복사본에 조건 DB가 빠져 엔진 해시가 달랐다. 감사·갱신 스크립트의 복사와 지문에 동일한 데이터 파일을 포함했다.

## 재현과 검증

- DB 및 원문 해시 검사: `validation/conditions-2026-09-28/catalog-audit-final.json`.
- 최종 전체 시험: **938개 통과, 실패 0개, 경고 1개, 370.57초**. 저장소 Python 3.12.14에서 `tests_v3 tests`를 실행했다. `validation/conditions-2026-09-28/regression-final.txt`, `.xml`에 기록했다. 경고는 기존 `test_aabb_overlap_is_not_solid_overlap`의 Trimesh 체적 계산 중 발생한 `invalid value encountered in divide`다.
- 바탕화면 실행본 Python **3.13.15**에서 새 DB·통합·UI 시험 3개 파일을 다시 실행해 **115개 통과, 실패·오류·건너뜀 0개, 30.24초**를 확인했다. `desktop-focused.txt`, `.xml`에 기록했다. 이 115개는 전체 938개와 중복되므로 합산하지 않는다.
- 두 실행 모두 OPENBLAS/OMP/MKL/NUMEXPR 스레드를 1로 설정했다.
- 최초 전체 시험은 931통과/3실패/1경고였다. 새 테스트의 상태명 기대 불일치 1개, DB가 감사 복사본에 빠지는 실패 2개를 고쳤다. `regression-01` 로그는 삭제하거나 최종 통과 수에 합산하지 않는다. 해당 실행 중 독립 감사의 API 수정도 진행되어 최종 소스 검증은 반드시 최종 실행을 따른다.
