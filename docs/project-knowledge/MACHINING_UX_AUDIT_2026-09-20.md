# 절삭 검토 사용자 관점 재감사 — 2026-09-20

사용자의 최신 지시는 사출·프레스 개발 중단·제거와 절삭 기능의 근거·수치·편의성 재검토다. 이 문서는 절삭 화면·보고서의 사용자 해석을 다룬다. 제조 성공 여부를 확인한 문서가 아니다.

## 판단 기준과 검토 자료

처음 보는 사용자가 화면만 보고 다음 다섯 질문에 답할 수 있어야 한다.

1. **무엇이 걸렸는가?** 형상 수정 후보, 입력 부족, 계산 안 함, 범위 안 미검출을 구분한다.
2. **어떤 조건에서인가?** 입력 형상·방향·실제로 적용한 공구 치수를 함께 확인한다.
3. **어디이고 수치 차이는 얼마인가?** CAD 면 ID만 외우게 하지 않고 위치·측정값·비교값을 연결한다.
4. **무엇을 바꿀 것인가?** 현재 상태에 맞는 다음 행동을 제공한다.
5. **얼마나 확인된 것인가?** 검토 범위 밖과 실제 공구/홀더/가공 경로 검증 여부를 구분한다.

검토 자료는 현재 `dfm/machining_view.py`, `dfm/machining.py`, `docs/USER_GUIDE_MACHINING.md`, `tests_v3/test_machining_ui.py`, [기존 실제 Edge QA](../../validation/machining-2026-09-19/ui/UI_QA.md)다. 기존 QA의 8단계 통과를 이번 수정본의 통과 증거로 재사용하지 않는다. AppTest는 상태·표·문구·차트 명세를 검증하는 도구이며 실제 브라우저 캡처나 사람의 사용성 시험과 구분한다.

## 상용 도구에서 참고한 구조

- [Autodesk Fusion — Evaluate the accessibility](https://help.autodesk.com/cloudhelp/ENU/Fusion-Model/files/SLD-ACCESSIBILITY-ANALYSIS.htm), 공식 본문을 2026-09-20에 확인했다. 형상과 접근 방향을 선택하고 모델에서 위치를 확인하며 방향·표시를 편집하는 흐름을 제공한다. 이 프로젝트에서는 방향 표시와 결과 위치 연결의 참고로 사용한다. Autodesk 기능의 정확도를 이 앱의 표본 광선 계산에 이전하지 않는다.
- [HCL DFMPro — How DFMPro Helps with the Design Review Process](https://dfmpro.com/blog/how-dfmpro-helps-with-the-design-review-process/), 공식 본문을 같은 날 확인했다. 개별 검토 항목의 상세 위치, 실제값·검토 기준, 이유, 후속 행동과 보고서 이미지를 연결하는 구조를 설명한다. 이 프로젝트의 화면·내보내기 정보구조에 참고한다. 제조사 홍보상의 효과나 성공 표현을 제품 성능 검증으로 사용하지 않는다.

단순한 빨강/초록 합격 표시는 채택하지 않는다. 이 앱의 미검토 범위와 실제 제조 조건을 보존하면서, **현재 비교에서 걸린 이유와 바로 할 행동**을 분명하게 표시하는 것이 목적이다.

입력 형식 문제는 설치된 Streamlit 1.63의 `number_input.py`에서 float 기본 형식 `%0.2f`를 직접 확인했다. 공식 로컬 `st.number_input` 문서도 `format`이 표시만 바꾸고 반환값은 바꾸지 않는다고 설명한다. 따라서 이는 계산 정확도와 별개인 **표시값·실제 적용값 불일치**다. 이 확인을 위해 실행한 최초 CLI 도움말은 Windows cp949 인코딩 오류로 실패했고, `python -X utf8 -m streamlit docs st.number_input`으로 다시 읽었다.

## 유지할 점

- 공구 치수를 모를 때 빈칸으로 측정을 실행할 수 있고, 미입력을 0이나 합격으로 바꾸지 않는다.
- 결과는 이유·다음 행동·위치·범위의 순서이며, 새 형상/방향에 이전 결과를 표시하지 않도록 조건 식별자를 사용한다.
- 표면 가림은 실제 검사한 점에 색과 기호를 함께 부여한다. 광선 하나의 결과를 전체 면 색이나 유한 공구의 통과 판정으로 바꾸지 않는다.
- 방향 화살표가 부품에서 공구 쪽을 향한다는 설명을 유지한다.
- 곡선·분할·섬 포켓을 인식하지 못한 것은 포켓이 없는 판정과 구분해야 한다.
- 계산 완료를 실제 가공 성공으로 표시하지 않는다.

## 이번 수정본 검증

다음 사항을 실제 코드와 AppTest로 확인했다.

- 오목면 R3에 Ø8 공구는 `반경 3 / 공구 반경 4 / 차이 −1 mm`와 초과를 보여준다. Ø4로 바꾸면 공구 반경 2, 차이 +1 mm이며 다음 행동도 실제 경로·홀더 확인으로 바뀐다. 작은 공구를 다시 요구하지 않는다.
- Ø6의 동일 반경 조건은 표에서 `수치 경계·별도 확인`으로 표시한다. 계산 오차 경계를 제조 공차나 가공 여유로 해석하지 않는 안내가 있다.
- 공구 지름을 비우면 측정한 R3은 유지하지만 공구 반경과 비교값은 `미입력·미비교`로 바뀌며 지름 입력을 안내한다.
- 현재 보고서에 적용한 지름·날 길이·장착 후 돌출 길이가 결과 위에 표시된다. 새 form 입력은 실행 버튼 뒤 반영됨을 명시한다.
- 최소 허용 입력 0.001 mm가 위젯의 표시 형식과 적용 조건에 0이 아닌 값으로 보존된다. 이 시험은 초소형 공구의 실제 가공 가능성을 입증하는 시험이 아니다.
- 항목의 CAD 면을 하나 선택하면 형상 강조 범위가 해당 위치로 줄어든다. 같은 형상에서 공구 치수를 바꾸어도 선택 위치를 유지한다. 추가 검토에서 단순 측정 위치까지 모두 주황색이 되는 문제를 찾아, **파랑은 선택한 측정 위치, 주황은 원래 계산 결과에서 조건 확인이 필요한 위치**로 분리했다.
- 비정렬 원통의 치수 비교 보류는 `축 불일치·미비교`로 표시한다. 입력 공구가 실제 존재하는데 `미입력`이라고 보이던 모호함을 없앴다.
- HTML은 한글 적용 조건표, 항목별 치수·상태·행동·근거 링크, 원본 좌표의 오프라인 SVG 참고도와 접힌 원자료를 포함한다. 참고도는 공구축으로 회전한 그림이나 정밀 도면이 아니며, 형상 식별자가 다른 모델의 그림을 붙이려 하면 거부한다. 외부 CDN 없이 표시되며 사용자 텍스트는 이스케이프하고 http(s) 이외의 출처는 활성 링크로 만들지 않는다.

기존 +X 기대 변경은 단순히 테스트를 통과시키기 위한 완화가 아니다. 기준 STEP에서 CAD 면 10을 직접 읽어 중심 `[10, 15, 11] mm`, 법선 `+X`, 면적 `96 mm² = 12×8`인 포켓 내부 옆벽임을 확인했다. +X 방향에서는 내부 바닥 후보가 되지만 네 개의 동일 높이 벽으로 둘러싸인 직사각 포켓 조건을 충족하지 않는다. 따라서 폭·벽 높이는 측정하지 않고 해당 CAD 위치를 미확정으로 유지한다. 수정한 테스트는 `unknown`, 측정 포켓 빈 목록, 미확정 CAD 면 `[10]`을 함께 확인한다.

### 남은 확인 범위

후속 통합 검증: 실제 브라우저에서 직접 각도 0.005°의 반올림 표시를 재현하여 0.005000°로 보존하도록 수정했고, 독립 삼각함수와 보고서 방향을 비교하는 AppTest 1개를 추가했다. 이 변경까지 포함한 전체 818개가 통과했다. [최종 통합 기록](MACHINING_REAUDIT_2026-09-20.md)과 [실제 브라우저 QA](../../validation/machining-reaudit-2026-09-20/ui/BROWSER_QA.md)를 따른다.

- AppTest는 실제 화면의 줄바꿈·가로 스크롤·색 인지·키보드 조작을 입증하지 않는다. 이번 실행본의 실제 브라우저 QA는 루트 작업의 별도 기록을 따른다.
- 측정 위치와 조건 확인 위치의 색 분리는 차트 명세뿐 아니라 최종 브라우저에서 색과 안내 문장의 일치 여부를 별도로 확인한다.
- HTML SVG는 전체 형상의 식별용 참고도다. 개별 특징을 확대하거나 직접 회전하며 확인하는 기능은 앱에 있다. 보고서가 완전한 CAD 뷰어나 CAM 충돌 검증을 대신하지 않는다.
- 사람을 대상으로 한 사용성 시험, 스크린 리더 접근성 시험, 모든 화면 폭·브라우저 검증은 수행하지 않았다.
