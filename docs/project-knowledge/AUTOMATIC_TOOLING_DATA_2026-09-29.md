# 공개 CAD 학습 자료·공구 입력 최소화

사용자 요청: MFCAD++ 및 대안 데이터의 학습 활용성, 공정별 학습 방식의 이유, 빈 공구 입력의 자동 추천. 적층·절삭만 유지하며 학습법 설명을 제품 화면에 추가하지 않는다.

## 구현

- 공구 세 치수를 비워 둔 채 검토하면 선택 접근축의 STEP 특징을 측정하고, 비어 있는 값만 제안한 다음 같은 엔진으로 재검산한다. 기존 입력·조건 DB의 출처 값은 보존한다.
- `dfm/tool_recommendation.py`: 측정 개구·내부 반경의 지름 상한 중 최솟값에 기본 80%를 적용한다. 날 길이는 인식한 벽 높이·원통 구간 중 최댓값+1 mm다. 돌출 길이는 선택축의 전체 형상 메시 상단부터 대상 특징 끝까지의 거리+1 mm를 초기 후보로 사용한다. 날 길이≤돌출 길이를 유지한다.
- 80%와 1 mm는 편집 가능한 앱의 초기 제안 정책이다. 표준 한계, 제조사 공구 규격, 학습된 최적값으로 표시하지 않는다. 실제 공구 SKU를 선택한 결과도 아니다. 공구 카탈로그·목부·홀더·경로를 연결하는 후속 확장이 남는다.
- 떨어진 높은 형상 때문에 전체 상단 기준이 길어질 수 있다. 이 값보다 짧은 고정 공구를 곧바로 오류로 판정하지 않는다. 원호 밀링의 짧은 날은 여러 깊이 절입·목부 사용 조건을 확인하도록 구분한다.
- 내부 직각에 지름 0을 추천하지 않는다. 축이 다른 구멍·가려진 특징·미측정 치수·복수 솔리드·STL은 자동 값 산정 범위를 제한한다. 원호 밀링용 엔드밀과 홀별 드릴 명목지름 요구를 구분한다.
- `cnc_tool_recommendation` finding으로 새 수치 충돌·진입 조건의 미확정을 결론·위치·표·JSON·HTML까지 보존한다. 자동 제안이 생겼다는 이유로 기존 미확정이 정상으로 바뀌지 않는다.
- 보유 공구 입력은 접어 두고, 종합 결론에 검토 공구 세 치수와 자동/입력 출처를 표시한다. 자동 제안을 끄거나 기본 여유를 변경할 수 있다. 조건 변경 때 이전 결과는 숨기고 재검토한다.

## 학습 자료 판단

[MFCAD 조사·실제 샘플 검사](../research/public-cad-data-2026-09-29/MFCAD.md), [대안 자료·AI 우선순위](../research/public-cad-data-2026-09-29/ALTERNATIVES.md).

MFCAD++는 면별 가공 특징 학습용이며 공구 최적치수나 좋은 수정안의 정답은 아니다. MFInstSeg는 특징 인스턴스·바닥면을 추가로 제공한다. 공개 분할 목록에서 중복 행 13개와 분할 간 공통 ID 5개를 확인했다. MFCAD 원본은 STEP 면 name과 라벨을 연결해야 하며 파일상 순서로 연결하면 틀린다. 소규모 STEP 두 개를 OCP로 읽고 면·라벨·치수·체적을 확인했다. 전체 MFCAD++ 다운로드·재학습은 하지 않았고, 기존 학습 가중치를 변경하지 않았다.

우선순위는 특징을 더 잘 찾는 그래프 모델→CAD 치수 재측정→기존 조건 및 개선안 평가의 연결이다. 적층은 실제 공개 형상에서 방향별 표적을 만들고, 절삭 순차 계획은 동일 행동 공간의 탐색·모방학습을 DQN과 비교한다. 현 DQN의 기존안 대비 우위가 충분히 확인되지 않아 강화학습 확장이 자동으로 최고라는 주장은 하지 않는다.

`scripts/audit_public_cad_data.py`는 원본을 수정하지 않고 SHA·면/라벨 연결·공개 분할 중복을 재검사한다. 실제 자료와 초기 실패 로그는 저장소 밖 `study/public-cad-data-2026-09-29/`에 보존한다.

## 검증

실제 STEP 단차홀(전체 깊이21 mm)을 구간 길이11 mm로 잘못 대표하는 반례에서 돌출 후보를12→22 mm로 고쳤다. 떨어진 높은 돌출부, 짧은 고정 날, 미지원 면 공존을 독립 재검사했다. 새 자동 입력은 공구 계획의 규칙·정책 확장이지 새 학습 성능 결과가 아니다.

최종 결과는 [검증 요약](../../validation/automatic-tooling-2026-09-29/summary.json)에 있다.

- V3 전체 첫 실행 1,277통과/1실패. 실패는 빈 값을 유지하던 이전 기본 동작의 시험이므로 자동 제안을 끄는 입력으로 수정했다. 이후 해당 파일10개+기존 검사167개가 모두 통과했다. 고유 검사1,445개의 최종 상태가 통과이며, 한 번에1,445개를 실행했다고 합쳐 설명하지 않는다. 초기 UI 대상 검사에도 같은 종류의 이전 옵션 목록 기대값 실패가 있었고 전체 V3 재실행에서 해소됐다.
- 바탕화면 Python3.13에서 새 수치·화면·조건 DB 관련54검사를 통과했다. 소스와 실행본의 런타임·모델·앱 바이트가 같다. 코드 SHA는 `50a7f9974fb3b330960bcbb6cb854c04ebb93fd6b44b7a23d8c3721da3a3c591`이다.
- STEP33개×접근축3개×입력상태3개=297조건의 입력 보존·치수 재검산·미확정 전달 검사.44조건에서110개 빈 값을 채웠다. 조건 결과는 conditional41/unavailable210/conflict25/not_applicable21로 보존했다.297개가 모두 자동 치수 추천에 성공했다는 뜻은 아니다.
- 최초 실행은31파일279조건 후 Raspberry Pi 조립체의75초 읽기 제한으로 중단됐다. 마지막2파일은 감사에서만180초를 허용해18조건을 추가 확인했다. 제품의 기본75초 제한은 바꾸지 않았다. 두 실행과 초기 실패를 보존한다.
- 실제 브라우저에서 모든 공구 치수가 비었을 때2.4/21/21 mm, 지름만2 mm로 지정했을 때2/21/21 mm를 확인했다. 개선 반경도1.2→1 mm로 바뀌었다. 위치 버튼이 CAD 면11의 포켓 바닥 폭3 mm·벽 높이20 mm로 직접 이동하고 제목에 초점을 주는 것을 확인했다.

원본 배치 기록·교체 전 백업은 `study/automatic-tooling-2026-09-29/`에 있다. 새 공개 CAD 전체 학습이나 가중치 교체는 이번 완료 범위가 아니다.
