# 절삭 재감사: 계산·근거·사용자 편의성

작업일: 2026-09-20. 사용자의 최신 지시는 **사출·프레스 제거 및 미진행, 절삭가공의 정확성·문헌 근거·수치·사용자 편의성 검토**다. 현재 제품 범위는 적층·절삭이며 장기 계획을 근거로 다른 공정을 자동 재개하지 않는다. 이번 변경은 작업 저장소의 개발판이다. 바탕화면 배포본 갱신이나 GitHub 푸시를 수행했다는 의미가 아니다.

## 최종 판단

현재 절삭 기능은 **단일 STEP과 선택한 원통형 엔드밀에 대한 고정축 국소 기하 검토**로 설명하는 것이 타당하다. 반경·폭·국소 길이를 공구와 비교하고, 위치와 다음 행동을 제공할 이유가 있다. 반면 절삭 전체 제조성, 실제 공구 경로의 충돌, 품질·강성 또는 가공 성공 확률까지 검증했다고 표현할 수 없다.

문헌에 검토 항목이 있다는 사실과 우리 계산이 맞는다는 사실을 구분했다. 공식 기술문서 6개·연구논문 관련 본문 2개·OCCT API 문서 1개를 실제 측정·입력 조건·허용 결론과 대조했다. 읽은 범위와 접근 실패도 [문헌 재감사](../research/MACHINING_EVIDENCE_REAUDIT_2026-09-20.md)에 남겼다. 독립 생성 치수와 회전식 등으로 계산을 검증했으며 문헌을 알고리즘 정확도의 대체 증거로 쓰지 않았다.

## 사출·프레스 제거

이번에 추가했던 두 공정의 Python 모듈, 공통 비교 화면, 앱 진입점, STEP 23개와 목록·생성기, 전용 시험·설명서·연구 문서, 생성 로그와 바이트코드를 제거했다. 실행 중이던 해당 시험과 개발 서버도 소유 프로세스를 확인한 뒤 종료했다. 삭제된 시험의 pytest 캐시 항목 190개도 정리했다. 기존 적층·절삭 코드, 사용자의 원문 문헌·원본 보관자료·기존 검증 기록은 유지했다.

일괄 재귀 삭제는 자동 승인 검토에서 `blocked by policy`로 거절됐다. 이후 삭제 대상 텍스트 파일을 명시한 패치와 개별 파일·빈 폴더 삭제로 범위를 좁혀 제거를 완료했다. 삭제 범위 확인은 [removal-verification.json](../../validation/machining-reaudit-2026-09-20/removal-verification.json)에 있다. 장기 목표 문서는 구현물이 아니라 과거 의사결정 기록으로 보존하고, 최신 미진행 지시를 맨 앞에 명시했다.

## 실제로 찾아 수정한 문제

| 문제 | 수정과 사용자에게 보이는 결과 |
|---|---|
| 같은 8 mm 포켓을 회전하니 8.000000000000675 mm가 되어 공구 길이 초과로 표시 | 계산 오차 밴드를 도입하고 같은 값은 **수치 경계·별도 확인**으로 표시. 이 밴드는 제조 공차가 아니다. 0.001 mm의 실제 차이는 계속 검출한다. |
| 회전 후 큰 좌표로 이동하면 내부 바닥이 인식에서 빠져 ‘없음’으로 보임 | 안쪽 벽이 연결된 미확정 바닥 위치를 보존하고 폭·높이를 미측정으로 안내. 채널·밀폐 공동도 포함할 수 있어 열린 포켓으로 확정하지 않는다. |
| 약 0.0081°까지 실제 축 기울기를 정렬로 취급 | 외적 기반 수치 정책으로 분리하고 원통축과 선택축 사이 실제 각도를 보고. 비정렬 면의 공구 치수 비교는 보류한다. |
| UV 각도 범위 360°를 완전한 원통 벽으로 표현 | **원주 방향 범위가 360°인 내부 원통면**으로 수정. 교차 창·분할 원통·막힌 구멍 반례에서 면과 전체 구멍을 구분한다. |
| 지름 8→4 mm로 문제를 해소해도 작은 공구를 권장 | 문제 있음·해소·수치 경계·미입력에 따라 다음 행동이 바뀐다. 원통 항목도 축·지름·길이·사용자 기준 중 실제 확인 사유를 설명한다. |
| 모든 항목에 같은 문헌과 계산 방법을 붙임 | 입력 계약·CAD 치수·포켓 인식·표본 레이를 분리하고 항목별 근거를 연결한다. |
| 반경과 지름을 혼동할 수 있는 표 | 오목면은 형상 반경·공구 반경·차이·비교 결과를 나란히 표시. 원통·포켓에도 입력 공구 조건을 함께 표시한다. |
| 위치를 고르기 어렵고 문제없는 측정면까지 주황색 | **확인할 위치**에서 CAD 면을 선택. 측정·추가 확인은 파란색, 해당 항목의 조건 확인 위치는 주황색. 원래 결과는 바꾸지 않는다. |
| 작은 수치가 반올림되어 다르게 보임 | 공구 0.001 mm와 직접 각도 0.005°가 각각 0.0010 mm, 0.005000°로 유지되도록 표시 정밀도 수정. |
| 스크롤하려다 3D 형상이 축소됨 | CNC 그림의 휠 확대를 끄고 문서 스크롤을 유지. 회전·확대는 그림 도구 모음으로 한다. |
| 내보낸 보고서가 영어 조건 원자료 위주 | 한글 적용 조건표, 오프라인 SVG 참고도, 항목별 출처를 HTML에 추가. JSON 정밀 원자료와 미입력 상태는 보존한다. |

상단에는 현재 결과에 실제 적용한 지름·날 길이·장착 후 돌출 길이를 보여준다. 폼 안의 새 입력은 실행 버튼을 눌러 적용된다는 안내를 넣었다. 재료·장비명은 현재 기록용이며 이를 입력한다고 절삭력·처짐이 계산되는 것은 아니다. 날 길이보다 벽이 높아도 감소 목부와 분할 절입이 가능하므로 곧바로 가공 불가로 판정하지 않는다.

## 검증 기록

**최종 전체 회귀검사 818개 통과, 경고 1건, 483.46초(8분 3초).** [콘솔 출력](../../validation/machining-reaudit-2026-09-20/regression-complete.txt)과 [JUnit](../../validation/machining-reaudit-2026-09-20/regression-complete.xml)을 보존했다. 경고는 기존 `test_aabb_overlap_is_not_solid_overlap`의 Trimesh 체적 기반 질량중심 계산 RuntimeWarning이며 해당 검사는 통과했다. 별도 레거시 검사도 [55/55 통과](../../validation/machining-reaudit-2026-09-20/legacy.txt)했다. 이 숫자는 소프트웨어 검사 수이며 제조 시편 수나 가공 성공률이 아니다.

- 계산: 새 독립 반례 22개를 포함한 대상 검사 131개 통과. 생성 치수·Rodrigues 회전식·원통 면적식을 기대값으로 썼다. 인치 단위, 회전·이동, 실제 수치 차이, 축 경계 양쪽, 섬·채널·보스·밀폐 공동, 교차 창·분할 원통을 포함한다. [계산 감사 기록](../../validation/machining-reaudit-2026-09-20/geometry/README.md).
- UI·보고서: 새 UX 15개와 기존 사용자 흐름 5개, 총 20개가 색 구분까지 통과했다. 이후 실제 브라우저에서 발견한 소수 각도 표시 문제의 검사 1개를 추가하여 최종 전체 검사에 포함했다. [UX 감사 기록](MACHINING_UX_AUDIT_2026-09-20.md).
- 실제 화면: Codex 내장 브라우저의 별도 localhost 8512 테스트 앱에서 공정 목록, R3/Ø8→Ø4, 측정면 선택, 수치 경계와 작은 각도 표시를 확인했다. [브라우저 QA](../../validation/machining-reaudit-2026-09-20/ui/BROWSER_QA.md). 사용자 8507 포트나 바탕화면 앱을 교체하지 않았다.
- 형상 목록: 128개 파일, SHA 기준 122종을 무결성 검사했다. 추가 10개 STEP은 독립 회전·이동 5조건의 수정 전후 내보내기 기록으로 물리적으로 다른 10개 설계라는 뜻이 아니다.
- 기존 절삭 예제 12개를 최종 코드로 다시 계산해 [관측 보고서](../../validation/machining-reaudit-2026-09-20/observations-complete/summary.json)를 저장했다. 이 저장 자체가 독립 기대값 검사를 대신하지 않으며 별도 pytest의 치수 검증과 구분한다.
- 기존 무작위 형상 26개도 전수 입력·범위를 관측했다. 처음에는 24개가 처리되고 큰 STEP 2개가 감사용 45초 한도를 넘었다. 이 두 개만 실제 앱과 같은 180초로 재확인해 펌프 조립체 66.94초, Raspberry Pi 조립체 142.41초에 완료했다. 최종적으로 26개 모두 입력은 처리했지만 **제한된 CAD 치수 검토는 단일 솔리드 9개**, 나머지 17개는 다중 솔리드 10·표면 STEP 2·STL 4·3MF 1로 정량 판정을 보류했다. 조립체는 앱에서 부품을 선택하면 그 부품을 따로 검토한다. 단일 솔리드 9개 중 8개에도 미지원 곡면 또는 미확정 원통면이 남았다. [전수 기록과 재시도](../../validation/machining-reaudit-2026-09-20/corpus-observations/README.md)를 보존했으며 **26개 형상의 전체 치수 정확도를 통과한 결과로 해석하지 않는다.** 원본 SHA와 엔진은 변경되지 않았다.
- 초기 새 후보 인식의 상단 테두리 오인식과 시험 문구 불일치, UI의 이전 미검출 기대값은 첫 실패와 수정 근거를 보존했다. 전체 검사 중 UI 추가 문제를 찾아 중단한 두 로그는 완료 검사로 세지 않는다.

최종 엔진·화면 소스 보관본: [engine-source-complete/manifest.json](../../validation/machining-reaudit-2026-09-20/engine-source-complete/manifest.json). 코드 식별자는 `9b8fda0296c7bccb9fa320a9ffa15638f11a738ca497bc11b6925dfbdf674fe5`다. 환경은 Windows, Python 3.12.14, Streamlit 1.63.0, cadquery-ocp-novtk 7.9.3.1.1이다.

## 사용 방법과 남은 한계

처음 사용하는 경우 [절삭 사용법](../USER_GUIDE_MACHINING.md)을 따른다. R3 예제에서 Ø8은 공구 반경 4 mm가 형상 반경 3 mm보다 크다. Ø4로 바꾸면 반경 비교 문제는 사라진다. Ø6은 수치상 경계이므로 실제 가공 여유·물림을 확인해야 한다. 이 예는 공구 선택에 따른 국소 기하 차이를 보여주는 것이며 실제 가공 시험 결과가 아니다.

인식기는 모든 포켓·구멍을 재구성하지 않는다. 특히 큰 좌표에서 치수를 확정하지 못하는 한계는 오류 없이 측정한 것으로 숨기지 않는다. 표면 가림은 제한된 점의 직선 검사이며 전체 면 또는 유한 공구·홀더의 통과를 증명하지 않는다. 원소재·고정구·공구 어셈블리·소재 제거 순서·진입/복귀 경로·공차·강성·절삭력·표면 품질·실물 검증은 별도로 남아 있다.

따라서 현재 신뢰 범위는 **명시한 조건과 독립 반례에서 검증한 기하 측정·비교·미확정 보존**이다. 일반적인 가공 가능/불가 또는 성공 확률을 추가할 근거는 아직 없다.
