# 절삭 1차 구현과 검증 기록

> 후속 지시·현재 상태: 2026-09-20 사용자가 사출·프레스 제거 및 미진행을 명시했다. 아래 문서는 당시의 1차 구현 기록이다. 현재 개발 범위와 최신 검증은 [절삭 재감사](MACHINING_REAUDIT_2026-09-20.md)를 우선하며, 이 문서의 장기 계획을 다른 공정의 재개 지시로 해석하지 않는다.

작업: 2026-09-19~20. 경로 날짜는 작업 시작일이다. 기존 AM-DFM v3에 고정축 밀링의 제한된 기하 검토를 연결했다. **개발 작업공간의 변경이며 바탕화면 배포본·GitHub 출시 완료를 뜻하지 않는다.** 적층·절삭·사출·프레스 전체 목표와 연구 목표는 유지한다. 사출·프레스·AI와 실제 CAM/실물 검증은 이번 변경에 포함하지 않았다.

## 개발 순서에 대한 판단

다음 미팅을 위한 우선순위는 **절삭 규칙 기반 핵심 → 적층·절삭 결과의 일관된 표현 → 공통 AI 설명·근거 검색·도구 호출**이다. 처음부터 적층 전용 AI와 절삭 전용 AI를 별도로 만드는 구조를 피하고, 현재 `Finding`의 측정·근거·위치·다음 행동·미확정 범위를 두 공정이 재사용한다. 전체 보고서와 모든 공정이 완전히 통합된 것은 아니다.

AI 없이도 검사 결과의 정의와 독립 검증이 성립해야 한다. AI의 첫 역할은 계산 결과·적용 조건·원문 근거를 이해하기 쉽게 설명하고 사용자가 요청한 비교를 도구로 실행하는 것이다. 제조 성공 확률은 외부 실물 자료의 조건 적합성·대표성·독립 평가·확률 보정을 요구하는 별도 연구다. 템플릿 설명과 비교해 AI가 수치 오류·출처 오류·미확정의 확정 승격 없이 판단 정확성과 시간을 개선하는지 평가할 수 있다. 이 방향 자체의 독창성은 아직 입증하지 않았다.

이번 개발 순서와 추가로 확인한 외부 연구·확인 깊이는 [AI 도입 판단 기록](../research/AI_SEQUENCING_NOTE_2026-09-19.md)에 있다. 초록만 확인한 논문은 본문 검토 완료로 기록하지 않았다.

## 구현한 것과 이유

| 변경 | 사용자 결정 / 구현 이유 | 검토 범위 |
|---|---|---|
| 공정 선택과 절삭 입력 화면 | 같은 형상을 다른 공정에서 검토하고 공구 조건을 기록 | 기존 적층 화면 유지, 절삭 전용 상태·캐시·보고서 분리 |
| STEP 트림 경계와 인접 면 정보 | 평면 하나를 무조건 포켓으로 오인하지 않도록 실제 CAD 연결을 확인 | 원래 face/body ID 보존; 선·원호·외곽/내부 wire; 기타 곡선은 미지원 |
| 평면 면적·중심 및 원통 축 구간 | 표시용 메시와 CAD 치수의 출처를 구분 | OCCT 해석 곡면의 수치 적분·UV 구간; 공차나 드릴 전체 깊이 보증 아님 |
| 직사각 포켓 인식 | 내부 직각·좁은 폭·국소 벽높이와 공구를 비교 | 네 직선 바닥 경계, 안쪽 수직 벽, 동일 높이, 바깥을 향한 평면 테두리만 인식 |
| 원통면·오목 부분 원통면 비교 | 선택 공구 지름·길이와 방향의 차이 확인 | 원통면 수와 홀 수 구분; 복합·교차 홀 자동 병합 없음 |
| 표면 가림 검사 | 다른 방향을 검토할 표본과 미확정 영역 확인 | 점·직선 검사, 유한 공구/홀더/고정구의 swept-volume 검사 아님 |
| 결과 위치·다음 행동·표본 분류 | 사용자가 숫자를 보고 무엇을 바꿀지 결정하도록 안내 | 주의·측정·미검출·미확정 구분; 표본은 실제 점으로 표시 |
| HTML/JSON/원본 내보내기 | 조건·근거와 결과를 다시 확인 | 입력 SHA·코드 식별, 계산 원자료와 한계; CNC HTML의 3D 그림은 미포함 |

CAD 경계는 **면당 512개 edge, 모델 전체 50,000개 edge** 예산을 둔다. 초과는 `partial`로 보존하며 검출 없음으로 바꾸지 않는다. 표면 가림은 기본 표본 최대 512개·200,000삼각형·20,000,000 ray-triangle 검사·10초 작업자 시간 한도로 제한한다. 작업자 실패·시간 초과는 미확정이다. 표본 상태는 visible/occluded/back_facing/tangent/unknown을 한국어로 각각 표시한다. 내부 공동·분리/문제 껍질 등에서는 접근성 판정을 보류한다.

공구 값은 기본 미입력이며 6D 같은 서비스 가이드를 보편적 절삭 한계로 고정하지 않았다. `공구 지름 ≤ 특징 지름` 또는 `공구 반경 ≤ 오목면 반경`은 현재 단순 원통 공구 가정에서의 국소 기하 비교다. 길이 비교는 국소 벽높이/원통 구간이며 입구부터의 전체 도달 길이가 아니다. 공식 근거와 조건은 [M01~M05](../research/MACHINING_EVIDENCE.md)에 기록한다.

## 독립 검토에서 찾아 수정한 문제

- `role=unknown` 원통면이 있으면 오목면 검토에서도 `unknown`과 면 ID를 보존한다. 확정된 충돌 후보는 다른 면의 미확정 때문에 지우지 않는다.
- 공구 미입력 상태를 “공구보다 작은 반경 0개”로 쓰지 않고 비교 보류로 설명한다.
- 표면 차폐만 표시하면 반대쪽·측면 표본이 숨겨지므로 다섯 상태를 요약하고 선택할 수 있게 했다. 표본을 측정한 면 전체를 위험 색으로 칠하지 않는다.
- “도달 길이 초과”를 “원통 구간 > 도달 길이” 또는 “벽 높이 > 도달 길이”로 좁혀 표시한다. `아니오`는 실제 가공 통과가 아니다.
- 면 경계 추출 완료를 전체 특징 인식 완료로 표현하지 않는다. 챔퍼 때문에 8변이 된 포켓과 곡선·섬·분할 포켓의 폭·깊이는 미검토다.
- 새 `dfm` 패키지를 코드 식별에 포함하면서 기존 전수 감사의 엔진 스냅샷 목록과 식별 계산이 불일치하는 회귀를 발견했다. 감사·보고서 갱신 스크립트도 같은 패키지를 보존하도록 수정했다.
- 실제 브라우저에서는 형상 변경 후 확인 항목의 선택 표시와 본문이 불일치했다. 옵션의 순서·라벨을 고정하고 새 형상의 첫 항목만 우선순위로 선택한다. 같은 형상의 공구 변경에서는 사용자가 보던 항목을 유지한다. 별도 브라우저 재실행에서 D8→D4 결과·표·강조의 일치를 확인했다.
- 평면 블록이 곡면처럼 보이는 음영을 줄이기 위해 CNC의 Mesh3d만 flat shading으로 표시했다. 기존 적층 그림의 기본 설정은 유지한다.
- 기존 작업자 종료 시험의 0.4/0.6초 준비 가정이 현재 호스트의 실측 첫 Python 실행 0.753~1.515초와 맞지 않았다. 생산 시간 제한 코드는 변경하지 않고 시험을 5초 절대 제한·6.2초 호출 상한·실제 자식 준비 표식·늦은 출력 감시로 보강했다. [실측·실패·변경 원리](../../validation/machining-2026-09-19/process-timing/README.md)를 보존한다. 세부 기동 지연 원인은 미확정이다.

## 기준형상과 실행 기록

자체 STEP 12개는 [manifest](../../examples/machining/manifest.json)의 독립 생성 치수·체적·반경·방향·SHA와 대조한다. 직사각/좁은/둥근 포켓, 수직·측면 구멍, 보스, 밀폐 공동, 열린 채널, 섬 포켓, 단순 블록, 회전 포켓, 분리 솔리드를 포함한다. 기존 원본 형상과 문헌을 수정하지 않았다. 전체 형상 색인은 118파일·112개 SHA로 확장했다.

검증은 Windows Python 3.12.14, Streamlit 1.63.0, OCP 7.9.3.1 환경이다. 새 검사는 CAD 특징 10개, 표면 가림 39개, 자체 형상/검토 40개, 미확정·표시 계약 20개, AppTest 사용자 흐름 5개다. 이 숫자는 소프트웨어 검사 수이며 실제 가공 표본이나 제조 성공률이 아니다.

최종 전체 회귀검사는 **780 통과, 경고 1건, 509.27초**다. [최종 출력](../../validation/machining-2026-09-19/regression-complete.txt)과 [JUnit](../../validation/machining-2026-09-19/regression-complete.xml)에 보존했다. 경고는 기존 `test_aabb_overlap_is_not_solid_overlap`에서 Trimesh의 체적 기반 질량 중심 나눗셈이 발생시킨 RuntimeWarning이며 해당 시험은 통과했다. 별도 레거시 검사도 55/55 통과했다. 전체 실행 원자료는 [검증 색인](../../validation/machining-2026-09-19/README.md)에 있다. 첫 AppTest의 1건 실패는 Plotly JSON의 유니코드 이스케이프를 문자열로 직접 검색한 시험 문제였으며 JSON 파싱 후 4개 모두 통과했다. 실제 브라우저에서 찾은 선택 문제에 대한 별도 1개 시험을 추가한 뒤 최신 UI·계약 25개도 통과했다. 전체 형상 추가에 따른 과거 색인 기대값 변경, 코드 스냅샷 누락, 작업자 준비 시간 전제의 실패는 삭제하지 않는다.

실제 화면은 설치된 Edge 153의 독립 headless context에서 1440px/780px로 확인했다. CUA 브라우저가 연결되지 않아 이 대안을 사용했으며 기존 사용자 8507 서버와 프로필은 조작하지 않았다. [최종 브라우저 결과](../../validation/machining-2026-09-19/ui/final-browser-v3/browser_result.json)는 8개 흐름, page error 0건이다. D8의 R3 초과4개→D4 초과0개, 동일 항목 유지, 블록의 반대2/평행8/직선가림없음2 표본, 필터의 즉시 갱신, 적층 복귀를 확인했다. [QA 기록과 PNG](../../validation/machining-2026-09-19/ui/UI_QA.md)에 초기 실패와 최종 화면을 구분한다. 좁은 화면의 긴 표 열은 가로 스크롤을 사용하며, 사용자 과제 평가나 실물 가공 실험은 수행하지 않았다.

최종 기하 관측은 [observations-final/summary.json](../../validation/machining-2026-09-19/observations-final/summary.json)에 12개를 저장했다. [최종 엔진 소스](../../validation/machining-2026-09-19/engine-source-final/manifest.json)의 코드 SHA는 `2d668f2a637e9338356acae7f5fa3c7338faedb723a1200f0705d39003af6d86`이며 CAD 측정과 UI를 포함한다. 앞선 `observations/`의 다른 코드 SHA는 UI 수정 전 기록으로 보존한다.

재현 명령:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m pytest tests_v3 tests -q
.\.venv\Scripts\python.exe -X utf8 verify_legacy.py
.\.venv\Scripts\python.exe -X utf8 scripts/verify_geometry_inventory.py
.\.venv\Scripts\python.exe -X utf8 scripts/verify_machining_examples.py --out validation/new-machining-observations
```

관측 저장 스크립트는 새 출력 폴더만 허용하고 원본 SHA를 확인한다. 가상 공구 조건 D4/날10/도달15 mm로 각 형상의 결과와 기대값을 저장한다. 이 저장 자체가 독립 검증 통과를 선언하지 않으며, 수치 assert는 별도 tests가 수행한다.

## 남은 일

다음 기능은 임의 형상의 확대된 특징 인식, 유한 공구·샤프트·홀더의 접근 조건 및 독립 CAM 대조, 두 공정의 더 일관된 방향·수정 전후 비교다. 공통 AI는 실제 구조화된 결과와 문헌을 사용하도록 연결하고 템플릿 대비 평가한다. 사출·프레스는 각각 하위 공정·필요 입력·지원 범위·독립 반례를 정해 실제 기능으로 구현해야 한다. 제조 성공 확률과 연구 기여는 아직 미입증이다.
