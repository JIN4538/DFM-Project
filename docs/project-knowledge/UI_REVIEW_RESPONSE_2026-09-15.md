# UI 검토의 타당성 판단과 반영

사용자가 제공한 외부 AI의 UI 검토는 **주요 시각화 문제를 올바르게 지적했다.** 측정 방법과 한계 설명이 있어도 그림이 위치·비교 대상을 잘못 전달하면 사용자는 판단하기 어렵다. 이번 수정은 측정 규칙을 바꾸는 작업이 아니라, 기록된 결과를 사용자가 이해하고 다음 작업으로 옮길 수 있도록 표시·조작을 개선하는 작업이다.

원보고서는 `ae2a868`을 대상으로 작성됐다. 이번 작업의 시작 상태는 `1322780`이며, 그 사이에 이미 반영된 개선은 다시 미구현으로 취급하지 않았다. [원본 보고서와 4개 이미지](../../validation/v3/ui-review-20260915/input/), [입력 SHA와 같은 결과의 HTML 전후 비교](../../validation/v3/ui-review-20260915/report-comparison.json)를 보존한다. 문서에 적힌 제안은 검토 대상으로 읽었으며 자동으로 실행 지시로 취급하지 않았다.

## 사용자 관점에서 달라진 흐름

1. 파일의 크기를 확인하고 설계 검토를 시작한다. 작은 유효 부품은 벽 표본도 함께 확인한다.
2. 첫 카드의 **관측한 내용과 다음 행동**을 읽는다. 장비 기준이 없으면 측정값은 보여주되 임의로 적합 판정을 내리지 않는다.
3. 벽에서는 실제 점과 값을 고르고, 방향에서는 현재와 후보를 비교하고, 단면에서는 모양과 높이를 함께 본다. 색 외에도 도형·선 모양·숫자를 사용한다.
4. 세부 설정은 필요할 때 펼친다. 전체 요약의 다음 행동 버튼을 통해 다른 항목으로 이동한다.
5. HTML은 그림과 결론을 전달하는 용도로, JSON은 전체 원자료와 재현 조건을 보존하는 용도로 함께 저장한다.

3D 그림을 스크롤하다 뜻하지 않게 축소되는 동작도 관찰해 휠 확대를 껐다. 확대는 그림의 Zoom 도구로 한다. 드래그 회전과 툴바 조작은 유지한다.

## 설계 근거와 검증

색상만으로 선택·상태를 구분하지 않는 설계는 [W3C WCAG 2.2 — Use of Color](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)의 원칙을 따른다. 축의 같은 배율과 빈 영역 문제는 [Plotly 공식 축 문서](https://plotly.com/python/axes/)의 `scaleanchor`, `constrain='domain'` 동작에 근거한다. Streamlit 1.63에 포함된 레이아웃·위젯·세션 상태 문서도 확인했다. 앞서 조사한 [상용 도구의 공식 사용자 흐름](USER_WORKFLOW_RESEARCH_2026-09-15.md)을 유지하면서 불필요한 상단 반복을 줄였다. 이 근거가 앱 전체의 접근성 인증이나 사용자 만족도 검증을 뜻하지는 않는다.

브래킷 +Z, 기본 MEX 프로필, 벽 24표본·형상 변화 단면 4개·층간 200층을 **동일한 결과 객체**로 전후 HTML에 넣었다. 기준 `1322780` HTML은 693,328바이트·685,590자, `<pre>` 12개·671,709자·그림 0개였다. 개선 HTML은 33,192바이트·25,916자, `<pre>` 1개·1,679자·SVG 2개였다. 약 95.2%의 바이트 감소이며, 원보고서의 “16 KB가 된다”는 예측값을 실측 결과로 사용하지 않았다. 전체 JSON은 표시 과정에서 변경되지 않았다. [HTML 예시](../../validation/v3/ui-review-20260915/AM-DFM_review.html)와 [그 결과 JSON](../../validation/v3/ui-review-20260915/AM-DFM_review.json)을 함께 보존한다.

1366×768 브라우저에서 벽 실행 버튼의 상단은 약 370 px, 단면 실행 버튼은 약 425 px였다. 단면 X 범위는 브래킷 실제 −20~20 mm에 여백을 둔 −22.4~22.4 mm이며 같은 배율을 유지한다. 현재 +Z와 비교 +Y의 높이 40→30 mm, 측정점·선택점 구분, 두 단면 윤곽, HTML 실제 그림을 확인했다. [벽](../../validation/v3/ui-review-20260915/wall-after.png), [방향](../../validation/v3/ui-review-20260915/orientation-after.png), [단면](../../validation/v3/ui-review-20260915/sections-after.png), [보고서](../../validation/v3/ui-review-20260915/report-section-after.png) 캡처를 남겼다. 이 위치 수치는 해당 화면 조건의 관찰이며 모든 화면 크기의 보장은 아니다.

새 검사는 실제 24개 표본의 4~40 mm 차이와 좌표 변환, 기준 1/5 mm 구분, 무관한 형상의 보고서 혼합 차단, 미확정 단면의 0 표시·인접 연결 금지, 현재·추천·직접 선택·적용 상태를 대조한다. 최초 집중 검사에서 중복 Plotly ID와 표본 선택의 변수 충돌을 발견해 고쳤다. 다음 집중 검사 48개는 통과했다. 전체 검사에서는 하단으로 옮긴 전체 요약의 이동 버튼 누락과 공간 초과 시 다음 행동 누락을 발견해 복구했다. 최초 실패 로그도 보존하고 최종 결과와 구분한다.

최종 Windows Python 3.12.14·3.13.15에서 각각 **전체 666개 검사**가 통과했다. 기존 기본 수치 검증은 각각 55/55, 의존성 검사도 통과했다. 기존 겹침 반례의 trimesh 경고 1건은 남아 있고 해당 검사는 통과했다. 테스트 형상 106개 경로·100개 고유 SHA를 확인했고 원본 24개 Git blob을 보존했다. [통합 검증 기록](../../validation/v3/ui-review-20260915/integration.json)에 최초 실패·최종 통과 로그와 코드 식별자를 구분한다. 보고서 예시는 마지막 이동 버튼 복구·소스 줄바꿈 정리 이전의 표시 코드 SHA를 그대로 보존한다. 실물 출력이나 초보자 대상 사용성 실험은 이번 작업에서 수행하지 않았다. 일부 점을 측정한 결과를 전체 최소 두께·제작 성공으로 확대하지 않는 제한은 그대로다.
