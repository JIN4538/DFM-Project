# 내부 규칙 학습과 결론 중심 화면 · 2026-09-29

상태: 구현·학습·관련 검사·바탕화면 배치를 완료했다. 실행별 수치와 버전은 아래 기록 및 `validation/learned-review-2026-09-29/`의 원본 로그를 따른다.

## 사용자 목표와 범위

현재 문헌과 구현 규칙에 기반하여 형상의 문제를 찾고 개선 조치를 제안하는 AI를 실제 학습한다. 장비 유무를 개발의 차단 조건으로 삼지 않는다. AM 4개 공정과 현재 CNC 범위를 유지한다. 사용자 화면은 짧은 결론·핵심 수치·조치·위치를 우선하고, 방법과 범위는 접힌 상세로 옮긴다. 기존 실물 제조 성공률 예측 논의는 이번 목표가 아니다.

## 구조

- 학습: 형상 측정값과 명시적 수치 조건을 입력으로, 현재 규칙에 따른 문제·조치 종류를 정답으로 사용한다. 결과 상태·문장·정답 ID를 입력 특징에 넣지 않는다.
- 실행: 학습한 모델을 JSON으로 내장하고 PC에서 추론한다. 외부 AI 서비스와 학습용 패키지가 실행 시 필수이지 않다.
- 확인: 모델의 예측과 수치 비교를 대조한다. 불일치·지원 범위 밖 입력·누락은 별도 상태로 기록한다. 규칙 대체 결과를 모델 적중으로 세지 않는다.
- 표시: `dfm/learned_view.py`는 결론·수치·조치 카드를, `dfm/learned_output.py`는 HTML의 요약과 전체 식별 기록을 제공한다.
- 재현: 계산 코드 SHA에 `data/models/**/*.json`을 포함하여 모델 교체 시 이전 캐시가 재사용되지 않게 한다. 훈련용 환경은 `requirements-training.txt`, 실행용 환경은 기존 `requirements.txt`로 구분한다.

## 선택 근거

첫 후보는 숫자 조건의 분류를 다루는 의사결정나무와 나무 앙상블이다. 단순 모델과 더 큰 모델을 실제 보류 사례로 비교하고 결과에 따라 선택한다. 모델 종류가 복잡하다는 이유만으로 우수하다고 판단하지 않는다.

- [scikit-learn 1.9.1 Decision Trees](https://scikit-learn.org/stable/modules/tree.html): 지도학습·다중 출력·과적합과 외삽 한계. 2026-09-29 확인.
- [scikit-learn Group cross-validation](https://scikit-learn.org/stable/modules/cross_validation.html#group-k-fold): 같은 그룹이 훈련과 시험에 섞이지 않게 하는 평가 설계.
- [TabArena, NeurIPS 2025](https://arxiv.org/abs/2506.16791): 데이터와 검증 방법·학습 예산에 따른 모델 비교의 필요성. 이 문헌의 벤치마크 성능을 본 DFM 모델 성능으로 옮겨 쓰지 않는다.

형상 측정과 설계 규칙의 문헌 근거는 기존 `amdfm/evidence.py`, `dfm/machining.py`, 조건 DB 및 2026-09-21 원문 대조를 따른다. 이번 지도학습 정책·표본 분포·UI 우선순위는 개발 선택이며 표준 규정으로 서술하지 않는다.

## 검증 구분

1. 학습하지 않은 수치 사례와 경계 사례에서 원래 규칙과의 일치도.
2. 학습에 넣지 않은 실제 STEP 형상을 현재 엔진으로 측정한 뒤의 연결·문제 누락·조치 검사.
3. 결측·부분·미지원 입력, 모델 손상·버전 변경의 대체 경로.
4. 기존 회귀검사와 실제 바탕화면 실행 환경·브라우저 확인.

## 완료 기록

### 학습·모델 선택

11개 항목별 지도학습 분류기를 만들었다. 학습 55,000건, 선택용 검증 11,000건에서 깊이 제한 의사결정나무와 24개 나무의 랜덤포리스트를 비교했다. 동일한 검증 성능에서는 작은 모델을 선택하여 최종 11개 모두 의사결정나무가 선택됐다. 내장 파일은 약 8KB의 JSON이며 pickle이나 임의 코드를 실행하지 않는다. 모델·특징 스키마·현재 교사 코드의 SHA가 맞지 않으면 규칙 결과로 전환한다.

입력은 벽 표본 거리, 면적, 배치 치수, 원통 지름·축, 포켓 폭·벽 높이, 공구 조건 및 접근 표본이다. 문제 상태·조치 정답·설명 문장을 특징으로 넣지 않는다. 모델은 문제와 조치 종류를 예측하고, 한국어 문장과 현재 치수는 검증된 서식으로 작성한다. CAD 특징 추출과 방향 추천 정책은 기존 기하 엔진이 담당한다. 사용자 중점은 지원하는 항목의 표시 순서와 기존 방향 비교 정책에 연결된다.

### 수치 검증 해석

`training-001`부터 `training-005`는 개발 기록이다. 초기 기준 부근의 float32 손실을 발견하여 연속적인 수치 여유의 asinh 변환과 경계 표본을 추가했다. 이때 본 경계 사례를 독립적인 최종 시험이라고 재사용하지 않았다. 구현을 고정한 뒤 새 난수 시드 `2909202606`으로 `training-final-006`을 생성했다.

|---|---:|---:|
| 일반 사례 | 16,500 / 16,500 | 16,488 |
| 기준 부근 사례 | 5,500 / 5,500 | 5,500 |
| 큰 크기 범위 사례 | 5,500 / 5,500 | 4,696 |

이 숫자는 합성한 **수치 규칙·조치 일치도**다. CAD 인식 정확도나 모든 임계값에서의 정확도를 뜻하지 않는다. 독립 난수 사례에도 같은 원시 수치가 반복될 수 있다. 범위 밖 816건에는 실행 모델을 적용하지 않고 규칙을 사용한다. JSON 내보내기와 학습 라이브러리의 범위 내 추론 불일치는 없었다.

추가로 학습 후 실시한 `numeric-nextafter-stress.json`은 9개 크기에서 인접한 부동소수점 수 36건을 대조한다. **원시 모델 13건 불일치**, 규칙 대조 후 확인된 문제를 잘못 지운 사례는 0건이었다. 이 결과를 보존하며 모델 출력만으로 기존 규칙을 대체하지 않는다. 규칙 대체 결과를 모델 적중으로 합산하지 않는다.
