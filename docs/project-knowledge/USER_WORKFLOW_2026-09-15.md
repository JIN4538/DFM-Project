# 프로그램 전반의 사용자 중심 결과 개편

## 변경 이유

사용자는 벽 최솟값 4 mm, 층간 후보 면적 0, 계산 상태 complete를 보고도 적합 여부와 다음 행동을 알기 어렵다고 지적했다. 단면 화면만 개선한 이전 변경을 넘어 입력부터 보고서까지 검토 흐름을 개편했다. 교수님의 기능 구현 이유·사용자 편의성 피드백을 따라 수치의 존재보다 **설계 판단과 다음 행동에 필요한 정보**를 우선한다.

공식 Netfabb·Prusa·Materialise 문서에서 확인한 조건·형상·조치 연결 방식과 이번 구현의 추론은 [별도 조사](USER_WORKFLOW_RESEARCH_2026-09-15.md)에 기록했다. 타사 UI를 근거로 제조 임계값이나 해석 정확도를 정하지 않았다. 이번에는 새 제조 한계나 공정 물리 모델을 추가하지 않았다.

## 실제 바뀐 행동

- **시작:** 형상 옆 실행 버튼, 입력·크기·공정 확인 순서와 첫 사용자 안내를 제공한다.
- **종합 판단:** 우선 조치 개수 0 대신 확인할 후보와 미입력 기준·미실행 검사를 구분하고, 가장 먼저 할 일로 바로 이동한다. 세부 화면에서는 종합 안내를 접어서 검사 질문과 결과를 우선 보여준다.
- **설계 조치:** 선택 항목의 판단·관측·다음 행동과 3D 위치를 연결한다. 전체 검토 상태를 한 표에서 확인할 수 있다. 새 결과를 만든 뒤에도 바로가기에서 선택한 항목을 기본 강조 항목으로 덮지 않는다.
- **방향 비교:** 높이 감소, 공정에 적용되는 하향면 후보 감소, MEX의 평평한 바닥 증가 중 목적을 선택한다. 해당 지표로 후보를 정렬하고 현재 대비 증감과 배치 미리보기를 제공한다. 모든 후보가 지정 공간을 초과하면 이를 먼저 알린다. 복잡한 전체 표는 펼침 영역에 보존한다.
- **정밀 검토:** 벽·층간·단면 중 답을 얻으려는 질문을 먼저 선택한다. 긴 단면 결과 아래에서 다른 검사 버튼을 찾을 필요가 없다.
- **벽:** 측정값과 사용자 기준을 나란히 제시한다. 기준 미입력·기준 미만 관측·표본 내 기준 충족·부분 측정을 구분한다. 같은 화면에서 벽 기준을 입력하고 새 프로필로 재검토한다. 주황색은 기준 미만 후보가 없을 때에도 가장 짧은 표본 위치임을 설명한다. p05·표본 수·좌표는 상세로 옮긴다.
- **층간:** 요청 층·윤곽·세 지표의 계산 범위를 모두 확인한 경우에만 모든 후보 없음으로 요약한다. 확인할 층을 먼저 표시하고 높이를 선택하면 기록된 위치 경계 상자를 3D 형상에 표시한다. 경계 상자는 실제 결함 윤곽으로 설명하지 않는다. 전체 0 그래프를 생략하고 원시 전체 표는 접는다. 미확정과 일부 범위, 작은 양수는 보존한다.
- **단면:** 이전의 두 단면 겹침과 계산 검산 설명을 유지하고 질문별 화면 안에 배치한다.
- **G-code:** 현재 모델과 파일·방향·배율을 맞춰야 함을 안내하고, 읽기 일부 완료와 연습용 실험 경로를 구분한다.
- **수정 전후:** 같은 형상은 수정 파일을 선택하도록 안내하고, 비교 조건이 다르면 맞춰야 할 조건을 설명한다.
- **내보내기:** HTML은 사람에게 공유, 방향 STL은 슬라이서 전달, JSON은 전체 기록 보관, STEP 원본은 CAD 수정이라는 용도를 안내한다. HTML도 같은 순수 해석 함수를 사용해 화면과 판단을 맞추고 원자료는 접어서 보존한다.

## 구조와 보존 계약

`amdfm/detail_summary.py`는 벽·층간 해석, `amdfm/workflow.py`는 항목별 상태·다음 행동·명시 목적 정렬, `amdfm/detail_view.py`는 상세 화면을 담당한다. `presentation.py`의 보고서는 같은 해석을 호출한다. 수치 측정은 기존 엔진이 담당하고 보고서 원자료를 변경하지 않는다.

기준 미달 후보가 없는 부분 결과를 전체 정상으로 요약하지 않는다. 층간의 `complete`만 신뢰하지 않고 요청 수·실행 수·행 순서·높이·윤곽·세 지표의 `*_full_scope`를 확인한다. 후보 위치는 기존 `bounds_mm`와 빌드 높이만 사용하며 중복 배치 변환을 하지 않는다. 읽을 수 없는 위치를 임의로 만들지 않는다. 표의 1부터 시작하는 층 번호는 화면용이며 JSON의 원래 인덱스는 유지한다.

벽 기준 변경은 새 프로필로 빠른 검토와 벽 검토를 다시 실행한다. 이전 프로필의 다른 정밀 결과는 새 결과로 재사용하지 않는다. 공정별 기준 입력 상태를 섞지 않는다. 기능별 정상·미확정은 기하 검사 범위이며 출력 승인 등급이 아니다.

기존 `analysis.py`, `detail.py`, `detail_worker.py`, `cross_sections.py`, `event_sections.py`, `orientation.py`, `src/core/`의 수치 알고리즘은 변경하지 않았다. 새 표시 모듈과 보고서 코드 때문에 코드 식별자는 변경된다. 과거 실형상 감사 수치는 당시 코드 식별자와 원자료로 보존한다.

## 검증

첫 전체 회귀검사는 Windows Python 3.12.14 및 3.13.15에서 각각 607개를 통과했다. 기존 `verify_legacy.py`도 두 환경에서 각각 55/55, 의존성 검사는 오류 없이 통과했다. 이후 독립 검토에서 발견한 바로가기 선택 덮임, 모든 방향 공간 초과 안내, 공정별 보고서 안내와 버튼명 불일치를 수정하고 **최종 전체 609개를 두 환경에서 각각 통과**했다. 소요 시간은 3.12에서 216.23초, 3.13에서 226.13초다. 최종 실행 결과·코드 식별자·변경되지 않은 수치 모듈 20개의 SHA와 원본 로그는 [검증 기록](../../validation/v3/user-workflow-20260915/summary.json)에 보관한다. 퇴화 메시 반례에서 기존 trimesh 체적 나눗셈 경고 1개가 발생했고 해당 검사는 통과했다.

새 검사는 기준 없는 4 mm 벽, 기준 1 mm와 5 mm, 누락 표본, 200층 전체 0, None·행 누락·부분 비교 범위, 1e-18 양수 후보, 실제 박스 측정, 경계 상자 좌표, 미지원 공정, HTML 삽입 방지, 프로필 변경 후 재계산·내보내기·바로가기를 포함한다. 개발 중 일부 테스트는 기대한 버튼/층 표기와 실제 문구의 불일치로 실패했으며 표현을 실제 계약에 맞춰 바로잡았다. 실패가 있었던 실행 로그를 최종 성공 기록으로 대체하지 않는다.

실제 브라우저에서는 브래킷의 첫 판단·벽 기준 입력·층간 요약·선택 강조·전체 수치 접힘을 확인한다. 이는 구현자의 화면 검증이며 별도의 일반 사용자 관찰 실험 결과라고 주장하지 않는다.

## 남은 범위

기준 출처·프린터·재료는 사용자가 지정해야 한다. 현재 장비 미확정 상태를 임의 장비 기준으로 대체하지 않는다. 벽의 법선 거리 표본은 전체 최소 두께 보증이 아니며 층간 후보는 실제 슬라이서 경로나 물리적 실패가 아니다. 공정 물리와 실물 출력 검증의 기존 미완료 범위는 유지한다. 사용자가 바로 판단할 수 있도록 해당 검사 범위 안에서는 후보 없음·기준 비교 결과를 분명하게 표현한다.

사용 방법은 [첫 사용자 안내](../USER_GUIDE_V3.md)에 별도로 정리했다.
