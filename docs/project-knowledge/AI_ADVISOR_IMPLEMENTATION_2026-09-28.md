# 2026-09-28 사용자 요구 연결과 AI 1차 도입

사용자 요구: 초보자가 문제 위치와 개선 방향을 직관적으로 찾도록 다시 개선하고, 장비·설계 중점 입력을 실제 검사와 추천에 연결하는 실용적인 AI를 도입한다. 적층·절삭만 지원하며 사출·프레스는 추가하지 않는다.

## 변경한 기능

- `dfm/advisor.py`: 명시적 검토 의도, 실제 조건 DB 이름 검색, 공정별 반영 설명, 조치 우선순위. 이름 일치는 조건 적합성 인증이 아니다. 입력 장애·빌드 제약과 관측 후보/미확인 구분 유지.
- `dfm/ai_client.py`: OpenAI Responses API 구조화 추출. 입력 문장만 전송, `text.format=json_schema`, `store:false`, 무자동재시도. 키/오류 원문/응답 원문은 보고서에 넣지 않는다. 자유 문자열은 입력의 실제 부분문자열인지 검증한다. enum 해석 자체는 모델 오류 가능성이 있어 적용 전 확인한다.
- `dfm/advisor_view.py`: 직접 조건 입력, 관련 자료와 적용값 확인, 선택적 AI 연결→해석 미리보기→조건 반영. 숫자를 AI에서 직접 엔진으로 넣는 통로는 없다. 적층 장비·재료 변경 시 이전 기준값이 새 장비에 남는 반례를 수정했다.
- `amdfm/recommendation.py`: `review_context.priority` 반영. 지원되는 기하 목표만 3배 선호 비중으로 비교. 입력 없음/균형은 기존 순위를 유지한다. 지원하지 않는 강도·비용 등은 방향 점수에 반영하지 않고 사유를 표시한다. 정책 버전 `preference-geometric-regret/2`.
- AM/CNC 검토 UI: 첫 화면 입력, 조치 카드에 관측·할 일·위치 연결, 결과와 HTML/JSON에 검토 의도 기록. 불필요하게 크게 보이던 부피 등은 접어 둔 요약으로 이동. CNC 시작 버튼을 본문에도 추가.

## 근거와 설계 판단

기존 문헌 기반 측정법·기준값을 새로 추정하지 않는다. 변경한 가중치 3배는 사용자가 고른 선호를 반영하기 위한 개발 정책이며 제조 실험이나 표준에서 얻은 계수가 아니다. 방향의 현재값/후보값과 불리해지는 항목은 유지한다. 고정 후보 기준 정규화·현재 방향과 동등하면 유지·unknown 차단을 유지한다.

AI 인터페이스는 다음 공식 문서를 확인해 구현했다(2026-09-28).

- [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs): JSON 스키마 구조화, refusal/incomplete 처리. 스키마 일치가 내용의 정확성을 보장하지 않는다.
- [Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create): 응답 생성 구조와 `store`.
- [GPT-4.1 mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini): 선택한 기본 모델의 Responses·구조화 출력 지원. 사용자 계정 권한은 별도다.

## 실제로 검증할 범위와 한계

API 프로토콜 모의 응답 시험은 실제 모델의 의미 이해 성능을 검증하지 않는다. API 키가 없으므로 현재 실제 호출은 수행하지 않았다. 조건 검색과 의도 반영은 오프라인에서도 사용할 수 있다. 한국어 긍정·부정·상충 요청·알 수 없는 장비의 실제 모델 평가는 별도 사례집으로 준비한다.

사용자의 원본 파일과 기존 로그는 보존한다. 전체 회귀 1,178개 통과 후 마지막 안내·기본 강조 상태 수정을 관련 검사 57개와 실제 AM/CNC 초점 반례 2개로 재검증했다. 이 수를 합산한 전체 일괄 검사로 설명하지 않는다. 코드 SHA, 실행 기록과 바탕화면 배치는 [검증 기록](../../validation/ai-advisor-2026-09-28/README.md)의 최종 상태를 따른다.
