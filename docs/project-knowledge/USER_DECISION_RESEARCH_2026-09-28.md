# 사용자가 바로 결정할 수 있는 검토 흐름

조사일: 2026-09-28. 사용자 요청은 기본 검토 뒤 정밀 검토를 다시 눌러야 하는 부담과, 목적마다 달라지는 방향 후보를 직접 판단해야 하는 부담을 줄이는 것이다. 이 문서는 현행 코드의 독립 UX 감사와 공식 제품 문서에서 확인한 설계 근거다. 실제 구현·검증 완료 범위는 이번 변경 기록과 검사 로그를 따른다.

## 문제의 원인

수치 설명을 늘리는 것만으로 해결되지 않는다. 사용자는 **무엇이 문제인지, 어디인지, 무엇을 바꾸면 되는지**를 한 화면에서 보고 싶다. 기존 앱은 측정·요약·방향 선택·추가 계산을 별도 화면에 두어 마지막 해석을 사용자에게 맡기고 있었다.

| 감사 시작 시 코드 | 사용자에게 생기는 문제 | 바꿀 구조 |
|---|---|---|
| `app.py` 기본 검토는 제한된 벽 검사만 추가; 층간 검토는 별도 버튼 | 첫 결과에 계산 가능한 문제도 나타나지 않고 다시 실행해야 함 | 한 번 실행에서 예산 내 핵심 검사까지 수행하고, 미완료 범위와 재시도만 상세 화면에 둔다. |
| `workflow.ranked_orientations`는 선택한 지표 하나로 정렬 | 높이·하향면·바닥 중 사용자가 우선순위부터 결정해야 함 | 기본 화면에 공정별 공개된 정책으로 고른 종합 추천 1개, 개선·악화 수치와 적용 버튼을 둔다. 목적별 비교는 상세 선택으로 남긴다. |
| 방향 비교 선택은 결과 시각과 목적이 달라지면 첫 후보로 초기화 | 재검토할 때 추천이 뒤집히는 듯 보임 | 같은 형상·조건·후보 집합이면 같은 추천을 유지한다. 현재 방향은 비교 기준이며 순위 기준으로 쓰지 않는다. |
| `workflow.summarize_review`의 warning에는 수정 후보와 계산 실패가 함께 포함 | 실제 문제 수와 모르는 항목 수를 혼동 | 관측된 수정 후보, 필요한 입력, 계산 미확인을 분리한다. |
| 층간 결과는 checklist에만 추가되고 `report.findings` 선택에는 없음 | 처음 보는 결과 화면에서 층 문제 위치를 찾을 수 없음 | 요약에서 해당 높이·후보 종류·그림으로 바로 이동하거나 바로 표시한다. |
| 절삭은 표면 가림 검사가 기본 꺼짐; 수정 후보는 항목명으로만 요약 | 실행 뒤 추가 검토와 치수 해석을 다시 해야 함 | 안전 예산 내 표본 검사를 기본 실행하고, 실제 형상 치수와 공구 치수·조치·위치 버튼을 먼저 표시한다. |

## 공식 제품 문서에서 확인한 구조

아래 자료는 화면 구조를 설계하는 근거다. 타사와 같은 계산 정확도, 특정 임계값·가중치의 타당성 또는 실제 제조 성공을 확보했다는 근거가 아니다. 웹 원문은 조사일에 확인했으며, 제품 버전과 문서 범위를 함께 기록한다.

1. **Autodesk Netfabb 2025 — Part analysis reference**
   - 공식 문서: <https://help.autodesk.com/cloudhelp/2025/ENU/NETF/files/GUID-320E31A8-80A9-4A82-B4F3-070334B1675A.htm>
   - 확인 범위: Upskin/downskin, Wall thickness, Support volume 절.
   - 분석 위치를 색으로 표시하면서 각도·면적·영역 수를 문자로 함께 제공한다. 벽 색은 입력 기준과 비교한 의미를 갖는다. 빠른 벽 검사 중단은 나머지 위치가 미완료일 수 있음을 구분한다. 서포트 아래를 꽉 찬 블록으로 계산한 값과 실제 생성 서포트량도 구분한다.
   - 적용 판단: 문제 위치와 수치·조건을 같은 화면에 묶는다. 표본 계산을 면 전체의 확정 결과로 칠하지 않는다. 계산 시간 제한을 없애는 대신, 계산한 범위와 남은 범위를 보존한다.

2. **Materialise Magics — Optimize Part Orientation 공식 튜토리얼**
   - 공식 문서: <https://www.materialise.com/en/academy/industrial/magics/video-tutorials/optimize-part-orientation>
   - 확인 범위: Analyzing part data, Optimizing orientation, Orientation Comparator 안내. 영상 전체를 시청한 기록은 아니며 페이지의 텍스트 지침을 확인했다.
   - 현재 지표와 분석 위치를 먼저 보고, 관련 기준을 선택해 최적화한 뒤 실제 방향에 적용한다. 비교 표는 각 지표의 개선·악화를 구분한다. 해당 문서는 서포트 면과 최대 XY 단면적 사이의 균형도 예로 든다.
   - 적용 판단: 추천을 설명하는 지표와 추천 방향의 그림·적용 동작을 연결한다. 기본 정책을 소프트웨어가 제시할 수 있지만 모든 사용 목적의 유일한 최적이라고 표현하지 않는다. 문서에 없는 가중치를 표준 또는 제조사 인증 값으로 제시하지 않는다.

3. **Autodesk Fusion — Analysis tools**
   - 공식 문서: <https://help.autodesk.com/view/fusion360/ENU/?contextId=SLD-INSPECT-TOOLS>
   - 확인 범위: Accessibility Analysis, Minimum Radius Analysis 절.
   - 선택 방향에서 보이는 영역과 가려진 영역을 구분하고, 오목면 곡률을 최소 반경과 비교해 위치를 표시한다.
   - 적용 판단: CNC에서도 측정 위치와 공구 치수 비교를 직접 연결한다. 현재 구현은 제한된 표본의 직선 가림이며 유한 공구·홀더의 전체 경로 충돌 검사로 확대하지 않는다. 반경 비교와 지름 비교는 명시적으로 나눈다.

## 이번 CNC 화면 반영

- `dfm/machining_view.py`의 `machining_decisions`는 원래 finding과 원자료를 바꾸지 않고 관측된 후보, 판단 보류 항목, 필요한 공구 입력을 분리한다.
- 우선 최대 3개의 후보 카드에서 형상 치수와 공구 치수, 기존 조건부 개선 제안, ‘이 위치 보기’를 표시한다. 첫 측정면이 아닌 실제 비교 문제가 있는 행을 우선 선택한다. 카드에 없는 추가 후보는 기존 항목 선택으로 볼 수 있다.
- 위치 그림을 치수 원자료 표보다 먼저 배치한다. 원자료·출처·조건 DB와 미입력 값은 유지한다. HTML 보고서에도 같은 우선 조치를 포함한다.
- 가림 검사는 기본 선택하되 사용자가 해제할 수 있다. 기존 `run_point_visibility`의 **최대 512개 표본, 200,000면, 20,000,000 ray-triangle tests, 10초 자식 프로세스 제한**을 유지한다. 이 숫자는 계산 예산이며 제조 성능이나 정확도 보증값이 아니다.
- 날 길이보다 포켓 벽이 높아도 분할 절입·목부 공구의 가능성이 있으므로 단순히 긴 공구가 정답이라고 안내하지 않는다. 공구·홀더·진입/복귀·고정·공차·절삭력·품질은 미검토 범위로 남긴다.

## 받아들일 수 있는 종합 추천의 조건

1. 같은 형상·공정·설정·후보 집합에서는 현재 표시 방향을 바꾸어도 추천이 반복해서 흔들리지 않아야 한다.
2. 입력한 빌드 공간을 초과하는 후보와 계산 핵심 값이 빠진 후보를 정상 후보처럼 추천하지 않는다. 모든 후보가 부적합 또는 미확정이면 그 이유와 다음 입력을 제시한다.
3. 공정에 적용되지 않는 지표를 0점·좋음으로 더하지 않는다. 고분자 PBF에 MEX의 접착면 목표를 동일하게 적용하지 않는다.
4. 추천 문구는 ‘검토한 방향·기하 지표에서의 종합 제안’ 범위여야 한다. 장비·재료·하중·열변형·지지 생성·제작 비용·실제 성공 확률의 최적을 함께 증명했다고 하지 않는다.
5. 추천을 적용한 뒤 자동 핵심 검토를 실행하여 추천 화면의 수치와 실제 적용 결과를 연결한다. 세부 반례와 미확정도 결과 화면에 남긴다.

사출·프레스는 사용자 지시에 따라 이번 조사·구현 범위에서 제외한다.
