# 전체 개발 변경 정리와 GitHub 공개

사용자 요청: 지금까지 작업한 파일의 원격 반영 여부를 확인하고, 미반영 파일을 용도별로 커밋·푸시하며 연구 주제를 제안한다.

## 공개 전 상태

2026-10-01 원격 갱신 후 로컬 `codex/am-dfm-evidence-review`와 원격 같은 브랜치는 `d8d1ab0`에서 일치했다. 그 이후 작업은 변경·미추적 파일 1,473개, 217,626,434바이트로 작업 트리에 있었으며 아직 커밋/푸시되지 않았다. `main`은 별도 원본 이력이고 이번 공개 대상은 기존 개발 브랜치다. 이후 작성한 공개 기록·연구 제안·아카이브는 위 최초 수에 포함되지 않는다.

## 파일 용도와 커밋 순서

| 분류 | 경로 | 보관하는 내용 |
|---|---|---|
| 조건·학습 모델·데이터 색인 | `data/conditions`, `data/models`, `data/training` | 출처가 있는 조건 라이브러리, 배포/연구 모델과 매니페스트, 데이터 수·분할·SHA |
| 실제 프로그램 | `app.py`, `amdfm/`, `dfm/` | 적층·절삭 검토, 학습 추론, 결론·위치·추천, 기하 검산·지원 STEP 수정 |
| 사용자 시연 형상 | `examples/` | 공개 STEP 14개, 구멍·포켓·수정 전후 등 시연과 출처·SHA |
| 재현과 자동 검사 | `scripts/`, `tests_v3/` | 수집·반입·학습·선택·배포·독립 CAD 검사 및 회귀시험 |
| 실행 결과·개발 증거 | `validation/` | 시험·학습·대조·실패와 재시험·원본 동일성 확인, 독립 형상 |
| 사용·근거·연구 문서 | `docs/`, `README.md`, `AGENTS.md` | 사용 안내, 구현 이유·계약·평가·한계, 연구 주제, 인수 기록 |

커밋은 위 용도 순서로 나눈다. 중간 커밋에는 뒤 분류의 의존 파일이 아직 포함되지 않을 수 있으므로 실행·검증 기준은 전체 공개의 마지막 커밋이다. 이미 존재하던 Git 이력을 다시 쓰거나 `main`을 강제로 갱신하지 않는다.

## 저장소 밖 작업 기록

`scripts/archive_development_records.py`가 저장소 옆 `study/`의 2026-09-26·28·29·30 단계에서 개발 스크립트·배포 확인·시험 실패와 재실행·최종 화면·기준 형상을 원본 바이트로 복사했다. 원자료는 옮기거나 덮어쓰지 않았다.

보관 경로는 `validation/workspace-archive-2026-10-01/files/`이며 전체 대응은 `manifest.json`이다. 최초 반입은 **2,194개 파일·456,578,148바이트**, 같은 SHA의 저장소 파일 참조 **123개**다. 원형 분할·기울어진 구멍 및 수정 전후의 실제 화면도 포함한다. 서로 같은 파일의 여러 경로를 서로 다른 연구 표본으로 세지 않는다.

새 보관본 STEP 299개를 기존 형상 색인에 등록했다. 기존 입력 155개와 합쳐 전체 **454개 파일·448개 SHA**이며 앱 시연 선택 수와 구분한다. 최초 등록 전 무결성 검사 실패를 보존하고, 새 목록·출처와 일치를 재검사한다.

로컬 전용 파일 기록 43,301개는 외부 SQLite DB·다운로드 패키지·재생성 가능한 학습 배열과 개별 측정 캐시·프로세스 상태 등이 대부분이다. 실행환경·백업·원본 외부 패키지 디렉터리는 별도로 제외 사유를 기록했다. 공개하지 않은 DB를 GitHub에 올렸다고 표현하지 않는다. 현재 가중치와 모델 카탈로그는 저장소에 있으며, 대용량 입력에는 수집·반입·학습 스크립트와 출처를 제공한다. 외부 배포처 접근 거절이나 누락 원본은 과거 수집 기록 그대로 남기므로 다른 컴퓨터에서 모든 학습을 즉시 재현할 수 있다고 보장하지 않는다.

이 아카이브는 원래 study 경로를 사용한 과거 스크립트·절대경로의 증거 보관본이다. 저장소에서 실행할 현재 스크립트는 `scripts/`다. 과거 배포·실패 기록의 경로를 임의로 고치지 않는다. 비밀 설정·API 키·가상환경·설치 캐시는 Git 대상이 아니다.

## 데이터와 모델 해석

`data/training/full-corpus-catalog.json`의 적격 외부 기록은 120,178개(적층 42,295·절삭 77,883), 가중치 학습 기록은 84,513개다. 이는 파일/원본 기록의 집계이며 120,178종의 서로 다른 기계 설계나 전체 형상에 대한 정확도를 뜻하지 않는다. 후보·반복 에피소드·이후 새 조합 학습을 신규 외부 형상 수로 더하지 않는다.

`data/models/` JSON 34개에는 매니페스트·연구용 미채택 아티팩트가 포함된다. 이를 제품에서 독립적으로 사용한 AI 모델 34종으로 설명하지 않는다. 실제 채택·미채택·회귀 test 재사용과 독립 CAD 검사는 최신 단계 문서를 따른다. 최신 구멍 개선은 새 가중치 학습 0이며 기존 AI+CAD 검산 연결이다.

## 검증과 원격 확인

이번 전체 공개의 새 회귀시험은 `validation/publication-2026-10-01/`에 보관한다. 과거 시험 결과를 이번 전체 실행으로 대체하지 않는다. 최초 원자료와 공개 전 파일 SHA를 검사하고, 아카이브의 저장소 참조는 해시로 다시 확인한다. 공개 후 `git status`, 로컬 HEAD와 원격 같은 브랜치의 SHA, 앞섬/뒤처짐을 대조한다. 최종 결과는 해당 폴더의 실행 XML·배포 매니페스트와 Git 이력을 따른다.

Windows Python 3.12.14의 전체 1,649개 검사에서 1,647개 통과·2개 실패였다(1,019.14초). 실패는 보관 STEP의 색인 미등록과, 크기 확인을 끈 상태에서 숨겨진 입력을 찾던 이전 UI 검사다. 형상 색인을 등록하고 현재 입력 흐름에 맞게 검사한 뒤 관련 5개·11개가 통과했다. 새로운 출처 검사 1개를 포함해 최종 고유 개별 결과는 **1,650개 통과·남은 실패 0**이다. 전체 검사를 두 번째로 전부 실행했다고 표현하지 않는다. 원래 실패 XML·로그와 재검사 결과는 보존한다. 기존 해석 검증은 별도 **55/55**, 의존성 일관성 검사도 통과했다.

새로운 형상 보관 규모와 전체 회귀 실행 17분을 고려해 GitHub Actions의 제한 시간을 20분에서 45분으로 조정했다. Python 3.12·3.13 매트릭스와 기존 검사는 유지한다. 이번 로컬 전체 실행은 3.12이며 원격 3.13 전체 결과는 실제 Actions 상태로 확인해야 한다.

공개 전 파일 검사에서 100 MiB 이상 파일·인증키 패턴·아카이브 참조 불일치는 0이었다. 기존 최초 원자료 24개 중 사용자 지시로 교체한 KS PDF 4개를 제외하고 Git 정규화 내용이 일치하며, 텍스트 줄바꿈 차이와 원본 교체를 구분했다. PDF 교체 이전 바이트도 원래 Git 이력에 남아 있다.
