## 초기 v1 → 초기 v2 계열

초기에는 7개 규칙을 곧바로 가중 평균했다. 입력 메시의 유효성이나 장비 한계 위반이 종합 점수의 산출을 막지 못했다. 미구현 구멍 인식은 빈 목록을 반환했는데 규칙에서 100점을 부여했다. 최소 특징은 최단 메시 모서리라 테셀레이션의 영향을 직접 받았다.

주요 수정은 다음과 같다.

- 하향면의 각도를 `clip(90-θ,0,90)`으로 뭉개고 수직벽·바닥까지 오버행에 포함하던 계산을 수정. 수평 기준 경사 `180-θ`, 하향 법선, 플레이트 접촉 제외를 구분했다.
- 45° 하드코딩을 공정별 임계각 전달로 변경했다. SLS의 0 임계값 나눗셈 오류를 N/A 처리로 막았다.
- 벽두께를 정점 법선에서 면 중심·면 법선 레이로 변경. 평판에서 √3배 과대 측정하던 문제를 줄였다. 무작위 표본에서 결정론적 면적/특징 표본으로 옮겼다.
- 서포트를 단순 면적×바닥 높이×0.4에서 투영 면적과 첫 하부 표면 거리로 개선. 이후 부피·둘레의 2항 경험식으로 발전했다.
- 지정 빌드 방향을 +Z로 회전해 방향 의존 분석을 수행하고 3축에서 ±6축으로 확장했다.
- 단위 선택과 mm 변환, 입력 진단, 실제 불리언 합집합 샘플, 하드 게이트와 소프트 점수 분리, N/A 재정규화, 연속 점수, 민감도/AHP를 추가했다.
- UI에서 평가 당시 설정과 결과를 연결하고 Plotly 면 색상을 문자열로 바꿨다. 이후에도 세션·재평가 문제가 남아 추가 수정됐다.

초기 보고서의 직육면체 오버행 76.9%→0%, 평판 두께 오차 +73.2%→0%, 검증 6/14→55/55는 **당시 특정 시험의 결과**다. 모든 임의 STL의 정확도를 뜻하지 않는다. 검증의 세부 기대값 일부에는 현재 설명보다 강한 ‘인쇄 불가’ 표현이 남아 있다.

## v2.2: 원자료 보존과 재현 가능한 Cura 대조

근거: `validation/history_v22`와 `cura_records.py`, `validation_metrics.py`, `reproducibility.py`.

새 실험 폴더를 사용하고 기존 측정 CSV 덮어쓰기를 거부한다. 임시 폴더에서 성공한 실험만 게시한다. 실제 저장한 방향별 STL 바이트를 다시 읽어 예측·형상 항을 계산하며 STL·코드·프로필·단위·필라멘트·Cura 설정 식별자를 기록한다.

과거 저장 예측 분석과 현재 코드 재계산을 분리했다. 잘못된 행은 설명 없이 제외하지 않고 오류/미입력 사유를 남긴다. 동일 조건별로 회귀를 나누고, 교차검증 학습 행렬의 계수가 식별 불가능하면 전체 Q²를 내지 않는다. 규칙 집합이 다른 방향끼리 총점 1위를 선정하지 않는다.

과거 Cura 4형상×6방향=24조건의 저장 예측 R²=0.9784086106593225, 현재 형상 항에 고정 계수 적용 R²=0.978431909544024. 기존 계수 a=0.165·b=0.2715를 자동 변경하지 않았다. 시간 칸은 미입력이다. 지름 기록이 없어 1.75mm 가정을 표시한다. 현재 계산으로 과거의 미기록 설정까지 복원한 것은 아니다.

당시 검증: 55 + 65 = 120 항목. `d.csv`의 NIST 6행을 별도 독립 실험으로 더하지 않는다. 전체 원자료 29개 파일의 바이트 보존 기록이 있다.

## v2.3: 손상 메시의 부분 분석과 벽두께 근거

GB는 열린 경계가 0이어도 비다양체 모서리1,274개·퇴화면174개가 있었다. ‘닫힘’만으로 솔리드 유효성을 확정할 수 없다. 보수적 정리 뒤에도 비다양체1,142개·열린 경계12개가 남아 전체 점수는 계속 보류했다. 외곽 좌표 변화0은 완전 복구의 증거가 아니다.

`mesh_diagnostics.py`를 분리하고 문제 면 인덱스·원본/정리 후보·부분 치수 정보를 제공했다. 정확한 면적0 면과 같은 방향의 정확한 중복면만 제거하며 임의 구멍 메우기·작은 성분 삭제·공동 반전을 하지 않는다.

벽두께 게이트는 단순 하한 미만 표본2개에서 **후보 면 내부3점의 추가 근거**로 변경됐다. 반대 법선 코사인0.85, 비인접면, 공간 범위 하한/4, 최대128후보면 등은 공학적 휴리스틱이다. 의심 표본이 남고 확증되지 않으면 보류한다.

당시 검증: 55 + 90 = 145. 외부10형상의 원본·정리 후보20회는 독립20형상이 아니다. 실제 GB AppTest는 샘플 입력 훅으로 주입했으며 업로드 위젯·브라우저 픽셀·GPU 시험이 아니다.

## v2.4: 기존 3D 평가와 별도의 FDM 층 단면 경로

삼각형-평면 교차의 방향과 non-zero winding으로 각 층 재료를 해석한다. 입력 전체를 복구하지 않고도 확정할 수 있는 층을 검토한다. 층 중간 평면, 마지막 부분 층, 특이 꼭짓점 높이의 제한적 재시도와 실제 높이를 기록한다.

선폭 기준 morphological opening 잔여, 이전 층에서 지지되지 않는 영역, 인접 층에 없는 한 층 영역을 추가했다. 단면의 종합 점수는 만들지 않았다. 미확정 층을 위험 없음으로 바꾸지 않았으며 3D 게이트/점수와 별도 결과로 표시한다.

당시 검증: 55 + 125 = 180. GB·Benchy·Prusa14개, 총16개 원본과 정리 후보가 요청 층 계산을 마쳤다. GB212층 계산 완료와 3D 점수 미산출이 동시에 성립한다. 이는 처리 범위이며 실제 제조 정답률이 아니다.

## v2.5: 작은 세부 보존, 부분 성분, 성능

사용자 리뷰의 구 표면 잔여·많은 핀·손상 구+분리 박스·상쇄 껍질 사례를 검토했다. 원 리뷰의 실행 스크립트·삭제 면 목록이 없어 동일 수치를 완전히 재현했다고 주장하지 않았다.

- `0.01×선폭²`는 삭제 기준이 아니라 표시 정책. 작은 세부 면적과 수를 보존한다. 지름0.03mm 핀처럼 성분 전체가 소실되는 경우는 크기와 무관하게 검출한다.
- 2A/P를 ‘국소 폭’으로 부르지 않는다. 원에서는 반지름이다.
- STRtree 후보 조회, 단순 폐곡선 빠른 경로, 면 높이 인덱스, UI 단면 캐시를 추가했다. 최악의 이차 계산과 예산 한도는 남는다.
- 손상 범위와 겹치는 닫힌 성분도 보수적으로 제외한다. 열린 공동을 채우지 않는다. 다른 정상 성분은 부분 검토하되 전체 면적·부피의 분모는 미확정으로 둔다.
- 모든 재료가 상쇄되는 모델은 모든 위험 검사를 미확정으로 둔다. 실제 공기 층은 허용한다.

900핀 첫 층 판별 후보25,920,000→27,000. 하지만 종전 실패17.080초와 개선본 전체 계산24.315초는 같은 작업의 속도비가 아니다. 손상 구+박스의 전체 확정104/250=41.6%는 그대로이며 나머지146층에서 박스 부분 검토가 가능해졌다. 이를 전체 완료100%로 바꾸지 않는다.

당시 검증: 55 + 149 = 204. 구 한 사례1.36배 개선은 10~50배 일반 개선의 증거가 아니다.

## v2.6: 세 검사의 표시 의미 통일과 비용 보완

근거: v2.6 `REVIEW_KO.md`, `VALIDATION.md`, `CHANGES.patch`, 루트/내부의 v2.6 개선계획 MD.

작은 세부 정책을 얇은 특징뿐 아니라 지지·브리지와 한 층 영역에도 적용했다. 전체 후보 = 우선 검토 + 작은 세부를 보존한다. 전체 성분 해당 여부는 검사마다 정의가 다르다. 지지/한 층 검사는 인접 재료와의 면적 겹침이 없는 경우를 따져 선 접촉만으로 지지됐다고 하지 않는다.

외곽 크기·높이 투영을 재사용하고 `FaceZIndex` 실패의 None 경로를 방어했다. 앱 버전이 다른 과거 결과는 재평가하도록 했다. 단면 방법 식별자는 `fdm_layer_review_v3`, 앱은2.6이다.

NIST +Z에서 우선 지지 검토 층15→14, 한 층 검토61→0으로 바뀌어도 작은 세부는 기록에 남는다. 이는 표시 분류 변화이며 정답 라벨 없이 오탐률 개선으로 환산할 수 없다. 선폭 우선20층은 유지됐다.

당시 검증: 55 + 167 = 222. 동일 환경 단회 기록의 구7.219→5.173초, NIST3.923→4.094초, 3D9.529→9.382초를 함께 본다. 모든 사례가 빨라진 것은 아니다. D01 초안의 다른 실행 시간과 섞어 속도 개선율을 계산하지 않는다.
