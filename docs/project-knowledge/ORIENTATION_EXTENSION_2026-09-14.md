# 2026-09-14 빌드 방향 확장과 좌표계 검증

사용자는 6방향 이외의 빌드 방향을 요청하면서 정확한 해석이 가능한 경우에만 추가하라고 했다. 임의 방향의 **기하 계산**을 독립 해석식과 대조한 뒤, 26개 축·대각선 후보와 기울기·방위각 직접 입력을 추가했다. 실물 출력 성공 또는 공정 물리의 정확성을 검증한 것으로 확대하지 않는다.

## 구현 이유와 범위

6축에 한정하면 경사 배치의 높이·하향면·접촉·공간 손익을 사용자가 확인할 수 없다. 기존 계산은 단위 적층축과 면 법선의 내적 및 강체 회전을 사용하므로 임의 방향에도 적용할 수 있다. 26개는 축 6개, 두 축 대각선 12개, 세 축 대각선 8개이며 공정의 최적 방향을 보장하는 표본 수가 아닌 **명시적 탐색 후보 선택**이다. 기존 주요 면 최대 6개 추가를 선택적으로 유지했다.

기울기 θ는 모델 +Z에서 0~180°, 방위각 φ는 모델 +X에서 +Y 쪽으로 0~360°다. 적층축은 `(sinθ cosφ, sinθ sinφ, cosθ)`이며 이 모델 방향을 프린터 +Z로 맞춘다. 숫자를 직접 입력할 수 있고 5° 버튼 간격에 제한되지 않는다. 3D 드래그는 카메라만 변경한다. 현재 방향이 기본 후보와 정확히 같은 단위벡터가 아니면 비교에 별도 행으로 남긴다. 비교표는 벡터·기울기·방위각을, JSON과 HTML은 최종 배치 행렬을 보존한다.

추가 XY 회전은 기존처럼 0/90°다. 전체 방향 공간이나 연속 XY 회전의 전역 최적화는 구현하지 않았다. 고분자 PBF의 하향 지지 지표와 비 MEX의 층간 규칙은 기존처럼 해당 없음으로 유지한다. 장비·재료·슬라이서는 미확정이며 새 공정 임계값은 도입하지 않았다. 따라서 새 수치 한계를 문헌 규정으로 인용하지 않는다. 기존 규칙의 문헌 근거는 [조사 문서](../research/AM_DFM_RESEARCH_AND_DESIGN.md)를 따른다.

## 발견한 반례와 수정

| 반례 | 이전 문제 | 수정 |
|---|---|---|
| `[1e200,2e200,3e200]` | 유한 벡터의 norm overflow로 0벡터가 생김 | 최대 절댓값으로 먼저 스케일한 뒤 단위화. 0·NaN·무한은 거부 |
| 극소 벡터, 거의 +Z | 빠른 검토와 legacy 층간 코드의 EPS/allclose 기준 차이 | 공통 단위화 후 최종 배치 메시를 +Z 층간 검사에 전달 |
| 원본을 Z=100으로 이동 | 화면 바닥은 0인데 층 결과는 원본 Z 근처 | XY 중심·Z=0·추가 yaw를 포함한 동일 행렬 적용 |
| 거의 항등 변환 | trimesh.apply_transform의 근사 생략으로 작은 회전 또는 캐시 법선 회전이 누락될 수 있음 | export와 층간 입력을 변환한 정점으로 직접 생성 |
| `[9e-15,0,1]`, 길이 1e7 mm | 후보 중복 허용오차로 +Z와 합쳐져 현재 높이와 비교 행이 다름 | 근접 방향을 같은 방향으로 합치지 않음 |
| 6축+면과 26방향+면 | 같은 면 후보 이름의 실제 방향이 달라질 수 있음 | 적용 callback에서 이름 대신 실제 벡터 매칭 |

층간 상세에는 `placement_transform`, `coordinate_frame=build_mm`를 기록한다. 벽 거리 표본은 원본 면 연결을 유지하는 `model_mm`이며 배치 행렬을 함께 남긴다. 상세 결과를 붙일 때 입력·프로필·방향뿐 아니라 배치도 대조한다. legacy 보관 계산 코드는 수정하지 않았다.

제공된 외부 STL을 변경 없이 사용한 26방향 포함 빠른 검토는 764면 부품 0.029초, 184,110면 브래킷 0.715초, 52,738면 훅 0.242초였다. 모델 읽기를 제외한 한 번의 로컬 실행이고 앞선 6방향 실행의 메시 캐시가 재사용됐다. 일반적인 속도 향상 주장이나 장비 비교에 사용하지 않는다. 외부 부품의 실제 단위·치수 미확정 상태는 그대로다.

최초 감사 스크립트는 원본 Markdown의 Git LF 바이트와 Windows CRLF 체크아웃 바이트를 그대로 비교하여 실패했다. [실패 기록](../../validation/v3/orientations-01/failure.json)을 보존하고 Git clean-filter 기준 내용 일치와 원시 SHA를 분리해 기록하도록 수정했다. 성공 재실행에서 원본 24개 Git 내용 보존을 확인했다. 분석 결과를 맞추려고 원자료를 수정하지 않았다.

## 남는 정확성 한계

STEP 곡면의 하향면은 삼각형 근사이며 임계각 부근에서 테셀레이션에 민감하다. 기존 구체의 비단조 오차 관측을 지우지 않는다. 층간 검토는 지정 층의 중간 단면 표본과 평면 연산이므로 매우 얇은 특징·단면 스냅 오차가 남고, 부분/미확정 결과를 0으로 바꾸지 않는다. 바닥 점·선 접촉의 면적 0은 첫 압출층 접착력 0을 뜻하지 않는다. 열변형·서포트 실체·출력 시간·강도·실물 성공은 이번 확장으로 검증되지 않았다.
