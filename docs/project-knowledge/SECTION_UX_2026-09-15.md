# 단면 결과를 사용자가 판단할 수 있는 화면으로 변경

사용자는 `complete · 확정 4 / 요청 4`, `3.989e-14%`, 두 개의 파란 선만으로 괜찮은 형상인지 판단하기 어렵다고 지적했다. 계산 상태와 제조 적합성을 구분하는 문장이 있어도, 수치 해석과 다음 행동을 사용자에게 맡기는 화면이었다.

## 변경 이유와 동작

- 맨 위에 한국어 계산 상태, 형상에서 관측한 변화, 다음 행동을 표시한다. 제조 합격/불합격이나 새로운 경험적 위험 점수를 만들지 않는다.
- 완료 표시는 요청 수·행 수·확정 수·구간 상태의 일치를 확인한다. 부분·미확정 결과와 원래 누락 사유를 우선 표시하고, 불완전한 결과에 체적값이 남아 있어도 전체 검산에 사용하지 않는다.
- 유효한 인접 단면 중 대칭차가 가장 큰 두 표본을 기본 선택한다. 누락 단면이나 건너뛴 높이 구간을 이어 비교하지 않는다. 같은 면적이 옆으로 이동한 경우도 단순 면적 차이와 구별한다. 관측한 표본 쌍에서의 상대적인 최대값이며 제조 위험 임계값은 아니다.
- 0부터 시작하는 단면 번호 슬라이더 대신 1부터 시작하는 번호·실제 높이·재료 면적으로 선택한다. 이전 단면은 파란 점선, 현재 단면은 주황 실선으로 겹쳐 표시한다. 두 색은 비교 대상의 구분이다.
- 네 점 사이를 직선으로 이어 점진적인 형상 변화처럼 보이던 그래프를 실제 검사 위치의 점 그래프로 변경했다. 높이와 면적의 축 이름을 표시한다. 대칭차·둘레·A/P·영역/루프 수는 설명과 함께 펼침 표에 보존한다.
- 체적 상대차는 첫 화면의 대형 지표에서 `계산 확인 · 부피 검산과 적용 범위`로 옮겼다. 작은 양수는 `0.0001% 미만`으로 읽기 쉽게 표시하고 원본 수치도 보존한다. 표시 자릿수는 합격 기준이 아니다.
- 단면 설정을 바꿨지만 실행하지 않았으면 이전 설정의 결과임을 명시한다. 검사 결과를 새 설정에 맞춘 것으로 바꾸지 않는다.

## 검증과 실제 사례

자체 CAD `07_bracket.step`, +Z, 금속 PBF에서 실제 브라우저를 확인했다. 4개 단면이 완료되고, 높이 3.15470053838 mm와 11.6076951546 mm의 단면적 1,200 → 120 mm², 대칭차 1,080 mm²를 비교 대상으로 선택했다. 원래 체적과 단면 수치는 유지된다. 이 두 표본만으로 실제 변화 위치나 출력 불량을 확정하지 않는다.

순수 설명 함수의 반례 34개, 화면 검사 3개, 기존 앱 흐름 8개를 검증한다. 실제 계산 방법의 단면 회귀 검사도 별도로 유지한다. 초기 화면 검사에서 Streamlit 차트 요소 이름과 기존 캡션 검사 위치의 불일치 2개를 확인하여, 실제 원형 점 마크와 이전 결과 방법 표시를 검사하도록 고쳤다. 앱 실행 예외를 숨기거나 수치 기대값을 낮춘 변경은 아니다.

최종 관련 검사 45개는 Windows Python 3.12와 3.13에서 각각 통과했다. 기존 단면·형상 변화 기준 계산 검사 52개도 Python 3.12에서 통과했다(설명 함수 34개와 함께 실행한 로그는 총 86개). 표시를 바꿔도 원래 상세 결과를 수정하지 않는 것, 미완료 결과의 체적값을 전체 검산으로 오인하지 않는 것, 기본 비교 위치와 버튼 재선택, 3개 비FDM 공정의 기존 앱 흐름을 확인했다.

기존 계산 알고리즘·규칙·형상은 변경하지 않는다. 추가된 화면 모듈도 현재 코드 지문에 포함되므로 새 지문은 이전 수치 감사의 지문과 달라진다. 과거 전수 감사 기록은 원래 지문과 함께 보존한다. 이번 검증 범위를 실제 출력 검증이나 전체 문헌 재조사로 확대하지 않는다.
