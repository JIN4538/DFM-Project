# AM-DFM 3.0 검증 기록

실행일: 2026-09-14, Windows 11 / Python 3.12.14. 의존성은 `requirements.txt`로 고정했고 `pip check`에서 충돌이 없었다. 실행은 저장소의 새 `.venv`를 사용했다. 과거 Linux 결과로 현재 결과를 대신하지 않았다.

## 결론과 검증 범위

**최종 통합 pytest 225개 통과(79.67초), 기존 기본검증 별도 55/55 통과.** 새 테스트는 58개, 기존 회귀는 167개다. [최종 JUnit XML](../validation/v3/combined-release.xml), [실행 로그](../validation/v3/logs/combined-release.txt), [55개 기본검증 로그](../validation/v3/logs/verify-legacy-final.txt)를 함께 보존한다.

기하 해석값·단위·배치·부분 결과·상태 변경·UI·내보내기·제한된 G-code 해석을 검증했다. 이는 실제 프린터에서의 출력 성공률·강도·공차 검증이 아니다. 장비·재료·슬라이서 미확정 상태에서 실물 시편은 출력하지 않았다. 기존 점수 엔진을 재검사한 55개 결과 역시 점수의 물리적 예측력을 입증하지 않는다.

기존 `test_aabb_overlap_is_not_solid_overlap`의 체적 0 반례에서 trimesh 중심 계산 RuntimeWarning 1개가 발생한다. 해당 반례의 판정과 테스트는 통과했다. 이를 숨기거나 전역 경고를 비활성화하지 않았다.

자체 CAD의 **설계 치수와 해석식은 측정 알고리즘과 별도로 정의**했다. 다만 STEP 생성과 STEP 입력 모두 OCCT를 사용한다. 완전히 다른 CAD 커널 간 상호운용성 검증이나 ISO 52902 인증 시험을 했다는 뜻은 아니다. 구 극점의 면적 0 테셀레이션 셀을 제외하고 CAD 면 연결을 유지하며, 원본 STEP 파일은 바꾸지 않는다.

## 외부 STL 세 개

[최종 사례 요약과 원본 보존 SHA](../validation/v3/release-cases-01/summary.json). 세 파일은 실제 치수가 알려지지 않아 **모든 mm 값은 좌표 단위를 mm로 가정한 시나리오**다. 최장 길이·축 배율을 임의 수정하지 않았다. 아래 시간은 이 PC에서의 단일 실행 관측이며 일반적인 성능 보증이나 v2.6 대비 배속 비교가 아니다. 빠른 검토 시간에는 파일 읽기·브라우저 렌더링이 제외되고, 정밀 시간에는 별도 프로세스 시작이 포함된다.

| 파일 | 삼각형 | 가정한 외곽 mm | 읽기 / 빠른 검토 | 벽 표본 | 층간 검토 |
|---|---:|---|---|---|---|
| `3DP_20546_S-0039.stl` | 764 | 150×142×25,000 | 0.003 / 0.046초 | 0.97초 | 125,000층 요청, 1,500층 한도 초과 |
| `strong_corner_bracket_vcd.stl` | 184,110 | 45×45×15 | 0.453 / 0.409초 | 2.78초 | 75/75층, 6.24초 |
| `strong_garden_tool_hook_vcd.stl` | 52,738 | 93.194×92.063×53.342 | 0.112 / 0.114초 | 3.03초 | 267/267층, 11.87초 |

각 입력에 빠른 JSON, 상세 JSON, HTML을 저장했다. 브래킷의 최소 법선 거리 표본은 0.5 mm, 가든 훅은 약 0.00676 mm다. **가든 훅에 6.76 μm 벽이 실제로 존재한다고 결론 내리지 않는다.** 해당 값은 작은 면에서 출발한 국소 첫 교차 거리이고, 면적 가중 5백분위는 약 4.545 mm다. 675개 유효 표본의 면 번호·좌표·거리와 단위 가정을 보존했다. 실제 최소 벽두께를 말하려면 해당 형상을 확인하고 별도 측정 정의로 검증해야 한다.

25 m 사례의 층 계산은 0.92초 안에 한도 초과를 알렸고, 빠른 기하와 벽 결과를 보존했다. 모든 사례를 완료로 표시하기 위해 층 간격을 자동으로 키우지 않았다.

## 곡면의 수치 오차

반지름 10 mm 구에서 수평 기준 45° 미만 하향면의 투영면적 해석식은 `πr²sin²45° = 157.0796327 mm²`다. 요청 각도 편차는 0.15 rad로 유지했다.

| 요청 선형 편차 mm | 삼각형 | 측정 mm² | 해석식 대비 상대차 |
|---:|---:|---:|---:|
| 0.05 | 3,534 | 156.168741 | −0.580% |
| 0.005 | 19,950 | 160.502176 | +2.179% |
| 0.001 | 100,518 | 158.601638 | +0.969% |

임계 각도에서 면을 포함/제외하는 연산 때문에 세분화가 항상 오차를 단조 감소시키지는 않는다. 이 세 번의 결과를 모든 형상의 ±2.18% 보증으로 사용하면 안 된다. 정확한 CAD 원통 지름과 근사 메시의 하향면 면적을 같은 정확성 등급으로 설명하지 않는다.

## 수정 전후 예제

같은 좌표·프로필·방향에서 30×20 mm 평행판의 두께를 0.3→1.2 mm로 바꿨다. [비교 JSON](../validation/v3/release-cases-01/thin_plate_comparison.json)에 CAD 체적 180→720 mm³(+540), 관측 최소 거리 0.3→1.2 mm(+0.9)가 기록됐다. 비교에 사용한 1 mm 벽 기준은 개발 시나리오이며 표준 합격 기준이 아니다. 재료량 증가와 얇은 구간 감소를 함께 보여주고 실제 강도·기능 향상을 확정하지 않는다.

## CuraEngine 대조

설치된 **UltiMaker CuraEngine 5.12.0**으로 리브 5개를 슬라이스했다. [실험 원기록](../validation/v3/cura-experiment-02/manifest.json)에 실행 파일·정의·고정 설정·입력 STL·출력 G-code의 SHA, 명령과 종료 코드가 있다. G-code 및 각 명령 로그도 보존한다.

공통 조건은 길이 20 mm, 높이 10 mm, 노즐/명목 선폭 0.4 mm, 층 높이 0.2 mm, 최소 특징 0.1 mm, 최소 비드 0.34 mm다. 단일 압출기, 지지·부착 구조·후퇴 없음, 100% 채움의 **합성 CLI 조건**이다. Cura GUI에서 선택한 특정 프린터/재료 프로필과 같다고 주장하지 않는다. 정의 파일의 기본값을 동결했고 UI 수식 평가를 재현하지 않았다.

## 실제 브라우저 확인

로컬 Streamlit에 `04_horizontal_hole.step`을 파일 업로드하고 30×20×20 mm, CAD 체적 약 11.2 cm³, 하향면·구멍 후보 2개, CAD 면 번호 6을 확인했다. 내부 문제 면이 외벽에 가려지는 것을 발견해 투명 보기와 중복 표면 제거를 적용했고, 주황색 내부 천장과 적층 방향 표시를 시각적으로 확인했다. 선택한 원통면의 지름·축은 별도 표로 제공한다.

AppTest는 방향 적용, 설정 변경 후 오래된 다운로드 숨김, 벽 결과 유지, 수정 전후 비교, Cura 경로 예제까지 실행했다. 1280×720 브라우저 화면을 점검했으며 모든 모바일·브라우저·그래픽 장치 조합을 검증한 것은 아니다.

## 최초 실패와 수정 이력

- 새 CAD 시험 최초: 40 통과 / 1 실패. 구 극점의 면적 0 메시 셀을 CAD 경로에서만 제거하고 면 ID를 동기화한 뒤 41/41 통과.
- 기존 회귀 최초: 166 통과 / 1 실패. Windows cp949로 UTF-8 JSON을 읽던 테스트를 UTF-8 명시로 수정. 기대값은 유지했다.
- 초기 통합: 208/208 통과. 이후 G-code·새 상태/공정 반례·UI 비교 검사를 추가했다.
- 확대 UI 시험: 222 통과 / 1 실패. 입력 교체 후 기본 결과 탭으로 돌아오는 정상 흐름에서 테스트가 비교 탭을 다시 선택하지 않았다. 실제 사용 순서대로 테스트를 수정한 뒤 해당 시험 통과.
- 이후 225/225 통과. 내부 면 표시 보완 후 **최종 다시 225/225 통과**했다. JUnit XML들을 별도 이름으로 보존했다.
- Cura pilot과 `cura-experiment-01`은 필수 설정 누락으로 실패했다. 압출기 기본값까지 합쳐 고정한 `cura-experiment-02`의 다섯 사례가 성공했다. 실패 로그와 중간 산출물을 삭제하지 않았다.
- 브라우저 자동화의 숨은 파일 입력 버튼에서는 파일 선택 이벤트가 잡히지 않았다. 실제 보이는 Upload 버튼으로 업로드하고 결과까지 확인했다. 앱의 STEP 처리 실패로 기록하지 않는다.

## 재실행과 남은 한계

```powershell
.\.venv\Scripts\python.exe -X utf8 -m pytest tests_v3 tests -q
.\.venv\Scripts\python.exe -X utf8 verify_legacy.py
.\.venv\Scripts\python.exe -X utf8 scripts/validate_release.py --out validation/v3/new-release-cases
```

새 사례 폴더를 사용해야 한다. 외부 STL은 로컬에 있을 때만 실행된다. 기준 사례 실행은 전체 테스트를 대체하지 않는다. 이 릴리스의 분석 코드 SHA-256은 `2ebbabd7902eb5880fe25f7ed1cfa9509cf88b8432922abb005a4f0eec81d10a`이며 각 JSON에도 기록한다. UI·문서·실험 스크립트까지 포함한 배포 파일 SHA는 별도 릴리스 manifest를 따른다.

실물 검증, 불확실 STL의 자기교차 전체 탐지, 임의 곡면의 정확 전역 벽두께, 내부 채널의 제거 연결성, PMI/GD&T, 연속 방향 최적화, 열·유동·강도 해석, 여러 공구·모든 펌웨어 G-code는 남아 있다. CPU 시간·입력·출력·표본 한도는 있지만 운영체제 수준 메모리 격리 한도는 설정하지 않았다. 제품이 제공하는 검토 범위는 [README](../README.md)와 [구조 문서](ARCHITECTURE_V3.md)를 따른다.
# 후속 방향 확장 검증

26방향과 직접 각도 입력의 최신 검증은 [2026-09-14 방향 확장 기록](project-knowledge/ORIENTATION_EXTENSION_2026-09-14.md)을 따른다. 전체 283개 회귀검사와 기존 55개 기본검증을 통과했고, 1,000개 임의 방향을 두 각도 기준의 독립 해석식에 대조했다. 아래의 초기 개선판 기록과 실패·측정값은 당시 결과로 보존한다.
