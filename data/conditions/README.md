# 공통 조건 데이터베이스

적층제조 4개 공정과 CNC 고정축 밀링에서 사용할 **출처가 있는 조건과 참고 자료**다. 네트워크·AI API 없이 앱과 함께 동작한다. 모든 장비·재료가 포함된 전 세계 제품 목록이나 제조 성공률 데이터셋은 아니다.

## 파일과 의미

- `am.json`: Prusa, Formlabs, EOS의 정확한 장비·공정 설정·재료 조건.
- `machining.json`: DATRON·Harvey 엔드밀, Haas 장비, Hydro·Outokumpu·Ensinger 소재, Sandvik 지침.
- `expanded_machines.json`: Bambu Lab·UltiMaker·Creality·ELEGOO·Anycubic·EOS·3D Systems·Tormach 장비 20종의 대조한 명목 치수.
- `literature.json`: 기존 43개 문헌의 파일 해시·전문 검토 기록·현재 코드 인용 연결. 수치 기준은 제공하지 않는다.
- 출처 감사: [적층](../../docs/research/conditions-2026-09-28/AM_SOURCES.md), [절삭](../../docs/research/conditions-2026-09-28/CNC_SOURCES.md).

`automatic`은 **사용자가 그 시나리오의 적용 버튼을 누르면 계산 입력으로 가져올 수 있다**는 뜻이다. 장비명만으로 재료를 추정하거나 실제 제조 적합성을 승인하는 뜻이 아니다. `reference_only`는 찾아볼 수 있지만 현재 계산에 자동 대입하지 않는 정보다.

## 값 한 개에 반드시 붙는 정보

| 필드 | 의미 |
|---|---|
| `value`, `unit` | 원문 값과 단위. 엔진 입력은 명시적 길이 단위만 mm로 변환 |
| `kind` | 장비 사양 / 공구 사양 / 제조사 지침 / 슬라이서 설정 / 물성 / 실험값 |
| `source_ids`, `locator` | 근거 출처와 실제 표·페이지·프로필·행 위치 |
| `conditions` | 방향, 정확한 재료·판본, 시험·제조 상태 등 적용 조건 |
| `application` | 계산 입력 또는 참고 전용 |

출처에는 제목·제조사·URL·확인일·판본·열람 상태·한계를 기록한다. 확보한 원문 파일과 고정 Git 커밋에는 SHA-256도 기록했다. 확인일은 웹 페이지의 발행일이나 제품의 최신 판본이라는 뜻이 아니다.

프로필에는 적용 공정, 정확한 이름, 적용 조건, 미평가 범위가 있다. 프로젝트의 실물 검증은 전부 `not_validated_by_project`다. 자료가 실험 결과를 포함한다는 것과 이 툴이 해당 장비에서 검증됐다는 것은 다르다.

## 연결 계약

- AM: 빌드 공간·층 높이·명목 선폭. 공간 제한은 별도로 켤 때만 적용한다.
- CNC: 공구 지름·절삭부 길이. 전체 길이·목 길이로 장착 후 돌출 길이를 계산하지 않는다.
- 벽 방향·연결 상태·시험 형상을 필요로 하는 권고, 물성, 열·속도·노광 설정은 참고 전용이다.
- 이 판에서 최소 벽·홀·돌출 길이·깊이비의 자동 입력은 없다. 원문에 있는 값을 현재 측정법의 보편 합격선으로 바꾸지 않았다.
- 자료 선택은 미리보기이며, 적용 버튼에서만 현재 조건을 교체한다. 다른 자료의 이전 기준을 섞지 않도록 미제공 조건을 초기화한다.
- 수동 변경값과 원자료에 없는 직접 입력·탐색 기본값은 출처 값과 구분해 JSON/HTML에 남긴다.
- DB가 바뀌면 기존 적용 상태를 재사용하지 않는다. 재적용하거나 직접 입력으로 초기화한다.
- 출처 누락·중복 ID·중복 JSON 키·잘못된 공정·알 수 없는 단위·비정상 값은 거부한다.

## 새 자료를 추가하는 순서

1. 공식 제품 문서, 표준 원문, 논문 원문에서 정확한 판본과 적용 조건을 확인한다. 검색 결과 요약만으로 수치를 채우지 않는다.
2. 기존 `sources`와 `profiles` 구조로 새 ID를 부여한다. 미확정 값은 생략하고 이유를 `limitations`에 남긴다.
3. 같은 이름의 다른 재료·방향·판본을 평균내거나 섞지 않는다. 충돌 자료는 제외하거나 서로 다른 조건으로 명시한다.
4. 처음에는 `reference_only`로 넣는다. 현 엔진의 측정 의미와 일치함을 검토하고 독립 반례를 추가한 뒤 필요한 필드만 자동 연결한다.
5. `python scripts/audit_conditions.py --out <새 결과.json>`으로 DB를 검사한다. 저장소에서 원문까지 확인하려면 `--verify-literature`를 붙인다.
6. `python -m pytest tests_v3/test_conditions.py tests_v3/test_conditions_integration.py tests_v3/test_conditions_ui.py -q`를 실행한다.

원문 전체와 전사·렌더 검증 작업물은 저장소 옆 `study/conditions-2026-09-28/`에 보존한다. 앱 배포본은 필요한 사실·조건·위치·링크를 포함하며 원문 웹페이지와 새 제조사 PDF 전체를 재배포하지 않는다.
